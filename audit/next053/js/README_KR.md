# JS 이력 페이지 성능 비교

동일한 합성 이력을 두 릴리스 JAR에 적용합니다. 기록 수, 페이지의 원본 순서와 총개수를 매번 검사하고 검색 결과의 체크섬을 대조합니다. 외부 요청이나 Burp 실행은 없습니다.

```sh
python audit/next053/js/run.py \
  --baseline-jar downloads/extensions/0.52.0/burp-workbench-kr-0.52.0.jar \
  --current-jar downloads/extensions/0.53.0/burp-workbench-kr-0.53.0.jar \
  --api-jar project/burp-development-workspace/burp-workbench-kr/burp-workbench/deps/montoya-2026.jar \
  --out tmp/next053-js-performance --records 3000 --forks 3
```

JDK 17 이상이 필요합니다. 각 JVM은 `-Xms128m -Xmx256m`을 사용합니다. 순서 편향을 줄이기 위해 이전/현재 버전의 실행 순서를 번갈아 적용합니다. 최종 비교는 다른 빌드·검사 작업이 끝난 동일한 호스트에서 수행하세요.

`comparison.json`은 입력 JAR와 하네스의 SHA-256, 환경, 각 실행의 결과와 실행별 수치의 중앙값을 담습니다. 최초 검색 시간과 같은 검색 조건에서 다른 페이지를 읽는 p50/p95를 구분합니다. heap은 작업 직후 표본의 최댓값이며 JVM 전체 최대 사용량 측정이 아닙니다. GC 시간은 JVM이 보고한 누적 collection 시간이며 개별 정지 시간의 p95가 아닙니다.

0.53.0의 캐시는 한 검색 조건의 일치 항목 해시를 디스크에 최대 8MiB 보관하고, 빈 검색의 페이지 위치는 최대 64개 보관합니다. 작성 중 임시 파일까지 포함하면 캐시 디스크 사용은 최대 16MiB입니다. 캐시가 가득 차거나 쓰기에 실패해도 전체 검색을 수행합니다. 저장·삭제·결과 갱신·색인 복구 때 고정 크기의 무작위 세대 토큰을 갱신합니다. 각 페이지 조회는 토큰을 확인하여 다른 인스턴스에서 완료한 변경도 포함해 페이지 위치·검색 캐시·전체 개수를 갱신합니다. 파일 시각의 정밀도에 의존하지 않습니다. 취소된 검색의 부분 결과는 공개하지 않습니다.

공유 경로의 캐시가 다른 인스턴스에 의해 교체되거나 손상된 경우를 구분하기 위해 인스턴스·검색·revision 식별자와 전체 파일 SHA-256을 확인합니다. 검사 실패 시 원본 메타데이터를 다시 검색합니다. 기록의 동시 쓰기를 지원하는 데이터베이스나 프로세스 간 쓰기 잠금 기능을 추가한 것은 아닙니다.

관련 회귀는 `JsArchivePagingTest`에 포함됩니다. 첫 검색의 원본 메타데이터 전체 스캔, 다른 검색어로 전환한 뒤의 스캔, 자주 바뀌는 이력에서의 캐시 재구성 비용은 남습니다. 이 마이크로벤치마크 결과를 실제 Burp 전체 처리량이나 JS 분석 속도 향상으로 해석하지 않습니다.
