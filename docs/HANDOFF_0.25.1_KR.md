## 문제와 변경

`WorkbenchExtension.addTraffic()`가 행을 추가하기 전에 인증 후보를 분석했고, 이 예외가 `drain()`과 기본 Swing Timer의 listener 밖으로 나갔습니다. Java 17에서 listener 예외 뒤 coalescing의 알림 플래그가 해제되지 않아 후속 갱신이 멈추는 것을 확인했습니다. 인증 Cookie가 있는 밑줄 포함 호스트는 `AuthComparePanel.origin()`의 URI 호스트 null 참조를 재현합니다. 사용자의 최초 오류를 이 예외로 확정한 것은 아닙니다.

목록 메타데이터 검증 → 행 보관 → 각각 보호된 환경·인증 관찰 순서로 변경했습니다. 타이머 전체와 항목별 처리, HTTP 요청·응답 관찰 단계, 여러 패킷 수동 가져오기를 보호했습니다. 로그에는 단계·예외 종류·Workbench 코드 위치만 남기고 예외 메시지·패킷 원문은 넣지 않습니다. VM의 `Error`까지 삼키지는 않습니다.

진단 항목은 수신·대기·크기 제외·큐 초과·처리 오류입니다. 부가 분석 오류와 실제 누락은 다릅니다. 이전 보관/크기 제한은 유지하는 0.25.1 안정화 배포이며, 원격에 없는 별도 0.26 기능 작업을 완료했다고 표시하지 않습니다.

## 후속 확인

사용자가 새 JAR를 로드해 정상 트래픽을 수집한 뒤 오류 수가 증가하면 상태 도움말의 마지막 오류 단계와 Extensions Errors를 확인합니다. 큰 응답 때문에 보관하지 않는 경우에는 크기 제외가 증가합니다. 250행·128KiB 한도 제거와 통합 SCOPE 모드는 별도 작업과 합쳐 검증해야 합니다. 같은 파일을 수정하는 다른 작업이 있으면 이 안정화 변경과 충돌을 해결한 뒤 회귀 검사를 다시 실행하세요.
