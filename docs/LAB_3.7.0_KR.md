# 커뮤니티 3.7.0 — 통합 커뮤니티와 취약점 실습

관리자·사용자는 모두 `http://127.0.0.1:8088/`에서 로그인합니다. `/admin`, `/user`와 기존 로그인 주소도 같은 커뮤니티로 이동합니다. 기본 커뮤니티는 수정 API를 사용하며, 관리자는 공통 기능과 관리자 메뉴를 함께 이용합니다.

## 실행

[Docker 실행 ZIP](../downloads/docker/3.7.0/community-security-lab-3.7.0-docker.zip)을 새 폴더에 풀고 Windows는 `./start.ps1`, Linux/macOS는 `sh start.sh`를 실행합니다. 직접 실행은 `docker compose up -d --build --wait --wait-timeout 900`입니다. 같은 포트를 사용하는 이전 스택은 해당 폴더에서 `docker compose down`으로 종료합니다. 기존 DB 볼륨을 삭제할 필요가 없습니다. 신규 테이블은 시작할 때 추가합니다.

| 계정 | 비밀번호 | 권한 |
|---|---|---|
| admin | `LabOnly!2026` | 공통 기능 + 전체 사용자·콘텐츠·신고·강의 관리 |
| alice | `LabOnly!2026` | 본인 게시글·댓글·신고·신청·정보 관리 |
| bob | `LabOnly!2026` | 다른 소유자의 데이터와 비교할 일반 사용자 |
| moderator | `LabOnly!2026` | 공통 기능 + 기존 공개·회원 전용 보안 게시판 관리 |

## 같은 화면에서 사용하는 기능

- 게시판: 조회·작성, 작성자/관리자 수정·삭제, 댓글 작성·수정·삭제, 첨부파일, 게시글·댓글 신고.
- 강의: 목록·상세 조회, 강의 신청. 내 활동에서 본인 신청 조회·대기 신청 취소.
- 내 활동: 본인 게시글·댓글·신고 사유와 처리 상태·강의 신청 내역.
- 내 공간: 쪽지, 서비스 요청 작성·조회·취소, 본인 이메일 수정.
- 관리자: 사용자 이메일·권한 변경·정지/해제, 전체 게시글·댓글 관리, 신고 처리·반려, 강의 등록·수정·삭제 및 수강 신청 수락·거절, 기존 서비스 요청 검토·공지 설정.

역할·소유권·CSRF는 서버에서 검사합니다. 계정 정지는 기존 로그인 세션과 신규 로그인을 차단하고, 역할 변경도 기존 세션에 즉시 적용됩니다. 기본 관리자 ID 3은 실습 복구를 위해 권한·정지 변경을 막습니다. 계정 삭제는 비활성화로 대신합니다. 수강 신청은 중복 신청, 마감 강의 신청, 처리 후 재처리·취소를 거부합니다. 강의 삭제 시 연결된 신청도 삭제합니다.

## 취약점 실습 메뉴

상단 또는 왼쪽의 **취약점 실습**을 엽니다. 실습 메뉴 안에서만 **취약 구현 / 수정 구현**을 선택합니다. 요청 실행은 사용자가 버튼을 눌렀을 때 수행하며, 최근 요청·응답과 실습 결과에서 실제 메서드·URL·HTTP 상태·본문을 확인합니다.

| 사례 | Alice 세션의 취약 구현 | 수정 구현 |
|---|---|---|
| 비공개 게시글 IDOR: 글 102 | Bob 비공개 글 200 | 404 |
| 관리자 기능 접근 | 전체 회원 정보 200 | 403 |
| 신고 내역 IDOR: 신고 602 | Bob 신고 사유 200 | 404 |
| 강의 수락·거절: 신청 702 | 관리자 처리 200 | 403 |
| SQL 인젝션 | 검색어가 SQL로 해석되어 비공개 기록 포함 | 검색어를 값으로 바인딩 |
| 저장형 XSS | 저장한 댓글 HTML을 실습 영역에 삽입 | 댓글을 문자로 표시 |
| 민감한 정보 노출 | 합성 API 키·토큰 응답 | 403 |
| CSRF 검증 누락 | 토큰 없는 신고 등록 200 | 403 |

취약·수정 경로는 같은 실습 데이터를 사용합니다. 취약 모드에서 승인·댓글·신고를 변경하면 공통 화면에도 반영됩니다. 정상 커뮤니티는 본문·댓글을 HTML 문자로 표시합니다. 관리자 **공지·실습 초기화**에서 신고·강의·기본 계정, 게시판·댓글·쪽지, 서비스 요청·공지를 각각 복원합니다. 초기화 API는 관리자 세션과 CSRF가 필요합니다.

API 키와 토큰은 `LAB_FAKE_`로 시작하는 사용할 수 없는 합성 값입니다. 기본 Compose의 공개 포트는 127.0.0.1에만 연결되며 DB·WAS는 호스트 포트를 공개하지 않습니다.

## Workbench 계정 권한 비교

1. `http://127.0.0.1:8088/`를 Burp Scope에 추가합니다.
2. 서로 다른 브라우저 프로필에서 admin·alice·bob으로 로그인합니다. 한 프로필에서 로그인 계정을 바꾸면 기존 세션은 무효화됩니다.
3. 계정별 `/api/access/me`를 수집해 비교 슬롯에 연결합니다. 세션 검사 JSON 경로는 `$.user.USERNAME`, 기대 값은 계정명입니다.
4. 일반 메뉴에서 정상 요청을 수집하고 실습 메뉴에서 같은 객체의 취약·수정 요청을 수집해 비교합니다. 메뉴 표시 여부보다 실제 API의 상태와 데이터·변경 결과를 기준으로 판단합니다.
5. 쓰기 시나리오는 먼저 복원하고 비교합니다. 이미 처리된 신청·신고를 재처리하면 409가 반환됩니다.

새 API 접두사는 `/api/workspace/fixed/` 및 `/api/workspace/vuln/`입니다. 기존 `/api/community/`, `/api/access/`도 재사용합니다. 전체 경로는 `/v3/api-docs`에 포함합니다.

## 검증

`python tools/check_role_portals.py`는 현재 Java 소스를 컴파일하고 별도 loopback 서버·격리 H2·admin/alice/bob/moderator/비로그인 세션으로 검사합니다. 새 수락 기준은 `tools/community_workspace_checks.py`에 있습니다. [현재 실행 기록](VERIFICATION_LAB_3.7.0.json)을 확인하세요. 실제 브라우저의 화면·XSS 실행과 실제 Burp GUI·Docker/Oracle 전체 기동은 이 HTTP 검사와 구분합니다.
