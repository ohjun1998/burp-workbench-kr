# 커뮤니티 3.7.1 — 단독 로그인과 권한별 연결

`http://127.0.0.1:8088/login`에서 **일반 사용자 / 관리자**를 선택한 뒤 로그인합니다. 커뮤니티 상단의 **로그인·회원가입**도 같은 페이지로 연결됩니다.

| 로그인 유형 | 실습 계정 | 연결 화면 | 사용 기능 |
|---|---|---|---|
| 일반 사용자 | alice, bob | `/?view=feed` 게시글 목록 | 글·댓글·신고·강의 신청·내 활동 |
| 관리자 | admin | `/?view=users` 사용자 관리 | 공통 기능 + 전체 관리 메뉴 |
| 일반 사용자 | moderator | `/?view=feed` 게시글 목록 | 공통 기능 + 기존 보안 게시판 관리 |

공통 실습 비밀번호는 `LabOnly!2026`입니다. 가입한 새 계정은 일반 사용자 유형으로 로그인합니다. 회원가입도 `/login`에서 할 수 있습니다.

## 로그인 흐름

1. `/login`에서 유형을 선택하고 계정과 비밀번호를 입력합니다. 유형을 바꾸면 해당 실습 계정 예시가 입력됩니다.
2. 서버가 비밀번호·계정 상태·실제 DB 권한을 확인합니다. 선택한 유형과 계정 권한이 다르면 403과 유형 변경 안내를 반환합니다. 관리자 선택만으로 권한이 부여되지 않습니다.
3. 서버가 정한 커뮤니티 경로로 이동합니다. 관리자도 게시글·댓글·신고·강의 신청을 함께 이용할 수 있습니다.
4. 로그아웃하면 세션을 폐기하고 `/login`으로 돌아갑니다. 기존 세션으로 로그인 페이지를 열면 실제 권한에 맞는 **현재 계정으로 계속하기** 링크가 표시되며 다른 계정으로 로그인할 수도 있습니다.

잘못된 비밀번호나 유형으로 계정 전환에 실패하면 기존 로그인 세션은 유지합니다. 전환 성공 시 이전 세션과 CSRF 토큰을 교체합니다. 기존 API 클라이언트는 `accountType` 없이 로그인할 수 있으며 동일하게 서버의 실제 권한을 사용합니다.

| 이전 주소 | 연결 |
|---|---|
| `/admin/login`, `/admin/login/` | `/login?type=admin` |
| `/user/login`, `/user/login/` | `/login?type=user` |
| `/?view=login` | `/login` (스크립트 실행 시) |
| `/admin`, `/user` | 기존 통합 커뮤니티 관리·내 활동 화면 |

로그인 전에는 커뮤니티 공개 게시글과 강의 목록을 둘러볼 수 있습니다. 회원·관리자 API의 서버 권한 검사는 계속 적용됩니다. [통합 기능과 취약점 실습 8개](LAB_3.7.0_KR.md)는 같은 커뮤니티에서 사용합니다.

## 실행과 확인

[3.7.1 Docker 실행 ZIP](../downloads/docker/3.7.1/community-security-lab-3.7.1-docker.zip)을 새 폴더에 풀고 Windows는 `./start.ps1`, Linux/macOS는 `sh start.sh`를 실행합니다. 같은 포트를 쓰는 이전 스택은 해당 폴더에서 `docker compose down`으로 종료합니다. 기존 DB 볼륨을 삭제할 필요는 없습니다.

```sh
python tools/check_role_portals.py
node --test tools/test_community_login.mjs
python dev.py release
python tools/package_downloads.py --verify
```

HTTP 검사는 현재 Java 소스를 컴파일하고 별도 H2·loopback 서버·쿠키 저장소로 실제 로그인·역할·세션·기존 기능을 검사합니다. Node 검사는 배포 스크립트의 유형 선택·폼 전송·오류·기존 세션·회원가입 흐름을 DOM 어댑터로 실행합니다. [실행 기록](VERIFICATION_LAB_3.7.1.json)을 참고하세요. 실제 브라우저 화면과 Burp GUI 검증은 이 검사와 구분합니다.
