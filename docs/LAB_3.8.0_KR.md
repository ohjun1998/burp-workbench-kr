# 커뮤니티 3.8.0 — 공통 권한 정책과 반응형 화면

같은 커뮤니티에서 일반 사용자·게시판 운영자·관리자의 기능을 이용합니다. `/login`에서 일반 사용자 또는 관리자 유형으로 로그인합니다. 관리자 시작 화면은 사용자 관리, 일반 사용자와 게시판 운영자는 게시글 목록입니다.

## 권한 검사

Spring MVC 공통 인터셉터와 `CommunityAccessPolicy`가 커뮤니티 API의 로그인·계정 상태·기능 권한·CSRF를 확인합니다. Spring Security 라이브러리를 새로 추가한 구현은 아닙니다. 기존 런타임에서 공통 정책을 적용해 실습 확장과의 호환성을 유지했습니다.

- 정상 커뮤니티의 각 API는 `@AccessRule`로 필요한 기능 권한을 선언합니다. 커뮤니티·강의·서비스 요청·인증 API에 정책 선언이 없으면 기본 거부합니다. 공개 API도 공개 정책을 명시합니다.
- 세션의 사용자 ID로 실제 DB 역할과 계정 상태를 읽습니다. 요청에서 보낸 역할·권한 값으로 허가하지 않습니다. 같은 요청 안에서는 확인한 계정을 재사용하고, 역할 변경·정지는 다음 요청에서 확인합니다.
- 게시글·댓글·첨부파일은 작성자와 관리 범위를 확인합니다. 비공개 글은 작성자와 전체 콘텐츠 관리자만, 쪽지는 발신·수신 당사자만 접근합니다.
- 게시판 운영자는 보안 게시판의 공개·회원 전용 글만 관리합니다. 다른 사람의 글을 다른 게시판이나 비공개로 바꿀 수 없습니다.
- 신고·강의 신청·서비스 요청은 소유권과 해당 업무의 관리 권한을 확인합니다. 대기 상태에서만 승인·반려·취소하도록 기존 상태 조건을 유지합니다.
- 정상 변경 요청에는 CSRF 토큰이 필요합니다. 명시된 취약 실습 경로에서는 비교 목적의 권한·소유권·CSRF 누락을 유지합니다.

| 역할 | 공통 기능 | 추가 범위 |
|---|---|---|
| 일반 사용자 | 내 글·댓글·신고·강의 신청·쪽지·서비스 요청·정보 | 본인 데이터와 조회가 허용된 게시글 |
| 게시판 운영자 | 일반 사용자 기능 | 공개·회원 전용 보안 게시판 관리 |
| 관리자 | 일반 사용자 기능 | 사용자·전체 콘텐츠·신고·강의·신청·공지·실습 복원·권한표·접근 기록 |

`/api/access/me`는 실제 역할과 부여된 기능 목록을 반환합니다. 화면은 이 목록과 게시글 API의 객체별 허용 작업을 사용해 메뉴와 버튼을 표시합니다. 직접 URL·API를 호출해도 서버 정책이 다시 검사합니다.

## 새 화면

- 왼쪽 탐색 메뉴, 현재 위치, 통합 게시글 검색, 넓은 본문으로 구성했습니다. 데스크톱에서는 메뉴를 접고, 작은 화면에서는 메뉴 서랍을 열 수 있습니다. Escape와 배경 클릭으로 닫습니다.
- 게시글·강의는 카드, 사용자·신고·신청은 표로 표시합니다. 표가 작은 화면보다 넓으면 내부에서 가로로 이동하며 페이지 전체는 넘치지 않도록 했습니다.
- 내 정보에서 사용할 수 있는 작업을 확인합니다. 관리자의 **권한 정책**에서 세 역할의 기능을 비교하고, **접근 기록**에서 거부·조회 불가·완료된 변경을 확인합니다.
- 접근 기록은 최근 200건을 서버 메모리에 보관하며 재시작하면 초기화됩니다. 쿠키·비밀번호·요청 본문·쿼리 값은 저장하지 않습니다. 영구 감사 로그를 대신하는 기능은 아닙니다.
- 단독 로그인 화면에 실습 계정 선택과 비밀번호 표시를 추가했습니다. 키보드 포커스, 본문 바로가기, 메뉴 상태와 동작 감소 설정도 반영했습니다.

## 실행과 검증

[3.8.0 실행 ZIP](../downloads/docker/3.8.0/community-security-lab-3.8.0-docker.zip)을 새 폴더에 풀고 Windows는 `./start.ps1`, Linux/macOS는 `sh start.sh`로 실행합니다. 기존 DB 볼륨을 삭제할 필요는 없습니다. 같은 포트를 사용하는 이전 스택은 해당 폴더에서 `docker compose down`으로 종료합니다.

계정은 `admin`, `alice`, `bob`, `moderator`, 공통 비밀번호는 `LabOnly!2026`입니다. 기존 [8개 취약점 실습](LAB_3.7.0_KR.md)과 [로그인 별칭](LAB_3.7.1_KR.md)을 유지합니다. 취약 실습에서 변경한 데이터·역할은 정상 화면에도 반영되며 관리자 초기화로 복원합니다.

```sh
python tools/check_role_portals.py
node --test tools/test_community_login.mjs
python tools/check_community_ui.py
python dev.py release
python tools/package_downloads.py --verify
```

브라우저 검사는 Playwright 1.62.1과 Chromium이 필요합니다. 별도 폴더에 `npm install --prefix tmp/browser --no-save playwright@1.62.1`로 설치하고 `tmp/browser/node_modules/.bin/playwright install --with-deps chromium`을 실행합니다. `PLAYWRIGHT_MODULE_ROOT`를 해당 폴더의 절대 경로로 지정합니다. 먼저 `python dev.py build`와 `python dev.py http-test`로 검증된 Java HTTP 런타임을 준비합니다. 테스트는 별도 loopback·H2·쿠키 저장소를 생성하고 종료합니다. 브라우저 프로필이나 프록시 설정을 바꾸지 않습니다.

검사 수와 실패 후 재실행·환경 차이는 [현재 검증 기록](VERIFICATION_LAB_3.8.0.json)에 구분합니다. HTTP 검사 전용 미선언 API fixture는 실행 ZIP에 포함하지 않습니다. 실제 Burp와 Windows Docker Desktop 조작은 별도 확인 범위입니다.
