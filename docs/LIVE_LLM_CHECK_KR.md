# Next 0.54.0 실모델·Burp 확인

자동 회귀 통과와 실제 사용 환경에서의 동작을 구분해 기록합니다. 아래 도구는 배포된 0.54.0 JAR의 LLM 클라이언트를 직접 사용합니다. JAR를 고치거나 모델 서버를 재시작하지 않습니다.

## 로컬 모델 한 번 확인

사용자 터미널에서 실행합니다.

```sh
python3 ~/workbench-next-local-llm/tools/check_live_llm.py
```

설치 JAR의 SHA-256을 manifest와 먼저 대조하고, 합성 요청·응답만 담아 Halogen에 한 번 요청합니다. 실제 사이트에는 요청하지 않습니다. 기본 주소는 `http://127.0.0.1:8731/v1`, 모델은 `halogen-qwen3.8-flash-next`, 출력 한도는 1,024토큰, 대기는 120초입니다. 자동 재시도는 없습니다.

결과는 `build/live-llm/result.json`입니다. `result: passed`는 실제 배포 클라이언트가 비어 있지 않은 모델 답변을 받았다는 뜻입니다. 답변 길이·해시·앞 400자·소요 시간·종료 이유를 남깁니다. 취약점 분석 정확도나 Burp GUI 동작까지 증명하지 않습니다. `finishReason: length`라면 출력이 토큰 한도로 끝났을 수 있습니다.

모델 ID나 포트가 다른 경우 다음처럼 지정합니다. 주소는 확장과 동일하게 loopback `/v1`만 허용합니다.

```sh
python3 tools/check_live_llm.py --endpoint http://127.0.0.1:8731/v1 --model 실제모델ID
```

`Operation not permitted`는 실행 환경의 소켓 차단일 수 있습니다. `Connection refused`는 포트·서버 실행 상태를, HTTP404는 `/v1` 및 모델 API 경로를, HTTP401은 서버의 인증 요구를 확인합니다. 0.54.0은 인증 없는 로컬 OpenAI 호환 서버용입니다. 서버 설정을 임의로 바꾸거나 오류만으로 서버가 꺼졌다고 단정하지 않습니다.

## 실제 Burp GUI에서 확인할 내용

기존 작업을 보존한 별도의 테스트 환경에서 [0.54.0 설치 JAR](../downloads/extensions/0.54.0/burp-workbench-kr-0.54.0.jar)를 등록합니다. 라이선스 동의가 필요하면 사용자가 직접 확인합니다.

1. Extensions에 로드 오류가 없고 Workbench Next가 표시되는지 확인합니다.
2. 허가된 로컬 테스트 사이트를 SCOPE에 넣고, 응답이 있는 요청 한 개를 선택합니다.
3. 우클릭 → **로컬 LLM 분석 준비**로 창이 열리고 원본 ID·가림 미리보기가 나오는지 확인합니다. 창을 열기만 해서는 분석을 시작하지 않아야 합니다.
4. **로컬 LLM 분석** 후 창 조작이 가능한지, 답변에 미검증 표시가 있는지 확인합니다.
5. **원본을 Repeater에 준비**했을 때 원본이 보존되고 Send가 자동 실행되지 않는지 확인합니다.
6. **검토 메모와 원본을 증거에 추가**한 뒤 원본 ID와 미검증 라벨을 확인합니다. 내보내기 전 가림 미리보기도 확인합니다.
7. 분석 중 중지, 새 원본 준비, 프로젝트 전환 시 이전 답변이 새 자료를 덮어쓰지 않는지 확인합니다.

사용자 패킷·인증값을 공유하지 않아도 됩니다. 확인한 단계 번호와 오류 문구, 합성 입력으로 생성한 `result.json`이면 후속 진단을 진행할 수 있습니다.
