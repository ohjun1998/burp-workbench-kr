# Workbench 0.26.0 · Feature Mapper 0.2.0 성능 검증

기준 Workbench **0.25.5 / Mapper 0.1.0**과 개선 후보 **0.26.0 / Mapper 0.2.0**에 동일한 하네스·입력을 적용했습니다. 화면 반영 대기와 Mapper 조회 작업은 줄었고, 디스크 색인과 삽입 비용은 증가했습니다. 수집은 양쪽 모두 **3,900건 전량 보존·누락 0·처리 오류 0**을 확인했습니다. 표는 표시 자릿수로 반올림하며, 정확한 원래 수치와 전체 통계는 [성능 JSON](PERFORMANCE_0.26.0.json)에 보관합니다.

운영 수집 콜백·디스크 저장소·Swing 타이머·Mapper를 실행했지만 Montoya 호스트와 입력은 합성 어댑터입니다. 실제 Burp, 브라우저, 외부 대상 또는 전체 화면 그리기의 성능 결과가 아닙니다.

## 실행 조건과 판정

- Java 17.0.20, 최대 힙 512MiB, 동일 호스트. 기준과 후보의 컴포넌트별 계측은 각각 1회입니다.
- 수집 준비 운동 100건과 Mapper 준비 운동 200건은 측정값에서 제외했습니다.
- 최종 후보 계측 중 같은 호스트에서 정규 회귀 검사가 병행됐습니다. 호스트 부하를 동일하게 통제하지 않았으므로 수치 비율을 일반적인 성능 보장으로 해석하지 않습니다.
- 합격 조건은 원본·행·조회 결과의 정합성, 누락·오류 없음, 모호한 매핑 처리 등입니다. 벽시계 속도는 합격 조건이 아닙니다.
- 계측 후 JS 미리보기 상태 문구를 줄이는 화면 수정이 반영됐습니다. 아래 소스 지문은 계측 시점의 후보를 식별하며 최종 배포 전체 소스·ZIP 해시와 구분합니다. 수집·Mapper 계측 대상 구현은 고정한 상태였습니다.

## 수집 지연

콜백 시간에는 입력 속도를 맞추기 위한 대기를 포함하지 않습니다. 화면 배출 시간은 마지막 콜백 반환 후 모든 메타데이터 행과 별도 관찰 작업이 반영될 때까지입니다.

| 100건/초 · 4KiB · 300건 | 0.569457 → 0.565922 | 0.308003 → 0.305269 | 29 → 29 |
| 500건/초 · 4KiB · 1,500건 | 0.125088 → 0.151428 | 5.993442 → 0.303525 | 1,038 → 144 |
| 200건/초 · 64KiB · 600건 | 0.447273 → 0.312060 | 0.605516 → 0.304182 | 145 → 58 |

## 수집 작업량과 보존

| 입력 | EDT 원본 복원, 기준 → 후보 | 백그라운드 복원, 기준 → 후보 | 행 삽입 이벤트, 기준 → 후보 | 보존 행 벡터, 기준 → 후보 |
|---|---:|---:|---:|---:|
| 100건/초 · 4KiB · 300건 | 1,200 → 0 | 0 → 600 | 300 → 11 | 300 → 0 |
| 500건/초 · 4KiB · 1,500건 | 6,000 → 0 | 0 → 3,000 | 1,500 → 11 | 1,500 → 0 |
| 200건/초 · 64KiB · 600건 | 2,400 → 0 | 0 → 1,200 | 600 → 11 | 600 → 0 |
| 버스트 · 4KiB · 1,500건 | 6,000 → 0 | 0 → 3,000 | 1,500 → 1 | 1,500 → 0 |

모든 시나리오에서 콜백 수·저장 원본 수·표시 행 수가 같았습니다. 각 시나리오 처음·가운데·마지막의 요청·응답을 원본 바이트와 대조하여 버전별 12쌍을 확인했고, 종료 후 임시 원본 파일 삭제도 확인했습니다. 수집 개수나 본문 크기를 줄여 얻은 결과가 아닙니다. 행 벡터 0개는 중복 테이블 행 저장을 없앴다는 뜻이며 전체 힙이 상수 크기라는 뜻은 아닙니다.

## 디스크·메모리 비용

| 입력 | 디스크 bytes, 기준 → 후보 | 추가 디스크 | 표본 최대 사용 힙 bytes, 기준 → 후보 |
|---|---:|---:|---:|
| 100건/초 · 4KiB · 300건 | 1,249,800 → 1,292,700 | +42,900 (3.432549%) | 32,188,096 → 26,090,064 |
| 500건/초 · 4KiB · 1,500건 | 6,249,000 → 6,463,500 | +214,500 (3.432549%) | 46,902,016 → 46,121,888 |
| 200건/초 · 64KiB · 600건 | 39,363,600 → 39,449,400 | +85,800 (0.217968%) | 46,331,568 → 47,038,464 |
| 버스트 · 4KiB · 1,500건 | 6,249,000 → 6,463,500 | +214,500 (3.432549%) | 46,711,312 → 28,661,896 |

후보는 원본 외에 메타데이터와 패킷당 12바이트 색인 항목을 기록합니다. 이 합성 URL·도구명에서는 총 **143바이트/패킷**이 추가됐습니다. URL 등 메타데이터 길이에 따라 달라지므로 모든 실제 패킷에 고정된 비용은 아닙니다.

힙은 JVM 사용 시점의 표본이며 보존 힙 정밀 측정이 아닙니다. GC·임시 객체·호스트 부하의 영향을 받습니다. 64KiB 시나리오의 표본 최대 힙과 일부 콜백·버스트 EDT 지연은 증가했으므로 모든 지표가 개선됐다고 해석하지 않습니다.

## Mapper 조회와 상관관계

기능 100개에 패킷을 넣고 각 기능의 패킷 조회를 30회 반복했습니다. 두 경우 모두 조회 호출은 3,000회입니다.

| 패킷 수 | 입력 시간 (ms), 기준 → 후보 | 기능 조회 (ms), 기준 → 후보 | 반환 멤버십 수 | 반환 패킷 ID 합 |
|---:|---:|---:|---:|---:|
| 5,000 | 233.548167 → 340.584388 | 293.868232 → 19.519935 | 150,000 | 375,075,000 |
| 15,000 | 450.569585 → 599.009880 | 1091.470506 → 20.820412 | 450,000 | 3,375,225,000 |

멤버십 수와 ID 합은 기준·후보가 같습니다. 조회 비용은 줄었지만 인덱스를 유지하는 입력 비용은 증가했습니다.

브라우저 상관관계는 기존 패킷 600개, 무관 URL 이벤트 40개, 일치 이벤트 20개, 무관 신규 패킷 200개를 사용했습니다.

| 단계 | 기준 (ms) | 후보 (ms) |
|---|---:|---:|
| 무관 URL 이벤트 40개 | 55.717928 | 11.677168 |
| 일치 이벤트 20개 | 44.098921 | 14.607340 |
| 무관 신규 패킷 200개 | 268.411867 | 13.968477 |

후보의 무관 URL 이벤트 처리에서 검사한 인덱스 후보 증가량은 **0**, 전체 시나리오 누계는 **43**입니다. 기준 버전에는 이 계측기가 없어 기준 후보 수를 추정값으로 채우지 않았습니다. 두 버전 모두 고유 연결 20개를 만들고, 같은 요청을 추가하자 모호해진 연결 1개를 해제하여 19개를 유지했습니다. 원본 패킷은 801개 모두 남았습니다.

## 계측 소스와 재현

다음 값은 하네스가 Java 소스 경로와 바이트를 합산한 SHA-256입니다. Git 커밋 ID나 배포 파일 해시가 아닙니다. 수집은 운영·테스트 Java, Mapper는 운영 Java 소스를 포함합니다.

| 구성 | 기준 소스 SHA-256 | 계측 후보 소스 SHA-256 |
|---|---|---|
| 수집 | `d67e554306aa7bee995c06895c84e5a4eed12f9397bc75239c69d7b497a4e52f` | `fb7d5bf3bdb857e0804bc87aebe7b7b30b3f4cd579fc461ac0c502fdcfe60810` |
| Mapper | `a10dc7b21cb423e2d08528c3795479c3f048f251d8014171cfe061a424b4009c` | `8e304fc24bb693fe0f96ce946dcc514e98682229dcdfc1536bc24a1e5e9306e3` |

수집 Java 하네스: `444d5a6c61864e1888e480c1d645b379cce83437a17793d835d79033fe78b0e0`.
Mapper Java 하네스: `81f1bfcf5ecf36f3db0967e4bdc943b3201b0de52929b53cefd9f6819fa26e16`.

하네스 해시는 각각 기준과 후보가 동일합니다. Java·의존성 지문, 모든 지연 분포와 힙 시작/종료값은 JSON에 포함했습니다.

```sh
python audit/performance/run.py --baseline /path/to/baseline-0.25.5 --candidate /path/to/candidate-0.26.0 --dependencies /path/to/repository-with-deps --output tmp/performance/comparison-new
```

두 소스를 별도 경로에 준비하고 매번 새 출력 경로를 지정합니다. 하네스는 공유 `build/`·`dist/`와 배포 파일을 변경하지 않습니다. 자세한 측정 정의는 [하네스 안내](../audit/performance/README_KR.md), 최종 배포 파일과 전체 회귀 결과는 [릴리스 검증 기록](VERIFICATION_0.26.0.json)을 기준으로 합니다.

이번 측정에는 대량 목록 검색어 입력·정렬 비용, native Burp/실제 브라우저, 다시간 수집, 운영체제 간 비교가 포함되지 않습니다. 검색은 전체 보관 행을 대상으로 유지하지만 현재 메타데이터 검색·정렬은 EDT에서 실행하므로 추가 대규모 계측이 필요합니다.
