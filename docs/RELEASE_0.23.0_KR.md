# 0.23.0 변경 안내

확장 0.23.0 / Community Security Lab 3.5.0. 이 브랜치는 이전 PR #2의 0.22.1 개선을 함께 포함합니다. 이전 배포 파일은 덮어쓰지 않습니다.

## 진단 과정에서 달라진 동작

| 문제 | 변경 후 |
|---|---|
| 저장 요청과 별도 조회가 연결되어도 증거 수준이 불분명 | 쓰기 2xx, 조회 마커, HTML 출력, 사용자 수동 브라우저 실행을 별도 표시 |
| Passive 결과와 데이터 차이에 실제 요청/응답을 따로 찾아야 함 | 선택 관찰·좌우 비교·URL GET 검증·저장/조회에서 원본을 증거 묶음으로 전달 |
| 먼저 수집한 200 응답들이 대표 URL 5개를 선점 | 상태와 관측 메서드별 그룹에서 번갈아 대표 선택, GET 재검증 후 목록 갱신 |
| 인증을 지정하지 않은 GET을 비로그인 검사로 단정 | Burp 세션 규칙이 반영된 실제 요청을 보존하고 실제 인증 확인 안내 |
| 저장 전 가림 결과를 확인하기 어려움 | ZIP과 같은 패킷 포맷터를 사용하는 가림 미리보기 |
| 브라우저 이미지가 바뀌거나 다른 흐름 이미지로 대체될 수 있음 | 연결·저장 시 SHA-256 확인, 다른 이미지 충돌은 패킷 추가 전 거부 |
| 가이드·현재 검증·과거 문서가 섞임 | 첫 화면에 다운로드/가이드/모의 진단 진입점, 문서 목차와 위치 안내, 과거 개발 안내 보관 |

0.22.1의 역할·조직 변경 재검토, 중요 입력값 변경 감지, 계정×API 증거 요건 및 파일 재연결 기능도 유지합니다.

## 새 실습 사이트

`/bounty-lab`은 객체 201~206의 공개/소유자/조직/공유 정책을 같은 URL 형태에서 비교합니다. Alice·Bob·Moderator·Admin·비로그인과 vuln/fixed를 대조합니다. 저장→조회, HTML 업로드→다른 계정 다운로드, MIME/Disposition, CSRF, 삭제·초기화 기능을 제공합니다.

실습 데이터는 메모리에 보관하며 한 계정 64개, 전체 256개, 업로드 64KiB 한도가 있습니다. 초기화는 로그인한 사용자의 신규 bounty 실습 데이터만 삭제합니다. 자세한 절차는 [모의 진단 가이드](TEST_WORKFLOW_KR.md)와 사이트의 `BOUNTY_LAB_3.5_KR.md`를 참고하세요.

## 원본·실행 근거 사용법

1. 대상 SCOPE와 계정·기대 정책을 먼저 지정합니다.
2. 응답 분석에서 고유 마커를 등록하고 실제 저장·조회를 수행합니다. 화면의 각 단계는 관찰 근거이며 자동 취약점 확정이 아닙니다.
3. 실제 브라우저 실행을 확인한 경우에만 해당 행에서 수동 확인과 민감정보를 가린 PNG/JPEG를 연결합니다.
4. 각 도구의 증거 보내기 버튼을 누릅니다. 원본이 만료되었거나 크기를 넘으면 다시 관측합니다. 입력을 편집한 데이터 비교는 원본 연결이 해제됩니다.
5. 점검 지원 → 증거 묶음에서 영향·재현 절차를 작성하고 가림 미리보기 후 저장합니다.

원본 자동 연결은 건당 요청+응답 합계 128KiB, 응답 분석 캐시는 종류별 최대 100건입니다. 증거 묶음은 최대 32개 요청입니다. 데이터 비교 표시는 64KiB/1,500줄 제한이며 큰 입력의 전체 차이를 의미하지 않습니다.

ZIP 하나에는 브라우저 이미지 한 장을 연결합니다. 서로 다른 이미지는 기존 증거를 저장하고 비운 뒤 별도 ZIP에 저장합니다. 이미지와 직접 작성한 영향/재현 문장은 개인정보가 자동으로 완전히 가려지는 자료가 아닙니다. JSON/폼 본문은 선택 포함하며 일반 HTML/바이너리 원문 파일 첨부는 이번 버전에서 제공하지 않습니다.

## 검증

공식 명령은 `python dev.py release`입니다. 확장 회귀·페이로드 HTTP → 전체 기능 HTTP → 신규 커뮤니티 모의 진단 → 버전별 패키징 순서로 실행합니다. 정확한 수치·파일 해시·로그는 [검증 JSON](VERIFICATION_0.23.0.json)에 기록합니다.

새 모의 진단은 최신 확장 JAR의 운영 로직과 현재 lab 소스를 컴파일한 실제 loopback Spring/Tomcat/H2 서버를 사용합니다. 과거 WAR는 실행하지 않습니다. 초기 전체 검사에서 드러난 JS 패널 테스트의 작업 큐/EDT 대기 경쟁 상태도 수정했습니다. 독립 코드 검토에서 확인한 응답 분석 종료 후 원본 캐시 재저장 문제와 이미지 연결 일관성 문제를 회귀 검사에 포함했습니다.

이번 환경에는 Burp 본체와 Docker 실행 환경이 없어 실제 Burp 로드/GUI, 브라우저 DOM, 전체 Docker/Oracle/Nginx, Pro Collaborator 및 외부 BApp 실행은 미검증입니다. PDF 그림은 운영 Swing 컴포넌트를 API 어댑터로 렌더링한 예시 화면입니다. 과거 버전의 실제 Burp/Chromium 검증을 현재 버전의 실적으로 합산하지 않습니다.

## 다운로드와 후속 검증

[JAR·소스·Docker·PDF](../downloads/README.md)에서 각 버전을 받습니다. Docker ZIP은 현재 소스를 빌드하는 실행 패키지이며 사전 빌드 이미지나 오프라인 설치 파일이 아닙니다.

후속 현장 검증: 별도 Burp 프로필에서 JAR 로드, 브라우저 저장형 실행 근거 확인, 장시간 수집과 큰 응답, 실제 Docker 스택 및 TLS/HTTP2 확인. 자동 `/me` 신원 검증과 정책 태그별 URL 대표 선택, 일반 바이너리 증거 첨부는 추가 개선 후보입니다.
