# 0.25.0 변경 안내

**무슨 일을 하는 도구인지 이름에서 알 수 있게 바꾸고, 화면 안에서 사용 순서를 확인하도록 개선했습니다.** 확장 버전은 **0.25.0**, 커뮤니티 실습 사이트와 Docker 패키지는 **3.5.0**입니다.

[최신 JAR·소스·PDF](../downloads/README.md) · [처음 설치하고 사용하기](../README.md#설치하고-첫-요청-확인하기) · [화면·버튼 안내](UI_0.25.0_KR.md) · [로컬 점검 순서](TEST_WORKFLOW_KR.md)

## 기능 이름 대응표

| 이전 이름 | 0.25.0 이름 | 이 도구로 하는 일 |
|---|---|---|
| 트래픽 | **요청·응답 목록** | 관측한 요청 선택, 원본 확인, 공통 SCOPE 등록 |
| 권한 비교 | **계정 권한 비교** | 같은 요청을 계정·세션별로 비교 |
| 데이터 도구 | **데이터 변환·비교** | 인코딩 변환, JWT 내용 읽기, 두 입력 차이 확인 |
| JS 추출 | **JS에서 API 찾기** | JavaScript의 API·입력 후보와 원본 위치 확인 |
| 환경 탐색 | **서버·경로 탐색** | 서버 정보와 경로 후보를 점검 대상으로 연결 |
| URL 수집 | **URL 후보 수집** | 출처별 경로를 모으고 실제 관측과 구분 |
| 활동 추적 | **점검 진행 현황** | URL·계정·업무의 점검 및 재검토 상태 관리 |
| 응답 분석 | **응답 보안 분석** | 응답의 보안 단서, API 문서, 쓰기·조회 관계 확인 |
| 페이로드 검사 | **입력값 보안 검사** | 선택한 입력을 바꿔 기준·검사·대조 응답 비교 |
| 점검 지원 | **재현·증거 정리** | 순서가 있는 요청 재현, 외부 결과 연결, 증거 저장 |

하위 화면도 데이터의 **인코딩·변환 / JWT 내용 확인 / 응답·데이터 비교**, 응답 보안 분석의 **응답 관찰**, 재현·증거 정리의 **여러 요청 재현 / 외부 연결 확인**처럼 용도를 드러냅니다. 외부 연결 확인은 콜백 서비스에서 대상의 외부 상호작용을 확인하는 OAST 연결 기능입니다.

기존 문서의 이름은 위 표로 대응할 수 있습니다. 기능 이름이 바뀌어도 같은 원본 요청·계정 조건·점검 기록을 사용하는 흐름은 이어집니다.

## 사용 흐름에서 달라진 점

| 이전에 어려웠던 점 | 0.25.0에서 확인할 수 있는 것 |
|---|---|
| 도구 이름만으로 용도를 추측해야 함 | 하고 싶은 작업을 드러내는 상위 화면 이름 |
| 화면을 연 뒤 무엇부터 입력해야 할지 찾기 어려움 | 화면 안 **기능 안내**에서 목적과 준비 순서 확인 |
| 오래된 이름과 여러 배포 문서가 섞여 시작점을 찾기 어려움 | README 첫 사용 순서, 최신 JAR·PDF 우선 링크, 이전 이름 대응표 |
| PDF의 설명과 현재 화면 이름을 다시 맞춰 읽어야 함 | 0.25.0 화면 이름으로 정리한 단계별 그림 가이드 |
| Record ON이나 우클릭 동작이 언제 요청을 보내는지 불명확함 | **새 요청 자동 비교 OFF/ON**, **선택 요청 계정 비교 실행**, **URL 후보 수집 시작**처럼 동작을 드러내는 이름 |
| 도메인 전체가 어디까지 포함하는지 모호함 | **현재 사이트 전체 경로 추가**로 같은 프로토콜·호스트·포트 범위를 안내 |

목적은 점검 도구를 쉽게 찾고 필요한 다음 동작을 줄이는 것입니다. SCOPE를 지정했다고 계정 비교나 입력값 검사를 모두 실행하지 않습니다. 관측한 응답의 분석과 공통 범위 적용은 반복 작업을 줄이고, 추가 요청·Repeater 전송·수동 판단·증거 저장은 사용자가 선택합니다.

## 처음 사용한다면

1. **요청·응답 목록**에서 정상 요청 한 건을 선택합니다.
2. 우클릭 → **SCOPE 지정**에서 필요한 경로나 도메인을 추가합니다.
3. 원본을 읽고 목적에 맞는 도구를 고릅니다. 계정 차이는 **계정 권한 비교**, 응답 차이는 **데이터 변환·비교**, 입력값 변화는 **입력값 보안 검사**에서 확인합니다.
4. 현재 화면의 **기능 안내**를 읽고 준비한 입력을 확인한 다음 필요한 동작만 실행합니다.
5. 재현한 원본과 결과를 **재현·증거 정리**에 모으고 가림 내용을 확인한 뒤 ZIP으로 저장합니다.

상세 클릭 순서는 [화면 안내](UI_0.25.0_KR.md)와 [모의 진단 흐름](TEST_WORKFLOW_KR.md)을 따릅니다. 회색 버튼은 먼저 선택한 행·연결 원본·실행 중 상태를 확인하세요.

## 검증과 배포

이번 실행의 검사 결과·산출물 해시·미검증 항목은 [0.25.0 검증 기록](VERIFICATION_0.25.0.json)을 기준으로 확인합니다. 테스트 수를 이전 버전과 합산하지 않습니다. 화면 렌더링은 운영 Swing 구성 요소와 합성 데이터를 사용하며 실제 Burp GUI·브라우저·Docker 실행과 구분합니다.

```sh
python dev.py release
python tools/render_ui_layout.py --out tmp/ui-layout --check
python tools/package_downloads.py --verify
```

JAR·소스 ZIP은 `downloads/extensions/0.25.0/`, PDF는 `downloads/guides/0.25.0/`에 둡니다. 0.24.0을 포함한 이전 파일과 검증 기록은 보존합니다. 실습 사이트와 Docker 3.5.0은 계속 사용합니다.
