# 0.25.1 — 요청·응답 목록 수집 중단 수정

HTTP history에는 응답이 늘어나는데 Workbench 목록은 145건 같은 중간 숫자에서 멈추는 경우를 조사했습니다. 145건이라는 별도 한도는 없습니다. 인증 후보 분석 등에서 예외가 발생하면 Swing Timer의 다음 갱신까지 멈출 수 있었습니다. Java 17의 실제 타이머에서 첫 예외 뒤 기존 타이머가 한 번만 실행되고, 예외를 처리한 타이머는 계속 실행되는 것을 재현했습니다. 사용자의 Burp에서 발생한 최초 오류는 실제 로그 없이 확정할 수 없습니다.

## 바뀐 동작

- 정상 요청은 먼저 목록에 보관하고, 서버 환경·인증 후보 관찰은 각각 오류를 처리합니다. 후보 분석이 실패해도 해당 패킷과 다음 패킷을 계속 보관합니다.
- 목록용 메타데이터를 읽을 수 없는 패킷은 그 항목만 건너뛰고 다음 항목을 처리합니다.
- 타이머 전체에도 예외 처리를 추가해 다음 갱신이 막히지 않도록 합니다.
- 응답 보안 분석·활동 현황·자동 계정 비교 오류가 원본 수집이나 Burp의 요청·응답 통과를 막지 않도록 각 단계를 분리합니다.
- Burp 우클릭으로 여러 요청을 가져올 때도 항목별 오류를 처리합니다.
- 하단에 **수신 / 대기 / 크기 제외 / 큐 초과 / 오류**를 따로 표시합니다. 상태 표시 위에 마우스를 올리면 마지막 응답 시각과 마지막 오류 단계도 확인할 수 있습니다.
- Extensions → Workbench → Errors에 오류 단계·예외 종류·Workbench 코드 위치를 기록합니다. 패킷 원문과 예외 메시지는 기록하지 않으며, 반복 오류는 기록 빈도를 줄입니다.

## 설치 후 확인

1. 기존 Workbench를 해제한 뒤 `burp-workbench-kr-0.25.1.jar`를 Java 확장으로 추가합니다.
2. 수집 ON 상태에서 Burp 브라우저로 사이트를 사용하고 **수신**과 **보관**이 늘어나는지 확인합니다.
3. 보관이 늘지 않으면 **크기 제외 / 큐 초과 / 오류** 중 무엇이 증가하는지 확인합니다. **오류**가 증가하면 상태 표시의 마지막 오류 단계와 Extensions의 Errors를 함께 확인합니다.

수신 수는 수집 OFF나 Scope 제한으로 제외되는 응답도 포함한 확장 로드 이후 누적 수입니다. 목록 비우기는 보관 목록을 지우며 누적 진단 수를 초기화하지 않습니다. 크기 제외와 큐 초과는 보관에서 빠진 항목 수이며, 오류는 처리 단계의 실패 횟수입니다. 부가 분석 오류는 패킷을 보관한 경우에도 셀 수 있습니다.

## 이번 수정의 범위

0.25.0 코드에 대한 안정화 배포입니다. 보관 한도는 최근 250건, 요청·응답 합계는 128KiB, 자동 갱신 대기열은 250건입니다. 이 수치는 상태 도움말에서 확인할 수 있습니다. 큰 응답 보관·보관량 확대·ON/OFF/SCOPE 통합은 별도 작업으로 기록되어 있으나, 이번 출발 커밋의 소스에는 없어 이 수정과 섞지 않았습니다.

현재 배포는 JAR와 소스 ZIP을 새 버전 폴더로 제공합니다. 사용 가이드는 0.25.0용 개정판을 함께 참고합니다. 실제 검사 결과는 [검증 기록](VERIFICATION_0.25.1.json), 이어받을 내용은 [인수인계](HANDOFF_0.25.1_KR.md)에 기록합니다. 실제 Burp GUI는 이 환경에 설치되어 있지 않아 검증하지 못했습니다.
