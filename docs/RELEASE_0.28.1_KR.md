# Workbench 0.28.1 · OFF / SCOPE 수집

전체 수집 ON을 제거했습니다. 새로 로드하면 OFF이며 클릭할 때 OFF ↔ SCOPE만 전환합니다. OFF는 새 트래픽의 저장·수동 가져오기와 자동 분석용 관찰을 차단하고 이전에 수집한 목록은 유지합니다.

SCOPE에서는 Burp **HTTP history → Add to scope**로 지정한 Target Scope와 Workbench SCOPE 목록의 체크 상태를 모두 통과한 URL만 수집합니다. Burp의 경로·포트·고급 규칙과 제외 규칙을 따릅니다. Scope가 비어 있거나 조회에 실패하면 수집하지 않습니다. 네이티브 범위가 제거되면 아직 로컬 행이 남아 있어도 새 패킷을 받지 않습니다. 기존의 체크 해제·삭제·프로젝트 저장 상태도 유지합니다.

Workbench에서 URL을 직접 추가한 규칙은 개별 도구의 대상 지정에 사용할 수 있지만 트래픽 수집을 허용하지 않습니다. 직접 추가한 넓은 도메인 규칙도 체크 해제된 네이티브 항목이나 Burp 제외 범위를 우회하지 못합니다. Burp의 범위 판정이 기준이므로 Add to scope 메뉴 이외의 방법으로 설정한 같은 Target Scope도 동일하게 동작합니다. 개별 도구의 명시적 실행과 이미 시작한 계정 비교의 응답 처리는 수집 버튼과 별개입니다.

## 사용

1. 기존 확장을 해제하고 [0.28.1 JAR](../downloads/extensions/0.28.1/burp-workbench-kr-0.28.1.jar)를 로드합니다.
2. Burp HTTP history에서 원하는 URL을 **Add to scope**로 등록합니다.
3. Workbench SCOPE 목록의 Burp 항목을 체크하고 **OFF → SCOPE**로 바꾼 뒤 사이트를 사용합니다. 과거 History는 범위 내 요청만 골라 Workbench로 가져옵니다.
4. 수집을 멈추려면 **SCOPE → OFF**로 바꿉니다.

## 레이아웃 시안

사용자가 요청한 큰 페이지 제목·검색 라벨 삭제, 검색 입력 상단 이동, 트래픽·요청·응답 영역 확장은 **대화에 제시한 이미지 시안에만** 적용했습니다. 운영 코드의 화면 배치·제목·검색 라벨·패킷 분할 구조는 변경하지 않았습니다. 두 모드의 상태 표시와 안내 문구만 기능에 맞춰 갱신했습니다.

## 검증

정식 release 2,016개(Java 48그룹 1,517개·페이로드 HTTP 132개·전체 기능 HTTP 101개·모의 진단 266개), 운영 Swing 144화면·안내창 48화면, 패키징 4개를 통과했습니다. 로컬 15초 연속 수집 321개는 누락·처리 오류 0건입니다. 실행 건수와 산출물 해시는 [검증 기록](VERIFICATION_0.28.1.json)에 기록합니다. API 어댑터를 통해 실제 HTTP 콜백·우클릭 가져오기·Scope 변경 알림·운영 Swing 구성요소를 검사합니다. 화면 테스트의 합성 데이터는 수집 정책을 우회한 전용 시드로 주입하며, 실제 수집 정책은 별도 콜백 및 우클릭 테스트로 확인합니다. 실제 Burp GUI·운영체제 DPI 검증과는 구분합니다.
