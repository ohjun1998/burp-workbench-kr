# Workbench 0.44.0 변경 안내

CSV·파일의 HTTP 200 오류 응답으로 발생한 잘못된 권한 우회 경고를 줄이고, 쓰기 요청에서 보류한 이유를 구체화했습니다.

## 적용한 개선

1. 기준 응답이 CSV·파일이어도 대상 응답의 JSON 차단 규칙을 검사합니다. 오류와 데이터·소유값·중요 필드가 함께 있으면 **차단 응답과 데이터 충돌**로 보류합니다.
2. 쓰기 검증 미설정, 처리 결과 미확인, 지연 처리, 기대 상태 미도달, 후속 조회 실패, 전후 조회 준비 실패를 구분합니다. 기대 권한 DENY·명시적 차단·지정 조회 항목 미변경을 함께 확인하면 차단 근거를 유지합니다. 변경 없음만으로 안전을 확정하지 않습니다.

403 응답 뒤 실제 저장 변경이 관측되면 계속 우회 의심으로 탐지합니다. 기존 레이아웃·색상·OFF/SCOPE는 유지하며 쓰기를 자동 반복하거나 되돌리지 않습니다. 후속 GET은 설정대로 최대 3회, 두 번째부터 500ms 간격입니다.

## 재검증 결과

50개 기능·7개 인증 방식·관리자/Alice/Bob/비로그인·정상/취약 경로와 두 설정으로 실제 Burp 비교 1,400기록·계정 대조 4,200개를 실행했습니다. 설정 후 2,100개 대조에서 정탐 392·오탐 0·미탐 0·보류 91입니다. 이전 오탐 21개를 없앴고 보류 623개 중 532개가 줄었습니다. 실습 반복 측정으로 운영 탐지 확률을 뜻하지 않습니다.

정식 회귀·HTTP 2,890개(신규 39개), 패키징 6개와 별도 HTTP 2,800개·잘못된 인증 조합 33개를 확인했습니다. 실제 Burp는 임시 프로필과 H2 Oracle 호환 모드입니다. GUI·Windows DPI/IME·실제 Oracle/Nginx는 이번에 다시 실행하지 않았습니다.
