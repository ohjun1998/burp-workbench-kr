# Workbench 0.48.0 · 미탐 보강과 재검증

이전 보고서의 변형 XSS 4건과 JSON 정보 노출 2건을 보강했습니다. 기존 11개 메뉴와 화면 구조는 유지합니다.

| 변경 | 새 동작 |
|---|---|
| 변형 XSS | 공백 없는 검사값·끝 완충 문자, 이벤트 속성 문맥을 확인합니다. HTML 주석·스크립트 문자열·템플릿·이스케이프 대조를 제외합니다. 후보와 브라우저 실행을 구분합니다. |
| JSON 진단 | `/debug/systemDiagnostics`와 런타임·DB·환경 키를 근거로 후보를 표시합니다. 일반 입력 검증 오류와 구분합니다. |
| 서비스 비밀 키 | 경로와 무관하게 streamKey 등 이름·값 특성으로 후보를 찾습니다. 근거는 위치와 가린 길이이며, 키 유효성을 검사하거나 추가 요청을 보내지 않습니다. |
| 응답 범위 | 앞64KiB 제한을 1Mi 문자까지 넓히고 구조·크기·후보 제한은 별도 관찰로 표시합니다. |
| SQL 오류 | 일반적인 `SQL syntax` 설명만으로 DB 오류를 표시하지 않습니다. SQLite·H2·PostgreSQL·ORM·MySQL 고유 표식은 유지합니다. |
| 대형 JS | 문자열·정규식 경계를 보강하고 구간 간 최상위 const 문자열을 연계합니다. 객체·함수·강제 분할 문맥은 미확정으로 남깁니다. 도메인·소스맵 보조 분석의 앞512Ki 문자 범위도 알립니다. |
| 권한·XML·404 | 설정한 JSON 거부 규칙을400/422에서도 확인하되 자료 동반 시 보류합니다. 기본 XML 검사값은 원본 description·업무 필드를 보존합니다. 큰404는 상태와 내용 미검사를 나눠 표시합니다. |

## 실제로 다시 확인한 범위

| 표본 | 0.47.0 | 0.48.0 |
|---|---|---|
| Benchmark XSS24개 | 정탐8·미탐4·정상12·오탐0 | 정탐12·미탐0·정상12·오탐0 |
| OopsSec 기존3개+추가 입력 오류1개 | 정탐0·미탐2·정상2·오탐0 | 정탐2·미탐0·정상2·오탐0 |

두 버전의 배포 엔진을 같은 JDK로 빌드하고 고정된 원본 대상 소스·입력 위치·Accept·예산으로 실제 loopback HTTP를 대조했습니다. XSS 기본 목록은 의도적으로7개에서10개로 늘었습니다. Benchmark24개는 요청192→264건입니다. 기존29개 XSS 전체·17개 SQL·39개 외부 계정 대조의 새 성능 수치로 합산하지 않습니다.

실제 HTTP 응답을 격리된 Chromium headless-shell146에서 렌더링하고 console 표식을 대조했습니다. 취약12개에서 실행, 안전12개에서 실행 없음입니다. 대상 페이지의 직접 탐색·Burp 브라우저 실행과는 다릅니다.

`python dev.py release`는 회귀2,590개+페이로드 HTTP136개+전체 기능 HTTP102개+업무 HTTP266개, 총3,094개를 통과했습니다. 신규 회귀45개입니다. 별도 Mapper94개·Node7개, 패키징 단위5개와 156개 Swing 화면도 확인했습니다. 종류가 다른 검사 수를 합한 값이며 취약점 탐지율의 분모가 아닙니다.

## 남은 확인

- 기존7개 사이트×11개 도구의 실제 Burp 전체 재측정은 수행하지 않았습니다. 이번 Burp GUI 수동 조작·외부 AI/OAST·Docker 검증도 없습니다.
- Chrome/Edge 도우미 클릭 연결은 미검증입니다. 이 환경의 전체 Chrome은 Unix 소켓 생성이 차단돼 시작하지 못했습니다. headless-shell DOM 대조와 구분합니다.
- 이전6.56M자 번들과 구간 간 객체·함수 문맥, Juice Shop 주소400·DVBank SQL/XML 실서버는 추가 검증이 필요합니다. 401 응답은 계속 후속 요청을 중단합니다.
