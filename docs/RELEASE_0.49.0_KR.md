# Workbench 0.49.0 · 수집 근거와 분석 한계 보강

Workbench 0.49.0과 내장 Feature Mapper 0.3.3은 기존 11개 메뉴에서 수집·연계·판정·증거 저장의 근거를 더 분명하게 표시합니다. 전체 도구를 재검토하면서 발견한 요청 간격 누락, 불완전한 신원 응답의 오판, 변경된 JS 상수의 잘못된 연계도 보완했습니다. 실습 사이트 버전은 3.10.0을 유지합니다.

## 메뉴별 변경

| 화면 | 이번 변경과 확인할 점 |
|---|---|
| 요청·응답 목록 | 자동 응답 수신과 수동 History 가져오기를 구분합니다. OFF·SCOPE 제외, 보관 성공, 저장 실패, 처리 오류를 각각 집계하며 정책상 제외한 패킷은 보관하지 않습니다. 누적 성공 수와 현재 목록 보관 수를 구분합니다. |
| 기능 자동 매핑 | 브리지 실행, 인증된 도우미 연결, 최근 이벤트 수신, 실제 HTTP 연결을 따로 표시합니다. 같은 클릭·시각·URL이라도 메서드와 본문 SHA-256이 다른 요청을 덮어쓰지 않습니다. URL·메서드·시간·본문 해시 대조와 모호한 연결 취소를 보강했습니다. |
| 계정 권한 비교 | 기존 계정·신원·정책·쓰기 전후 조회를 유지합니다. 이번 입력값 검사에 추가한 신원 대조와 별도 기능이며, 단일 응답 코드나 신원 일치만으로 접근 권한을 확정하지 않습니다. |
| 데이터 변환·비교 | 기존 변환·JWT 내용 확인·응답 비교와 원본 증거 연결을 유지합니다. 연결된 증거에는 이번 공통 가림 정책을 적용합니다. JWT 서명 검증 기능을 추가한 것은 아닙니다. |
| JS에서 API 찾기 | 큰 파일의 구간 간 상수·중첩 데이터 속성·단순 반환 함수를 제한적으로 연계합니다. 변경·별칭·외부 전달·동적 실행을 검사하고, 알 수 없는 baseURL에 실행 페이지의 호스트를 임의로 붙이지 않습니다. 원본 위치와 미확정 표시를 유지합니다. |
| 서버·경로 탐색 | 큰 응답의 HTTP 상태와 본문 분석 범위를 나눠 표시합니다. 없는 경로와 비교할 기준이 비었거나 너무 크거나 불안정하면 대조하지 못한 이유를 알립니다. 앞부분만 같은 응답을 전체가 같은 것으로 판단하지 않습니다. |
| URL 후보 수집 | 직접 관측·정적 추정·외부 아카이브·수동 가져오기를 구분합니다. 발견 메서드와 별도로 실행한 GET 확인의 시각·결과·원본 보관 여부를 표시하고 Excel로 내보냅니다. 경로·쿼리 순서·중복 키·퍼센트 인코딩이 다른 URL을 무리하게 합치지 않습니다. |
| 점검 진행 현황 | 계정별 목록에 ‘검사 시도 없음’과 ‘증거 미저장’ 필터를 추가했습니다. 수동 완료 상태와 검사·증거의 공백을 따로 확인할 수 있습니다. 검사 시도는 전체 프로필 검증 완료를 뜻하지 않습니다. |
| 응답 보안 분석 | 큰 JSON의 비밀 키·진단정보 구조 후보를 순차 검사합니다. 일반 문자열 규칙, JSON 구조 검사, 수신 본문 한도를 구분하고 미검사·큐 제외·처리 오류를 표시합니다. 한도 초과를 근거 없음으로 숨기지 않습니다. |
| 입력값 보안 검사 | 사용자가 켠 경우에만 같은 대상의 신원 확인 GET을 검사 전·비로그인·401/403 후에 대조합니다. 추가 요청도 총 예산·간격·SCOPE·중지 조건을 따릅니다. 신원 일치·불일치·미확인을 구분하고 불완전한 비로그인 대조에서는 검사값을 보내지 않습니다. |
| 재현·증거 정리 | 기본 민감 이름과 추가 지정 이름의 헤더·JSON·폼 값을 가립니다. 원본에서 확인한 민감값이 다른 필드·설명에 반사된 경우의 가림을 확대했습니다. 잘린 본문·미지원 형식·가림 한도는 제외 또는 저장 중단으로 표시하며 원본 바이트와 가린 텍스트의 길이·해시를 구분합니다. |

## 분석과 신원 대조의 범위

JS 연계는 실행하지 않는 정적 추정입니다. 구간 간에는 최상위 상수, 데이터 객체의 점 표기·상수 문자열 인덱스, 정적 인자를 받는 단일 무조건 반환 함수와 arrow를 제한적으로 지원합니다. 정적 `url` 속성이 있는 최상위 상수 객체를 단일 인자로 넘기는 `axios(request)`·`axios.request(request)`도 연계하며, 원본 호출의 인자 위치와 메서드를 보존합니다. 사전 검사에서 객체 변경·별칭·외부 전달·명시적 `eval`·`Function`이 발견되면 연계하지 않습니다. 조건부·부수 효과 함수의 반환값을 확정하지 않으며 강제 분할의 구간 간 연계도 제외합니다. 복잡한 객체 전달·프레임워크 런타임·실제 호출 도달 여부를 모두 복원하지 않습니다.

응답 보안 분석은 수신 본문 **2 MiB**를 넘으면 본문 미검사 기록을 남깁니다. 일반 문자열 규칙은 **앞 1 Mi 문자**, 큰 JSON 구조 검사는 **최대 2 Mi 문자**입니다. JSON에는 항목 100,000개·깊이 64·후보 32개 등 별도 한도가 있고, 큰 문자열을 전체 트리로 보관하지 않습니다. JSON 구조를 더 읽었다고 일반 문자열 규칙까지 후반부 전체를 검사한 것은 아닙니다. 형식 오류와 한도 도달 시 불완전 상태를 표시합니다.

서버·경로 탐색은 **1 Mi 문자**까지 전체 본문을 확인합니다. 이를 넘으면 앞·뒤 각각 512 Ki 문자에서 보조 단서를 찾고 중간 미검사 길이를 표시합니다. 큰 404·401·429의 상태는 유지하며, 부분 본문만으로 노출·부재·기준 응답과의 동등성을 확정하지 않습니다.

입력값 검사의 신원 대조는 기본 꺼짐입니다. 같은 대상의 `/api/me` 같은 GET 경로, 지원하는 JSON 경로, 기대 신원을 직접 설정합니다. JSON 한도·중복 키·형식 오류·잘린 본문·미지원 인코딩은 ‘신원 미확인’입니다. 비로그인 응답이 401이어도 신원을 읽을 수 없는 경우에는 검사값을 보내지 않습니다. 401/403 뒤 신원이 유지되어도 검사값 전송을 재개하지 않으며 대상별 권한·CSRF·업무 오류의 원인은 미확정으로 남깁니다.

증거 ZIP은 가린 텍스트 증거입니다. 원본 길이·해시는 Burp API가 제공한 HTTP 바이트를 기준으로 하며 네트워크·TLS 원시 캡처를 뜻하지 않습니다. 자동 가림은 모든 개인정보를 찾아내는 기능이 아니며, 사용자 첨부 이미지는 자동으로 가리지 않습니다. 저장 전 미리보기에서 확인하고, 재현에 필요한 인증값은 로컬 원본에서 확인합니다.

## 이번 검증과 실행하지 못한 범위

전체 회귀 결과는 [VERIFICATION_0.49.0.json](VERIFICATION_0.49.0.json)을 참조하세요. 이전 버전의 정탐·오탐·미탐 수치는 이번 버전의 새 측정치로 합산하지 않습니다.

| 구분 | 이번 실행 상태 |
|---|---|
| Feature Mapper | 격리 Java 검사 **114개**, Node 도우미 검사 **8개** 통과. 연결 상태·상관관계·부정 대조·OFF/SCOPE 통합을 검사했습니다. |
| 신원 대조 독립 재확인 | 200ms 설정에서 classic·adaptive의 신원 대조→기준 요청 경계를 포함해 간격을 확인했습니다. 동일 신원이 담긴 큰 익명 401 응답은 신원 대조 2회에서 중단하고 검사값을 전송하지 않았습니다. |
| 실제 Chrome MV3 | Chrome 146 시작을 시도했으나 `socket() failed: Operation not permitted`로 차단되었습니다. 실제 도우미 설치·클릭·HTTP 연결 검증은 **NOT_RUN**입니다. Node·Java fixture 통과와 구분합니다. |
| 실제 Burp | 실행 시도는 라이선스 안내 단계에서 차단되었습니다. 0.49.0 확장 로드 이후의 실제 Burp 전체 흐름은 검증하지 못했습니다. |
| 기존 7개 사이트 재측정 | 추가 취약점 재현 작업이 보안 검사에서 차단되어 새 전체 측정 결과가 없습니다. BenchmarkJava·DVBLab·VulnerableApp·OopsSec·Vuln Bank 소스와 Juice Shop 아카이브 준비까지만 기록했습니다. crAPI는 Docker/Podman 부재로 실행하지 못했습니다. |

[대상 준비 기록](verification/full-0.49.0/target-preparation.json)은 소스·아카이브 준비 기록이며 사이트 실행·취약점 재현·탐지율의 증거가 아닙니다. 별도 Microsoft eShop도 .NET/Aspire·컨테이너 런타임이 없어 실행하지 못했습니다. Swing/API 어댑터 검사는 실제 Burp 데스크톱 조작과 구분합니다.

## 이번 재개에서 확인한 결과

전체 회귀·격리 HTTP **3,361개**(회귀2,857·페이로드136·전체 기능102·업무266), Mapper Java114개·Node8개를 다시 통과했습니다. 최종 다운로드와 현재 소스 지문이 일치합니다. 앞선 동일 JAR의 50개 기능 결과를 재집계했으며, 권한표·쓰기 조회 설정 후에는 2,100계정 대조에서 TP392·FP0·TN1708·FN0, 보류91(중복)입니다. 미설정에는 FN392가 있으므로 설정 의존성이 남습니다. 실제 Burp 검증 수치가 아닌 API 어댑터·loopback HTTP 결과입니다.

실제 Chrome 재시도는 동일한 socket 권한 제한으로 실패했습니다. 이전 Burp 시도의 JAR 해시는 최종 배포본과 다르므로 최종 버전 검증에서 제외했습니다. [HTML 결과 보고서](reports/2026-10-20-full-hardening/Workbench_Full_Hardening_0.49.0_KR.html)에 각 한계와 완료 조건을 정리했습니다.

## 남은 고도화와 재검증

- 실제 Burp에서 11개 메뉴를 연결한 전체 흐름과 기존 7개 사이트의 동일 조건 전후 재측정이 필요합니다. 원본 사이트 준비만으로 완료 처리하지 않습니다.
- Chrome/Edge MV3의 실제 인증 연결·버튼 클릭·요청 귀속, Windows DPI/IME와 장시간 사용은 별도 환경에서 확인해야 합니다. 본문 해시를 얻지 못한 요청은 해시 검증 완료로 표시하지 않습니다.
- JS의 복잡한 객체 전달·동적 호출·대형 번들 실행 의미, 응답 한도 밖의 본문·중간 구간은 자동 판정 범위 밖입니다. 미확정 후보와 원본을 함께 검토해야 합니다.
- 대상별 권한 정책·CSRF·로그인 갱신·업무상 거부의 원인과 실제 저장·브라우저 실행은 별도 재현이 필요합니다. 신원 유지나 2xx·401/403만으로 취약점 유무를 확정하지 않습니다.
- 외부 AI·OAST·BApp, Docker 전체 스택 및 Microsoft eShop의 실제 동작은 이번 실행 근거에 포함되지 않습니다. 사용자 첨부 이미지와 알려지지 않은 개인정보의 가림도 수동 확인이 남습니다.
