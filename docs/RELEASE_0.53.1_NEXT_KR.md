# Workbench Next 0.53.1 설치·사용 안내

**0.53.1은 main에 병합한 사용자 편의성 개선판입니다.** 0.53.0 작업 커밋 `8b548422f12d498aef7334ebb86b55762c1a1569`을 기준으로 비교 준비, 결과 검토, 설정 재사용, 남은 점검, 검색과 작업 재개 흐름을 개선합니다. 내장 Feature Mapper는 **0.3.5**, 실습 사이트는 **3.10.0**입니다. [PR #89](https://github.com/ohjun1998/burp-workbench-kr/pull/89)로 main에 병합했으며, 기존 0.52.0 배포와 당시 검증 기록은 보존합니다.

이 문서는 0.53.1의 설치와 달라진 작업 흐름을 설명합니다. SCOPE 등록, 쓰기 조회 규칙, JS 분석, 기능 매핑과 증거 파일의 기본 개념은 [기존 상세 가이드](RELEASE_0.52.0_NEXT_KR.md)에 보존합니다. 기존 가이드의 화면·검사 수치를 0.53.1의 실제 실행 결과로 해석하지 마세요.

## 설치할 버전과 검증 상태 확인하기

검증 소스 `5704f48a9d12282ec3f7ea48ec7a78065aa78695`의 [최종 GitHub Actions](https://github.com/ohjun1998/burp-workbench-kr/actions/runs/40334451367)가 모두 통과했습니다. [검증 기록](VERIFICATION_0.53.1.json)과 [원격 근거·미실행 범위](reports/2026-10-26-usability-0531/REMOTE_CI_KR.md)를 함께 확인하세요. 이전 세션의 로컬 집중 검사 674개는 별도 기록으로 보존하며 최종 원격 검사에 합산하지 않습니다.

새 배포는 [0.53.1 설치 JAR](../downloads/extensions/0.53.1/burp-workbench-kr-0.53.1.jar), [빌드 가능한 소스 ZIP](../downloads/extensions/0.53.1/burp-workbench-kr-0.53.1-source.zip), [SHA256SUMS](../downloads/extensions/0.53.1/SHA256SUMS)로 제공합니다. 브라우저 연동을 쓰려면 [Mapper 도우미 0.3.5](../downloads/feature-mapper/0.3.5/feature-mapper-browser-0.3.5.zip)를 선택합니다. Workbench 안에 Mapper가 포함되어 있으므로 별도 Mapper JAR를 함께 추가할 필요는 없습니다. 파일별 목록은 [다운로드 안내](../downloads/README.md)를 확인하세요.

되돌릴 때는 0.53.1의 로드를 해제하고 보관한 이전 JAR를 다시 로드합니다. 이전 버전에 맞춰 보관한 프로젝트·설정·기록을 사용하세요. 새 버전의 저장 형식을 이전 버전에서 그대로 읽을 수 있다고 가정하지 않습니다. 기존 파일을 삭제하거나 덮어쓰는 방식으로 버전을 교체하지 않습니다.

## 1. 비교 준비와 설정 수정을 같은 화면에서 이어가기

0.53.0의 여러 원본 준비 목록을 유지하면서 계정, 기대 권한, 쓰기 결과 조회를 준비 화면에서 이어서 편집합니다. 설정 하나를 고칠 때마다 원본을 다시 선택하는 작업을 줄이는 흐름입니다.

1. **요청·응답 목록**에서 비교할 원본을 선택하고 **선택 요청 비교**를 엽니다. **계정 비교 준비 · 설정과 적용 상태** 창이 표시됩니다.
2. **1 적용 상태**에서 보완할 요청·계정 행을 고릅니다. 해당 원본의 메서드·대상과 계정을 확인합니다.
3. 같은 창의 **2 계정·쓰기 조회**, **3 세션·권한표**에서 부족한 값을 수정합니다.
4. **적용 상태 다시 확인**을 눌러 변경한 조건의 준비 상태를 읽습니다. 검토 뒤 설정이 바뀌면 실행 전에 다시 확인해야 합니다.
5. 전송할 대상과 계정, 쓰기 허용 여부를 확인한 뒤 **비교 시작** 또는 **제한 확인 후 비교**를 누릅니다.

설정 화면을 열거나 값을 저장하는 동작과 비교 실행은 구분됩니다. 계정 세션 검사를 직접 실행하거나 비교를 시작하면 실제 HTTP 요청을 보냅니다. 이미 전송한 쓰기 요청은 중지 버튼으로 되돌릴 수 없습니다.

## 2. 준비 목록과 결과에서 필요한 항목만 보기

준비 목록은 요청·계정·설정 상태를 중심으로 읽고, 긴 사유와 상세 조건은 선택 항목의 상세 영역에서 확인합니다. **전체 / 보완 필요 / 쓰기 요청** 필터와 **요청·계정 찾기**로 여러 요청 중 필요한 행을 먼저 처리할 수 있습니다.

비교 이력의 **결과 표시**에서는 **전체 / 우회 의심 / 확인 필요 / 계정·세션 / 권한 설정 / 쓰기 조회 / 전송·미실행**을 골라 확인합니다. 필터는 목록에 표시할 기록을 정하는 기능이며, 과거 기록을 삭제하거나 판정 결과를 바꾸지 않습니다.

결과가 ‘확인 필요’이면 상태명만 보고 재실행하지 말고 선택 항목의 이유를 먼저 읽으세요. 계정 연결·세션, 기대 권한, 쓰기 조회와 실제 응답 중 어느 부분을 보완해야 하는지 구분해 표시합니다. 정상 종료한 실행도 근거가 부족하면 수동 확인이 필요할 수 있습니다.

## 3. 설정 묶음의 변경점을 읽고 계정 다시 연결하기

설정 묶음 목록의 **더보기**에서 JSON 불러오기·내보내기, 선택 묶음 삭제와 저장 목록 다시 읽기를 엽니다.

설정 묶음은 재사용할 규칙을 적용하는 기능입니다. 인증값을 가져오거나 실제 계정의 신원을 증명하는 기능은 아닙니다.

1. **계정 권한 비교 → 더보기 → 설정 묶음 · 저장/불러오기**에서 적용할 묶음과 원본을 고릅니다.
2. **선택 묶음 적용**을 누릅니다. 이름·revision·Origin·요청 범위와 현재 설정에서 추가·변경·제거되는 항목을 먼저 읽습니다.
3. 권한표·조회 규칙·차단 규칙 등 변경 내용을 확인합니다. 세부 원문이 필요하면 **JSON 원문 펼치기**, 요약으로 돌아가려면 **변경 요약으로 돌아가기**를 사용합니다.
4. 적용을 확정합니다. 검토 중 원본이나 설정이 바뀌면 적용을 다시 준비합니다.
5. 적용 후 표시되는 **계정 다시 연결**로 계정 설정을 엽니다. 역할 1~3과 비로그인 조건, 신원·갱신 설정 및 쓰기 전송 허용을 다시 확인합니다.

묶음을 적용하면 기존 비교 계정 연결이 해제됩니다. 인증 후보가 남아 있더라도 역할에 맞는 실제 계정을 직접 연결해야 합니다. 변경점 확인이나 계정 설정 화면 열기만으로 비교가 시작되지는 않습니다.

## 4. 남은 점검에서 다음 작업 시작하기

**기능 자동 매핑 → 점검 진행 현황**에서 업무를 선택하고 **남은 점검**을 엽니다. 미실행·조건 변경·실행 중단/실패·증거 보완·입력/수동 검토·원본 연결 등의 실제 기록 사유로 목록을 좁혀 볼 수 있습니다. 하나의 항목에 여러 사유가 있을 수 있으므로 사유별 개수를 합산해 전체 항목 수로 해석하지 않습니다.

항목을 선택하면 어떤 계정과 요청에 대한 점검인지, 왜 남아 있는지, 다음에 무엇을 해야 하는지 확인할 수 있습니다. 다음 작업 버튼으로 해당 원본의 비교 준비, 기존 실행 확인 또는 증거 작업으로 이어갑니다. 연결된 원본이 없거나 현재 조건과 맞지 않으면 필요한 원본·계정 연결을 먼저 안내합니다.

‘실행 완료’, ‘증거 저장’과 ‘업무 완료’는 서로 다른 상태입니다. 필요한 요구 조합과 증거를 검토한 뒤 사람이 업무 완료를 결정합니다. 원본·실행·계정 ID가 다른 항목을 같은 URL이라는 이유만으로 대신 연결하지 않습니다.

## 5. 적용된 검색 조건을 보고 자주 쓰는 조건 저장하기

**요청·응답 목록**의 조건 표시에서 메서드·상태·검색 범위·기간 등 현재 적용된 필터를 확인합니다. 각 조건의 **×**를 누르면 해당 조건만 해제하고 실제 목록 검색에도 반영합니다. **모두 해제**는 필터와 현재 검색어를 초기화합니다. 검색 진행 상태와 오류는 조건 표시 아래에서 확인합니다.

프로젝트에서 자주 쓰는 필터 조합은 **조건 저장**에서 이름을 붙여 최대 24개까지 저장합니다. **저장한 조건**에서 이름을 고르고 **조건 적용**으로 다시 적용하거나 **삭제**로 정리합니다. 예를 들어 `POST + 4xx + 최근 30분`을 저장해 다음 점검에서 다시 사용할 수 있습니다.

화면의 **검색어 제외 · 조건만 저장** 안내처럼 검색어, 인증값, 요청·응답 본문을 저장된 조건에 보관하지 않습니다. **조건 적용**은 현재 입력한 검색어를 유지하므로 함께 확인하세요. 다른 프로젝트로 전환하면 해당 프로젝트의 저장 조건을 사용합니다.

## 6. 결과에서 설정 보완과 증거 작업으로 이동하기

비교 기록을 선택하고 원인과 연결 대상이 맞는지 확인한 뒤 **계정·세션 보완**, **권한 설정 보완**, **쓰기 조회 보완** 중 필요한 작업을 엽니다. 해당 기록의 원본을 준비하고 수정한 뒤에는 현재 조건으로 적용 상태를 다시 확인하고 사람이 실행을 시작합니다. 과거 실행 결과는 실행 당시의 조건으로 보존하며, 설정 수정만으로 과거 판정이 다시 계산되지는 않습니다.

종료한 실행의 근거를 보존하려면 **재현·증거 정리**로 이어갑니다. 설명 작성, 가림 미리보기, 실제 ZIP 저장을 완료한 뒤 실행과 증거 연결을 확인하세요. 증거 화면을 열거나 미리보기를 만든 것만으로 저장 완료로 처리하지 않습니다.

## 7. 작업 재개 안내에서 빠진 연결 확인하기

상단 **작업 이어가기**(이전 기록이 있으면 **이전 작업 이어가기**)는 마지막 작업 화면과 검색 조건 등의 메타데이터를 다시 확인하는 기능입니다. **화면·검색 조건 이어가기**로 복원하거나 **새 작업으로 시작**을 선택합니다. 프로젝트를 다시 열면 마지막 작업과 연결 상태를 검토하고 필요한 작업으로 돌아갑니다. 누락된 원본이나 계정 연결, 추가 확인이 필요한 조건이 있으면 안내를 읽고 복원합니다.

인증값·원본 패킷·검색어는 재개 메타데이터에 저장하지 않습니다. 세션 연결은 다시 확인해야 하며, 원본 ID가 남아 있어도 현재 원본 파일의 존재를 보장하지 않습니다. 이 기능은 프로젝트·원본·증거 파일의 전체 백업을 대신하지 않습니다.

재개를 선택했다고 대기 중인 비교나 쓰기 요청을 자동 전송하지 않습니다. 현재 SCOPE·계정·설정을 검토한 뒤 실행을 시작하세요.
