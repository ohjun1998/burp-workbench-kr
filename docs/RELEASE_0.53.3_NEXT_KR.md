**0.53.3은 main에 병합한 사용자 편의성 개선판입니다.** 0.53.1 main 커밋 `6737746f1a0c29c42c91a246a8161192c7d279d6`에서 검색 근거 찾기, 증거 수정, 입력 오류 보완과 화면 이동을 개선합니다. 내장 Feature Mapper는 **0.3.5**, 실습 사이트는 **3.10.0**을 유지합니다. [PR #91](https://github.com/ohjun1998/burp-workbench-kr/pull/91)로 main에 병합했으며 이전 버전의 파일과 검증 기록은 보존합니다.

## 1. 검색 결과에서 일치한 위치 읽기

**요청·응답 목록**에서 **요청 포함** 또는 **전체 패킷** 범위로 검색하고 결과 행을 선택합니다. 아래 요청·응답의 **목록 검색 문맥**에서 일치한 원문 또는 디코딩 본문을 강조해 보여줍니다. **이전 일치·다음 일치**로 주변 문맥을 옮겨 보고 **앞부분 보기**로 기본 패킷 표시로 돌아갑니다. 목록 범위 검색은 메서드·URL·상태의 일치임을 별도로 안내합니다.

목록 본문 검색은 원문 앞 **2 MiB**, 기본 패킷 미리보기는 앞 **64 KiB**를 기준으로 합니다. 일치 문맥은 기본 미리보기 밖의 위치도 보여주며, 위치는 바이트가 아닌 **문자 위치**입니다. 문맥·일치 개수와 부분 검사 제한을 화면에서 확인하세요. 전체 원본은 **⋯ → Burp 기본 편집기**로 확인합니다. 검색어나 문맥을 원본 패킷에 덧붙여 저장하지 않으며, 조건·선택이 바뀌면 이전 문맥을 다시 사용하지 않습니다.

## 2. 증거 묶음에서 필요한 항목만 정리하기

**재현·증거 정리 → 증거 묶음**에서 행을 선택하고 **선택 제거**로 잘못 넣은 항목만 뺍니다. **위로·아래로**로 순서를 정하면 화면의 순서가 ZIP 저장 순서에 반영됩니다. **Ctrl/Shift**로 여러 행을 선택할 수 있으며, 현재 증거 수와 선택 수를 함께 표시합니다. 증거는 최대 **32개**입니다.

**실행 취소**는 마지막 제거 또는 순서 변경 **1회**를 복원하며 원본·실행 연결과 순서를 유지합니다. 새 증거·이미지 추가, **비우기**, 프로젝트 변경 이후에는 이전 편집을 되돌릴 수 없습니다. 저장·실행 중에는 편집이 제한됩니다. 묶음 편집은 원래 트래픽과 완료된 비교 결과를 삭제하지 않습니다.

일부 증거를 제거했더라도 남은 항목에 반사된 인증값을 가릴 수 있도록 기존 가림 정보는 유지합니다. 비교 실행의 원본 일부만 남겼다면 ZIP 저장만으로 그 실행의 전체 증거가 갖춰졌다고 처리하지 않습니다. **가림 미리보기**에서 설명·이미지를 확인하고 **증거 ZIP 저장**을 실행하세요.

## 3. 검색 결과가 없을 때 조건 하나씩 확인하기

검색 상태는 **수집된 트래픽 없음**, **현재 조건과 일치하는 항목 없음**, **검색 중·취소·실패**, **본문 일부 검사**를 구분합니다. 수집이 없으면 SCOPE와 수집 상태를 확인하고 범위 안의 요청을 관찰하거나 History에서 가져옵니다. 일부 본문만 검사했다면 검사 범위 밖의 일치 여부는 미확인입니다.

현재 조건의 결과가 0건이면 **조건 하나씩 확인**에서 메서드·응답 상태·계정·기간·중요 표시·검색어 중 적용된 조건을 고르고 **이 조건만 해제**를 누릅니다. **이전 조건으로**는 방금 해제한 조건과 검색어를 복원합니다. 프로젝트나 다른 조건이 바뀌면 이전 복원을 적용하지 않습니다. 이 조작은 목록 필터만 바꾸며 SCOPE와 수집 범위를 넓히지 않습니다.

## 4. 입력 옆에서 오류와 적용하지 못하는 이유 확인하기

검색 정규식, 계정 확인 URL, 쓰기 조회 규칙, 권한표·경로 규칙과 응답 차단 규칙은 해당 입력 가까이에 오류와 예시를 표시합니다. 정규식은 잘못된 위치를, 권한 규칙은 문제가 있는 행을 안내합니다. 조회 URL은 HTTP(S) 형식과 대상 Origin·SCOPE를 확인하며, JSON 경로·숫자 변화 경계도 입력에 맞게 안내합니다.

입력이나 선택 상태가 맞지 않으면 **적용** 또는 **규칙 저장·갱신** 버튼 주변과 툴팁에서 이유를 확인하세요. 수정 후 다시 형식을 확인하고 직접 적용합니다. 입력 검사는 서버에 요청하지 않으며 세션 유효성이나 실제 조회 성공을 보장하지 않습니다. 비교 준비 상태를 다시 확인한 뒤 사람이 실행을 시작합니다.

## 5. 기능 찾기와 이전·다음 화면 사용하기

**기능 찾기** 또는 **Ctrl+K**를 열고 `권한 비교`, `증거 저장`, `JWT`처럼 이름이나 목적을 입력합니다. 방향키로 항목을 고르고 **Enter** 또는 **선택 화면 열기**로 이동합니다. 검색어가 없으면 최근 화면을 먼저 표시하며 **Esc**로 닫습니다. 기능 설명만 검색하므로 트래픽·본문 검색과는 별개입니다.

탐색 영역의 **←·→** 또는 **Alt+←·Alt+→**로 이전·다음 화면을 오갑니다. 같은 프로젝트에서 화면의 하위 탭·선택·스크롤과 트래픽 검색 조건을 복원합니다. 원본이 없거나 현재 결과에서 숨겨졌다면 직접 선택하라는 안내를 따르세요. 목록·설정이 바뀌면 복원이 생략될 수 있습니다. 화면 이력과 검색어 복원은 현재 실행의 메모리에만 보관하며, 0.53.1의 **작업 이어가기**가 제공하는 재시작 후 메타데이터 복원과 구분합니다. 화면 이동으로 비교·쓰기 요청을 실행하지 않습니다.

작은 창을 거친 뒤 넓은 창으로 돌아왔을 때 **기능 찾기**가 불필요한 두 번째 줄에 남지 않도록 탐색 막대 너비를 다시 계산합니다. **남은 점검**의 목록·설명 방향과 분할 방식을 유지하면서 작업 높이를 확보합니다. 1024px 창·넓은 메뉴의 전체 흐름 검사에서 설명 영역 높이 63px를 양 테마에서 확인했습니다.

## 6. 진행 중인 작업과 완료 결과 확인하기

상단 **도우미 → 진행 중인 작업 현황**에서 검색·JS 분석·계정 비교·증거 저장의 **작업·상태·현재 단계·처리 건수·경과**를 확인합니다. 알 수 있는 처리 건수를 표시하며 남은 시간이나 진행률을 추측하지 않습니다.

중지 가능한 작업은 **선택 작업 중지**로 요청합니다. **중지 요청**과 **종료**를 구분하며 이미 시작한 HTTP 처리는 응답·타임아웃까지 기다릴 수 있습니다. ZIP 저장처럼 정합성을 유지해야 하는 단계는 중지 버튼이 비활성화되고 이유를 안내합니다.

**결과 열기**가 표시되면 해당 실행에 보관된 결과로 이동합니다. **작업 화면 열기**는 작업 화면의 현재 상태를 열며 이후 실행으로 결과가 달라졌을 수 있습니다. 작업 목록은 최근 기록을 제한된 수만 보관하므로 전체 실행·증거 이력은 각 화면에서 확인하세요.

## 7. 응답을 상태·헤더·JSON 항목별로 비교하기

**요청·응답 목록 → 변환·비교 → 응답·데이터 비교**에서 양쪽 데이터를 준비하고 **비교 실행**을 누릅니다. **항목별 요약**은 상태·헤더·JSON 필드의 **추가·변경·삭제**와 양쪽 값을 보여줍니다. 행을 선택하면 아래의 왼쪽·오른쪽 원문에서 해당 위치를 강조합니다. **원문·줄 차이**와 **이전 차이·다음 차이**로 기존 줄 비교도 사용할 수 있습니다.

파싱 실패·비교 범위·표시 제한은 요약 안내에서 확인합니다. 표시된 개수가 전체 응답의 모든 차이를 뜻하지 않을 수 있으며, 차이 자체로 취약점이 확정되지는 않습니다. 원본 증거가 필요하면 양쪽의 **트래픽 가져오기**로 실제 응답을 연결하고 **원본 → 증거**로 보냅니다. 붙여넣거나 편집한 데이터만으로는 원본 증거 연결을 만들지 않습니다.

## 8. 처음 사용할 때 준비 상태 확인하기

상단 **도우미 → 시작 준비 체크리스트**에서 현재 프로젝트의 상태를 확인합니다.

| 단계 | 확인할 상태와 이동 |
|---|---|
| 점검 SCOPE 등록 | 체크한 범위 확인 → **SCOPE 열기** |
| 요청·응답 수집 확인 | 현재 건수와 수집 SCOPE ON/OFF 확인 → **트래픽 열기** |
| 비교 계정 연결 | 현재 연결 계정 수 확인 → **계정 설정 열기** |
| 첫 비교 결과 확인 | 정상 종료한 실행 수 확인 → **비교 화면 열기** |
| 증거 ZIP 저장 | 실제 ZIP 저장 완료 이력 확인 → **증거 화면 열기** |

각 버튼은 해당 화면만 엽니다. 수집 전환·세션 확인·비교 시작·ZIP 저장은 각 화면에서 직접 실행합니다. 준비·사용 이력은 보안 판정이나 업무 완료가 아니며, 저장 이력이 있어도 실제 ZIP 파일의 존재·내용은 별도로 확인하세요.
