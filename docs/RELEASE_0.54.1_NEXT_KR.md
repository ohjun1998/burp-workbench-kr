# Workbench Next 0.54.1 · ChatGPT 구독·로컬 LLM 검토와 기능별 패킷 분류

0.54.0 AI 통합 후보 [PR #110](https://github.com/ohjun1998/burp-workbench-kr/pull/110)의 소스 `6334ac1962caf42c7685c544bde61c327db47560`을 이어받은 Next 전용 후속 버전입니다. 이 후보의 기준 main은 `222aef191a34f7d6cd1014e941ecc7152341f640`(Next 0.53.4)입니다. 기존 AI 기능과 자동 요청 실행 전 확인을 유지하며, 작은 창에서 작업 영역이 줄어드는 배치 문제를 보정합니다. 이전 배포 파일과 Simple은 보존합니다.

## 0.54.1에서 마무리하는 내용

0.54.0 후보는 1024×720 창·150% 배율에서 증거의 영향·재현 입력 영역이 각각 61px로 줄어 최소 70px 기준에 미달했습니다. 밝은/어두운 테마에서 같은 두 영역이 실패해 총 네 건으로 집계됐습니다. 0.54.1은 증거 화면의 긴 `AI 보고서 초안` 버튼을 `AI 초안`으로 줄여 작업 영역을 확보합니다. 전체 기능명은 접근성 이름과 툴팁으로 유지합니다.

같은 검사 기준으로 전체 화면과 AI 화면을 다시 검증합니다. 검사 기준을 낮추거나 실패 항목을 제외하지 않습니다. 실패한 이전 검사와 새 실행 결과는 [검증 기록](VERIFICATION_0.54.1.json) 및 [수정 전후 보고서](reports/2026-11-16-next-0541/)에서 구분합니다.

기능별 패킷 분류·보고서 초안의 기본 경로는 **ChatGPT 구독**, 보안·계정·업무 로직·JS 검토의 기본 경로는 **로컬 Halogen**입니다. 자동 대상 요청은 실행마다 확인을 받으며 기본 선택은 **취소**입니다. AI가 기존 판정을 자동 변경하거나, 실행을 거절한 요청을 다른 서비스로 자동 재전송하지 않습니다.

## 설치

1. 기존 Workbench JAR와 프로젝트·설정 파일을 보관합니다.
2. 이전 Workbench 확장의 로드를 해제하고 Burp의 **Extensions → Add → Java**에서 `burp-workbench-kr-0.54.1.jar`를 선택합니다.
3. 화면에 표시되는 버전과 새 JAR의 버전이 일치하는지 확인합니다. 기존 버전과 새 버전을 동시에 로드하지 않습니다.
4. 아래 연결 방법에 따라 같은 M5의 Halogen 또는 공식 Codex CLI 구독 인증을 설정합니다. 연결 확인과 분석은 사용자가 실행합니다.

배포 파일의 SHA-256은 같은 폴더의 `SHA256SUMS`로 대조할 수 있습니다. 버전별 소스 ZIP과 검증 기록은 해당 설치 JAR의 입력 소스·검사 범위를 확인하는 자료입니다.

## 유지되는 AI 작업 흐름

관측한 원본을 고르면 작업별 실행 경로에 보낼 분석 입력을 준비합니다. **분석 버튼을 누르기 전에는 LLM 호출이 없습니다.** LLM에는 가림 처리한 제한된 미리보기와 원본 ID, 사용자가 입력한 맥락을 전달합니다. 화면의 전송 대상을 확인한 뒤 실행합니다. 모델의 응답은 원본 ID를 검증한 제안으로 표시하며 기존 권한 판정·기능 교정 규칙·점검 완료 상태를 덮어쓰지 않습니다.

## ChatGPT 구독 연결

공식 Codex CLI의 ChatGPT 로그인을 재사용합니다. 일반 OpenAI API 키를 ChatGPT 구독으로 대체하는 비공식 프록시를 사용하지 않습니다.

1. M5에 최신 공식 Codex CLI를 설치합니다. 공식 설치 문서는 https://learn.chatgpt.com/docs/cli 입니다.
2. M5 터미널에서 `codex login`을 실행해 사용할 ChatGPT 계정으로 로그인합니다. `codex login status`로 ChatGPT 인증인지 확인합니다. 실제 사용 가능 모델/구독 한도는 해당 계정에 따라 달라집니다.
3. Workbench AI 설정의 Codex 실행 파일에 `codex` 또는 실행 파일 절대 경로를 지정합니다. 모델을 비우면 CLI 기본 모델을 사용합니다.
4. 구독 로그인 확인으로 상태를 확인합니다. 로그인 페이지·암호·토큰 입력은 Workbench가 대신 처리하거나 인증 파일을 읽고 복사하지 않습니다.
5. 기능 분류 또는 보고서 초안을 준비합니다. 전송 대상이 ChatGPT 구독으로 표시되는지 확인하고 가림 미리보기를 검토한 뒤 AI 분석을 실행합니다.

`codex exec`는 빈 임시 작업 폴더와 비영구 세션, 사용자 설정 미로딩, 읽기 전용 sandbox 및 명령·연결 도구 비활성화 설정으로 호출합니다. 프롬프트는 명령행 문자열이 아닌 표준입력으로 전달하고 출력은 스키마와 원본 ID로 검증합니다. API 키 인증이면 구독 작업을 중단하며 자동 유료 API 전환을 하지 않습니다. 터미널/사용자 설정을 변경하거나 로그인 정보를 내보내지 않습니다. CLI가 요구하는 최신 옵션을 지원하지 않으면 업데이트 후 다시 실행해야 합니다.

구독 작업은 가림 후 내용이 OpenAI 서비스로 전송되고 해당 계정의 사용 한도와 데이터 처리 설정이 적용됩니다. 로컬 상세 검토는 설정한 Halogen으로 전달됩니다. 공식 연동 근거: https://learn.chatgpt.com/docs/auth · https://learn.chatgpt.com/docs/non-interactive-mode · https://learn.chatgpt.com/docs/config-file/config-reference.

## Halogen 연결

1. `재현·증거 정리 → AI 검토 → AI 설정`을 엽니다.
2. 같은 M5에서 Burp와 Halogen을 실행한다면 기본 주소 `http://127.0.0.1:8731/v1`을 사용합니다. 실제 설정 포트가 다르면 수정합니다. 다른 PC에서 접속할 때에는 M5의 사설 IP와 실제 포트를 지정하고 API 인증을 구성합니다.
3. `로컬 연결 확인`으로 `/health`, `로컬 모델 목록`으로 `/v1/models`를 직접 조회합니다. 사용할 모델 ID를 입력합니다. 기본값은 `halogen-qwen3.8-flash-next`입니다.
4. 기본 총 출력/추론 예산8192토큰, 추론low, 전체 응답 제한180초입니다. 설치 버전이 추론 옵션을 받지 않으면 추론 수준을 빈 값으로 지정하여 필드를 생략합니다.
5. 분석 원본을 준비하고 `전송 내용 미리보기`와 기대 정책/기능 설명을 확인한 뒤 `AI 분석`을 누릅니다.

연결 주소·키·설정과 분석 결과 캐시는 세션 메모리에서만 유지합니다. 프로젝트 전환·원본 목록 초기화·확장 종료 시 AI 원본과 결과·키를 해제합니다. Halogen HTTP 클라이언트는 로컬/사설 IP 주소만 허용하며 프록시를 우회해 해당 주소로 직접 연결합니다. 구독 경로는 별도 공식 Codex CLI가 담당합니다.

## 기능별 분류를 활용하는 방법

같은 화면/사용자 행동에서 발생한 요청을1~24개 선택합니다. 기대 정책·기능 설명에 화면 이름, 직전 행동, 계정·테넌트·객체 소유 관계를 적습니다. LLM은 URL뿐 아니라 요청/응답 구조와 맥락을 이용해 기능을 제안합니다. 같은 원본이 여러 기능에 포함될 수 있고, 분류하지 못한 원본은 미분류 행으로 남습니다.

예: 계정A로 내 주문 열기 → 주문 조회/배송 정보/결제 정보 요청 선택 → 기능별 분류 → 주문 조회 묶음의 원본 확인 → 테스트 계정B와 권한 비교 → AI 비교 해설. 분류 자체로 접근권한이나 취약점이 증명되지는 않습니다.

결과 표를 정렬해도 연결은 행 위치가 아닌 불변 원본 ID를 사용합니다. 복수 원본인 제안은 연결 원본 선택상자에서 하나를 고를 수 있습니다. `원본 위치`는 해당 원본의 제한된 Raw 미리보기를 열며 현재 트래픽 선택에 의존하지 않습니다. `원본 → Repeater`는 원본 요청을 준비할 뿐 전송하지 않습니다. 검증안은 설명으로 제공하며 실제 변경과 Send는 직접 수행합니다.

기능 분류와 보고서 작성은 자동 경로에서 ChatGPT 구독으로 배정합니다. 로컬로만 처리하려면 실행 경로를 Halogen으로 직접 바꿉니다. 각 서비스의 정책과 맥락에 따라 요청 처리가 달라질 수 있으며 작업 이름만으로 검열 여부를 보장하지 않습니다.

### 브라우저 조작 없이 분류

이번 기능은 수집한 원본을 입력으로 사용하므로 AI의 브라우저 조작과 대상 추가 요청이 필요하지 않습니다. 사람이 사이트를 사용하면서 수집한 트래픽을 선택해 분석할 수 있습니다. 후속 고도화 후보는 메서드·정규화 경로·파라미터명·응답 구조로 중복을 정리하고 대표 패킷만 AI로 분류한 뒤 같은 유형의 원본에 제안을 확장하는 방식입니다. 계정·권한·상태·응답 차이는 합치지 않고 보존해야 합니다. 현재 전체 트래픽 자동 클러스터링/대표 추출/제안 일괄 확장은 구현 범위에 포함하지 않습니다.

### 브라우저 탐색 중 분류와의 관계

기존 Feature Mapper의 Chromium 보조 확장은 사용자의 클릭/제출 요소·화면·탭/프레임과 요청 메타데이터를 기록합니다. Burp 프록시로 실제 원본을 수집한 뒤 메서드·URL·본문 해시·시간으로 대응해 기능/클릭 단위 그룹을 구성합니다. 보조 확장 자체가 Burp 프록시나 인증서를 설정하거나 LLM이 브라우저를 조작하게 하지는 않습니다.

이번 AI 기능은 선택한1~24개 원본과 수동 입력 맥락을 사용합니다. 기존 브라우저 이벤트/기능 그룹을 AI 입력에 자동 연결하거나 AI가 페이지를 열고 클릭하는 에이전트는 포함하지 않습니다. 이후 확장에는 그룹/원본 ID 연결, 화면 관찰과 브라우저 제어, Scope·탐색 예산·상태 변경/반복 요청 확인이 필요합니다. 현재 구독 분석용 CLI의 브라우저/실행 도구는 비활성화합니다.

## 분석 결과와 증거

AI 결과는 관찰/가설, 불확실성/반증 조건, 다음 최소 검증으로 표시합니다. JSON 형식, 필드 길이, 원본 ID를 검사하고 입력에 없는 ID가 나오면 적용하지 않습니다. 모델의 사실 해석이 옳다는 자동 검증은 아닙니다. 웹 응답과 코드의 지시문은 자료로 취급하며 모델에 실행 도구를 제공하지 않습니다.

`선택 제안 → 증거`는 완전한 원본과 미검증 AI 메모를 함께 추가합니다. 원본 없음/패킷 합계128KiB 초과/현재 Scope 제외이면 증거 전달을 중단합니다. 보고서 초안은 먼저 AI 화면에 표시하고, 사용자가 추가 버튼을 눌렀을 때 기존 재현 설명 아래에 붙입니다. 기존 문장은 유지합니다. 그 사이 프로젝트·증거 목록·증거명·메모·계정·재현 설명·영향을 수정하면 다시 준비해야 합니다. 보고서 자동 제출·취약점 확정·점검 자동 완료는 하지 않습니다.

## 자동 요청 실행 전 필수 확인

Workbench가 직접 실행하는 자동 전송 작업은 요청을 보내기 전에 작업·대상·요청 수/예상 범위·간격·상태 변경 가능성을 표시합니다. 기본 선택은 **취소**이며 `확인 후 실행`을 명시적으로 선택해야 시작합니다. 창 닫기·거절·오류·화면이 없는 실행은 승인으로 해석하지 않습니다. 영구 승인과 항상 허용 옵션은 없습니다.

| 확인을 요구하는 기능 | 실행 범위 |
|---|---|
| 입력값 검사·퍼징 | 기준·대조·신원 확인·페이로드를 포함한 전체 실행 계획, 모든 순차/적응형 유형 |
| 환경·경로 탐색 | 없는 경로 기준·신원 확인·후속 경로 포함, 시작과 남은 작업/일시정지 재개마다 확인 |
| URL 후보 GET 검증 | 선택한 URL의 GET 일괄 확인, 위험 경로의 단일 GET 포함 |
| 계정 권한 비교 | 원본마다 기준·각 계정 재전송·갱신·신원 검사·쓰기 전후 조회를 함께 확인 |
| 쿠키·세션 조합 검사 | 최대128회·120ms 간격의 전체/제외/단독/조합 비교 |
| 여러 요청 재현 | 단계 수·요청 예산·타임아웃·쓰기 허용을 확인한 뒤 순차 실행 |
| JS 소스맵 탐색 | 현재 Scope 안의 제한된 GET 후보, 최대10개 |
| NPM 존재 조회 | 레지스트리·패키지 수·외부 전송, 최대100개 |

승인한 실행은 검토한 불변 대상·설정을 사용합니다. 확인 중 대상/계정/설정/프로젝트가 바뀌어 승인한 계획과 달라지면 차단하거나, 이미 고정한 승인 계획만 실행하도록 설계합니다. 새 실행과 재개는 다시 확인합니다. 자동 계정 비교도 새 원본마다 확인하며 취소하면 대기 중/자동 비교를 함께 중지합니다. 거절하면 해당 작업의 기준 요청과 대조 요청도 보내지 않습니다.

워크벤치의 관측·로컬 분석·AI 입력 준비는 대상에 추가 요청을 보내지 않습니다. Repeater 준비 이후 Burp 사용자가 직접 실행하는 단일 Send, Burp Intruder와 외부 BApp 자체 동작은 해당 도구의 실행 제어 범위입니다. 이 승인창은 Workbench가 다른 도구의 독립적인 실행을 통제한다는 의미가 아닙니다.

자동 회귀 검사는 테스트 전용 실행기에서 사용자 승인/거절을 모의합니다. 해당 코드와 승인 주입은 배포 JAR에 포함하지 않습니다. 실제 운영 코드의 기본값은 승인하지 않음이며, 승인 거부 시 전송0회를 별도로 검사합니다.

## 처리 한도와 오류

- 단일 worker, 대기 최대1개, 취소 가능. 입력·설정 변경 시 이전 결과가 새 화면을 덮어쓰지 않습니다.
- 원본1~24개, 각 요청/응답2MiB 이하, 합계8MiB 이하. 입력 JSON100,000자, 맥락32,768자 이하입니다. 초과하면 기능별로 나눕니다.
- 패킷별 앞64KiB만 검사하고, 가림 후 요청/응답 미리보기는 각각8,192자로 제한합니다. 부분·미지원 압축/형식은 표시하며 전체 분석으로 취급하지 않습니다.
- HTTP 요청256KiB, 응답512KiB 이하. 모델 답변 JSON은131,072자 이하이며 Codex 최종 출력 파일은 별도로128KiB 이하, 제안1~64행입니다.
- 캐시는 최대16개/응답 길이 합계1Mi자 예산이며 원본·계정 맥락·모델·프롬프트·설정이 바뀌면 별도 결과가 됩니다.
- `finish_reason=length`, 빈 답변, 정상 종료 아님, JSON/원본 ID 오류는 분석 미완료입니다. 오류에 따라 토큰 예산이나 추론 수준을 조정합니다. 자동 재시도와 리다이렉트는 없습니다.
- 인증 헤더·쿠키·민감 키·알려진 토큰 패턴과 일부 개인정보를 가립니다. 모든 업무 민감정보와 개인정보를 탐지하는 기능은 아니므로 전송 미리보기를 확인합니다.
- 같은 JS URL의 원본이 여러 개면 임의로 최신 버전을 대체하지 않습니다. 트래픽에서 정확한 원본을 선택한 후 작업을 JS·API로 지정합니다.

검증 범위와 실제 실행 결과는 [0.54.1 검증](VERIFICATION_0.54.1.json)에 기록합니다. 실제 사용자 M5의 ChatGPT 구독 인증/추론과 Halogen/Qwen 모델 품질·지연, native Burp GUI와 Windows DPI/IME, 외부 버그바운티 대상은 이번 격리 테스트와 구분합니다.
