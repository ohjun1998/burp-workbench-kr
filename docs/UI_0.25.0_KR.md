# 0.25.0 쉬운 이름과 화면 안내

**작업을 먼저 고르고, 해당 화면에서 필요한 입력과 다음 버튼을 확인하세요.** 상위 화면은 이름만으로 용도를 알 수 있게 바꿨습니다. [이전 이름 대응표](RELEASE_0.25.0_KR.md#기능-이름-대응표)와 [그림 가이드북](../downloads/guides/README.md)을 함께 볼 수 있습니다.

## 첫 요청으로 시작하기

Burp 브라우저에서 점검 대상의 정상 기능을 사용한 뒤 **요청·응답 목록**에서 요청을 선택합니다. 오른쪽 원본을 읽고 우클릭 → **SCOPE 지정** → **선택 URL 경로 추가** 또는 **현재 사이트 전체 경로 추가**를 누릅니다. **SCOPE 목록**에서 정확한 프로토콜·호스트·포트와 경로를 확인하세요.

Workbench의 공통 SCOPE를 각 도구가 함께 사용합니다. Burp Target Scope와는 별도이며 `localhost`와 `127.0.0.1`, 서로 다른 포트는 같은 대상이 아닙니다. **Scope만**은 이후 요청·응답 목록에 수집할 대상을 줄이는 선택입니다.

이미 고른 요청은 우클릭 메뉴로 필요한 도구에 전달할 수 있습니다. 도구마다 주소와 원본을 다시 붙여넣기 전에 이 연결을 먼저 확인하세요. **Repeater**로 보내기는 편집할 요청을 준비하며 자동 전송하지 않습니다.

## 목적에 맞는 화면 선택

| 하려는 일 | 화면과 시작 위치 | 먼저 준비할 것 |
|---|---|---|
| 요청·응답을 읽고 범위 정하기 | **요청·응답 목록** → 요청 선택 → 우클릭 **SCOPE 지정** | 응답이 있는 실제 요청 |
| 계정에 따라 접근이 다른지 확인하기 | **계정 권한 비교** → **세션·권한 매트릭스** → **선택 요청 비교** | 서로 다른 계정 세션과 허용·차단 기대값 |
| 두 응답 내용 비교하기 | **데이터 변환·비교 → 응답·데이터 비교** | 기준·대조 요청을 좌·우 데이터에 연결 |
| JavaScript의 API 단서 찾기 | **JS에서 API 찾기** → **URL · API** | 관측한 JS와 분석 출처 |
| 서버 정보와 경로 살펴보기 | **서버·경로 탐색** → 대상 설정 → **선택 경로 GET 확인** | SCOPE와 사용할 계정; 관찰만 읽을 때는 GET 확인 불필요 |
| URL 후보의 실제 응답 확인하기 | **URL 후보 수집** → 후보 선택 → 선택 URL GET 확인 | 출처·메서드·조회할 대상 확인 |
| 미점검 계정·API 찾기 | **점검 진행 현황 → 계정별 점검** | 계정·Origin·관측 요청 연결 |
| 헤더·오류와 원본 연결하기 | **응답 보안 분석 → 응답 관찰** | SCOPE 내 관측 응답 |
| API 문서에서 요청 준비하기 | **응답 보안 분석 → API 문서 → Repeater 초안** | API 선택과 경로 변수 확인 |
| 입력값을 바꿔 반응 비교하기 | **입력값 보안 검사** → 요청 준비 → 검사 설정 → 입력값 검사 시작 | 정상 요청, 검사 위치, 유형, 요청 한도 |
| 여러 요청을 순서대로 재현하기 | **재현·증거 정리 → 여러 요청 재현** | 단계별 요청·변수·기대 결과 |
| 원본을 증거 ZIP으로 저장하기 | **재현·증거 정리 → 증거 묶음** | 연결한 원본과 직접 확인한 영향·재현 절차 |

새 **기능 안내**는 현재 도구의 목적과 준비할 입력, 결과를 읽은 뒤 할 일을 확인하는 시작점입니다. 안내 창에서 **처음 시작하기**나 다른 기능을 고를 수 있고 **이 기능 열기**는 해당 화면으로만 이동합니다. 도구 이름을 익힌 뒤에는 기존의 요청 선택·우클릭 연결을 이용해 반복 입력을 줄일 수 있습니다.

## 화면 이동과 실제 전송 구분하기

| 동작 | 무엇이 일어나는가 |
|---|---|
| 안내 창의 **이 기능 열기** | 해당 화면으로 이동 |
| **Repeater** 또는 **Repeater 초안** | Burp에서 직접 편집·전송할 요청 준비 |
| 우클릭 **선택 요청 계정 비교 실행** | 준비한 계정 조건으로 비교 요청 전송 |
| **새 요청 자동 비교 ON** | 사용자가 켠 동안 관측하는 새 요청의 계정 비교 실행 |
| 우클릭 **URL 후보 수집 시작** | History 등 설정한 출처에서 수집 시작; 외부 조회를 선택한 설정에 따라 조회가 일어날 수 있음 |
| **선택 URL GET 확인**, **입력값 검사 시작** | 선택한 대상에 실제 점검 요청 전송 |

처음에는 **새 요청 자동 비교 OFF**를 유지하고 요청 한 건을 직접 골라 비교하세요. 준비가 끝난 뒤 필요한 동작만 실행하고, 사용하지 않을 때는 자동 비교를 끕니다.

## 결과를 다음 작업으로 연결하기

두 응답의 차이는 **데이터 변환·비교 → 응답·데이터 비교**에서 확인합니다. 요청·응답 목록에서 기준 요청을 선택한 뒤 왼쪽 카드의 **트래픽 가져오기**를 누르고, 대조 요청은 오른쪽 카드로 가져옵니다. **비교 실행 → 원본 → 증거**로 연결하면 실제 패킷 두 건의 출처를 유지합니다. 직접 입력을 편집하면 그쪽의 원본 연결이 해제됩니다.

관측한 보안 단서는 **응답 보안 분석 → 응답 관찰 → 선택 관찰 → 증거**, 실제 GET 결과는 **URL 후보 수집 → 선택 검증 원본 → 증거**로 연결합니다. 발견 후보만 있는 상태와 실제 응답 원본이 있는 상태를 구분하세요.

저장형 출력이나 업로드의 등록·조회를 확인할 때는 **응답 보안 분석 → 저장/조회 연결 → 마커 등록**에서 고유 마커를 등록합니다. 실제 쓰기·조회를 관측한 다음 **선택 흐름 → 증거**로 두 원본을 함께 연결합니다. **브라우저 실행 확인**은 실제 실행을 직접 확인하고 가린 이미지를 첨부하는 동작입니다.

증거는 **재현·증거 정리 → 증거 묶음**에서 **가림 미리보기 → 증거 ZIP 저장**으로 저장합니다. 화면에 전달한 결과는 아직 저장 파일이 아닙니다. 영향·재현 문장은 직접 작성하고 정상 대조·계정 조건을 함께 기록하세요.

## 완료와 재검토 찾기

| 대상 | 위치 | 사용 방법 |
|---|---|---|
| URL·입력의 수동 완료 | **점검 진행 현황 → URL 점검 현황** | URL 행 또는 입력을 선택한 뒤 완료 |
| 계정마다 다른 완료 상태 | **점검 진행 현황 → 계정별 점검** | 계정 → API → 입력 순서로 선택 |
| 업무의 요구 계정·API | **점검 진행 현황 → 업무별 현황** | 업무를 고르고 하단 요구 계정 × API 표 확인 |
| 증거 파일 이동·변조 확인 | **업무별 현황 → 증거 파일 ▾** | **증거 ZIP 재연결**, **모든 증거 재검증**, **파일 상태 확인** |

검사 실행과 점검 완료는 별도입니다. 실제 결과를 검토한 뒤 완료하고, 역할·조직·중요 입력이나 근거가 달라지면 재검토합니다. 계정별 완료를 다시 지정해도 업무 마감은 전체 조건을 확인한 뒤 직접 실행합니다.

## 버튼이 회색이거나 결과가 없을 때

먼저 선택한 행과 원본 연결을 확인하세요. Repeater 초안에는 API 행, 데이터 비교 증거에는 양쪽 원본, 증거 ZIP 저장에는 원본 요청이 필요합니다. 검사 실행 중에는 설정·재실행·일부 결과 전달을 사용할 수 없으므로 **중지** 또는 현재 작업의 종료 상태를 확인합니다.

화면 이름과 설명을 정리한 이번 변경은 자동 취약점 확정을 추가하지 않습니다. 응답 분석의 관찰, API 후보 발견, 검사 시도, 사람이 확인한 결과, 저장한 증거는 서로 다른 상태입니다.

## 화면 검증을 읽는 방법

```sh
python dev.py test
python tools/render_ui_layout.py --out tmp/ui-layout --check
```

검사 도구는 운영 Swing 구성 요소를 여러 크기·밝은/어두운 테마로 렌더링해 버튼·입력과 본문 영역을 확인합니다. 0.25.0의 실제 결과는 [검증 기록](VERIFICATION_0.25.0.json)을 확인하세요. 과거 버전의 화면 수·측정값을 이번 실행 결과로 합산하지 않습니다.

이 미리보기는 실제 Burp에 JAR를 로드해 GUI를 조작한 캡처가 아닙니다. Burp의 실제 테마, 운영체제별 글꼴·DPI, 키보드 포커스, 팝업 메뉴, 브라우저 실행과 Docker 전체 기동은 해당 실행 기록을 별도로 확인해야 합니다.
