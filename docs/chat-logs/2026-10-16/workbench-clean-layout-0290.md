# 작업 화면 정리·공통 테마·오류 로그 구현 0.29.0

- 날짜: 2026-10-16 (Asia/Seoul)
- 작업: workbench-clean-layout-0290

이 작업에서 확인 가능한 사용자 요청과 사용자에게 표시한 응답을 기록합니다. 과거 대화 전체나 내부 추론·도구의 원본 출력은 포함하지 않습니다. 요약한 항목은 별도로 표시합니다.

## 01. 사용자 · 원문

그렇구만... 그럼 OFF / SCOPE 만 남기고, OFF는 트래픽 수집 금지, SCOPE는 HTTP history에서 add to scope 한 URL들만 수집하도록 설정해줘

그리고 현재 레이아웃 배치는 요청, 응답 목록 글자 크게 되어있는거 삭제시키고 검색 INPUT을 위에 올려서 밑에 트래픽/요청/응답패킷을 위로 늘려줘, 검색 텍스트도 없애고, 레이아웃 배치는 소스코드에 적용하지말고 이미지로만 보여줘

## 02. 사용자 · 원문

레이아웃 중간 중간에 이런 조금만한 가이드들 제거해주고、그 공간에 트래픽이랑、 요청／응답칸을 늘려줘、 기능안내 버튼도 상위 설정 버튼 왼쪽에 위치해줘

## 03. 도우미 · 요약

직전 단계에서는 소스를 바꾸지 않고 안내 문구를 줄이고 작업 영역을 넓힌 이미지 시안을 제시했습니다. 이전 첨부 이미지의 로컬 경로는 현재 읽을 수 없으며, 이 기록은 확인 가능한 텍스트 요청을 기준으로 합니다.

## 04. 사용자 · 원문

에러 로그 관련해서 로그 버튼 만들고 설정 버튼 오른쪽에 넣어줘

## 05. 도우미 · 요약

상단 기능 안내 → 설정 → 로그 순서를 반영한 이미지 시안을 제시했습니다.

## 06. 사용자 · 원문

이렇게 코드 수정해줘, 다른 extension도 전체적으로 이렇게 깔끔하게 설정해줘

## 07. 도우미 · 원문

확정한 시안을 Workbench 코드에 적용하고, 함께 관리 중인 다른 확장도 같은 기준으로 정리하겠습니다. 안내·상태 문구를 줄여 작업 영역을 넓히고, 상단은 기능 안내 → 설정 → 로그 순서로 맞추겠습니다. 로그 버튼에는 실제 오류 기록을 확인하는 기능도 연결하겠습니다.

## 08. 도우미 · 요약

범위는 Workbench 10개 도구와 같은 저장소의 독립 Feature Mapper로 정했습니다. 중복 안내는 F1/기능 안내로 모으고, 로그에는 예외 종류·단계·코드 위치를 기록하되 원문 예외 메시지·HTTP·인증정보를 담지 않도록 구현했습니다. 두 확장에 공통 테마·글꼴·폴더/선택 강조를 적용하고 실제 운영 Swing 화면을 검토했습니다.

## 09. 도우미 · 원문

전체 배포 검사 2,044개와 화면 228개의 레이아웃 검사가 통과했습니다. Workbench와 Feature Mapper 모두 변경을 마쳤고, 이제 배포 파일과 GitHub 자동 검사를 확인하겠습니다.
