## 02. 도우미 · 요약

0.26.0 PR #19의 제품·최종 문서 커밋 검사는 통과해 main8b29b6f로 병합했다. 병합 후 재검사에서 Windows TrafficCaptureRecoveryTest의 601건 목록 조회가 Invalid metadata string으로 실패했다. 단순 재실행으로 숨기지 않고 실제 저장소 경로를 조사했다.

## 03. 도우미 · 요약

기존0.26.0 JAR에 새 회귀를 적용해 읽기 FileChannel의 위치 변경이 RandomAccessFile 쓰기 포인터를 바꾸는 것을 재현했다. 독립 READ 채널 두 개를 열고 정상 종료·생성 실패 시 모두 닫도록 수정했다. 포인터 분리·동시 캐시 퇴출/쓰기·전량 원본/메타데이터·채널 정리의 5개 회귀를 추가했고0.26.1 전체 release와 저장소 두 그룹10회 반복 검증을 진행한다. 기존0.26.0과이전 배포는 보존한다.

## 04. 도우미 · 요약

0.26.1 로컬 release1,948개가 통과했고 CapturePipelineTest33개·TrafficCaptureRecoveryTest41개를 각각10회, 총20개 그룹 실행으로 반복해 모두 성공했다. 반복 횟수를 고유 검사 건수에 중복 합산하지 않는다. 새 JAR·소스 ZIP과 소스 지문을 생성했고 버전별 경로에서0.26.0을 보존한다. 새 소스 업로드 후 원격에서 로컬 검증본과 정확히 같은 해시의 배포 파일을 조립하고 PR의 Windows 반복 검사와main 재검증까지 진행한다.
