# 커뮤니티 3.6.0 관리자·사용자 전용 포털 구현

- 날짜: 2026-10-17 (Asia/Seoul)
- 작업: community-role-portals-360

이 작업에서 확인 가능한 사용자 요청과 사용자에게 표시한 응답을 기록합니다. 과거 대화 전체나 내부 추론·도구의 원본 출력은 포함하지 않습니다. 요약한 항목은 별도로 표시합니다.

## 01. 사용자 · 원문

커뮤니티 테스트 사이트에 관리자 계정 권한 사이트랑 일반 사용자 권한 사이트를 나누어서 구분하고 기능도 구분해서 만들어줘, 이걸로 계정 권한 비교 extension 테스트 진행할께

## 02. 도우미 · 원문

커뮤니티 테스트 사이트에 관리자 영역과 일반 사용자 영역을 나누고, 역할별 메뉴·기능·접근 권한을 구분하겠습니다. 계정 권한 비교 확장에서 정상 차단과 권한 검증 취약점을 비교할 수 있도록 기존 실습 구조를 먼저 확인하겠습니다.

## 03. 도우미 · 원문

기존 커뮤니티는 한 화면에서 계정과 운영자 메뉴를 바꾸는 구조입니다. 여기에 `/admin`과 `/user` 전용 화면을 추가하고, 관리자는 회원 조회·요청 승인·공지 설정을, 일반 사용자는 본인 요청 작성·조회·취소를 하도록 나누겠습니다. 같은 기능의 취약·수정 API를 두어 수직 권한 상승과 Alice/Bob 간 수평 권한을 비교할 수 있게 하겠습니다.

## 04. 도우미 · 원문

역할별 화면과 API를 구현했습니다. 수정 모드에서는 서버가 역할·소유자·CSRF 토큰을 검사하고, 취약 모드에서는 권한 검증 누락을 재현하도록 했습니다. 현재 별도 세션의 관리자·Alice·Bob으로 실제 HTTP 응답과 승인·취소 후 상태를 확인하고 있습니다.

## 05. 도우미 · 원문

새 포털의 HTTP 검사 88개가 통과했습니다. 일반 계정의 관리자 API 접근은 403, 타인 요청 조회는 404로 차단되고, 취약 API에서는 같은 접근이 허용되는 것을 확인했습니다. 한글 제목·공지 저장도 확인했으며, 기존 확장 전체 검사와 사이트 3.6.0 Docker ZIP 생성을 진행 중입니다.

## 06. 도우미 · 원문

비로그인 쓰기 요청, 다른 계정의 CSRF 토큰, 처리된 요청 재승인까지 포함한 최종 권한 검사 101개가 통과했습니다. 두 센터는 같은 주소의 `/admin`·`/user`로 나누어 확장의 같은 Origin 조건을 유지했습니다. 동시 비교를 위한 브라우저별 세션 분리 방법도 사용법에 넣었습니다.

## 07. 도우미 · 원문

통합 실습 검사에서 기존 진단·버그바운티 API의 버전 표기가 3.5.2로 남아 있어 검사가 중단됐습니다. 두 곳을 3.6.0으로 맞췄고, 최종 배포 검사를 다시 실행하고 있습니다. 새 포털의 권한 검사 101개는 통과한 상태입니다.

## 08. 도우미 · 원문

최종 배포 검사 2,442개와 새 포털 권한 검사 101개가 모두 통과했고, 3.6.0 Docker ZIP도 생성됐습니다. 기존 확장 배포 파일은 유지했습니다. 이제 배포 파일의 소스 일치를 확인한 뒤 PR의 원격 검사와 main 반영을 진행하겠습니다.

## 09. 도우미 · 원문

원격 내구성 검사에서 배포 검증 스크립트가 Docker ZIP 경로를 3.5.2로 고정한 문제를 발견했습니다. 실제 기능 검사와 3.6.0 ZIP 재생성은 통과했으므로, 스크립트가 현재 사이트 버전을 읽도록 고치고 배포 파일 보존 회귀 검사도 추가하겠습니다.

## 10. 도우미 · 원문

GitHub의 실제 Docker·Oracle·Nginx 스택 검사도 성공했습니다. 새 포털의 역할별 101개 검사는 격리 H2에서 수행한 결과로 구분해 기록하겠습니다. 배포 검증 스크립트 수정과 파일 보존 회귀 검사 2개도 통과해 PR에 반영하고 있습니다.
