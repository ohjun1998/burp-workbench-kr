## 02. 도우미 · 원문

링크 내용을 확인하고, 현재 Workbench에 반영된 상태와 비교해 업데이트하겠습니다.

## 03. 도우미 · 요약

공유 페이지의 내용을 읽었습니다. 링크는 Cookie 헤더를 개별/조합으로 검사하고 로그인 사용자 정보로 세션을 확인해 계정 권한 비교에 연결하는 기능 제안이었습니다. 사용자 예시의 쿠키 값은 실제 자격정보로 사용하지 않았습니다.

## 04. 도우미 · 원문

링크는 여러 쿠키 중 인증에 필요한 항목을 찾고, 로그인 상태와 사용자 정보로 세션을 검증하는 기능 제안입니다. 이를 계정 권한 비교에 연결하겠습니다. 검증 URL과 로그인 판정 조건을 설정하고, 사용자가 실행하면 SCOPE 안에서 확인하도록 구성하겠습니다.

## 05. 도우미 · 원문

현재는 인증 쿠키 이름을 수동으로 지정할 수 있고, 계정 신원을 대조하는 갱신 기능도 있습니다. 여기에 쿠키 제외·단독·조합 검사를 추가하겠습니다. HTTP 200만으로 통과시키지 않고, 설정한 사용자 식별값이 맞는지 확인해 비교 전 세션 검사에도 연결하겠습니다.

## 06. 도우미 · 원문

쿠키 이름만 보고 용도를 단정하지 않도록 구현하고 있습니다. 검사 결과에는 “제외하면 신원 확인 실패”, “단독으로도 유효”, “조합에 필요”처럼 관측한 동작을 표시합니다. 세션이 바뀌거나 비로그인 대조가 구분되지 않으면 결과 적용을 보류합니다.

## 07. 도우미 · 원문

검사 창과 계정 비교 전 검증을 연결했습니다. 이제 격리된 테스트 서버로 단일 쿠키, 복수 쿠키 조합, Bearer 토큰 혼용, 만료 세션을 확인하고 있습니다. 만료되거나 사용자 신원이 맞지 않으면 비교 대상 요청을 보내기 전에 중단하도록 했습니다.

## 08. 도우미 · 원문

새 쿠키·세션 검사 47개가 통과했습니다. 두 쿠키가 함께 필요한 경우와 각각 단독으로 유효한 경우를 구분했고, Bearer 인증을 쿠키 인증으로 잘못 판단하지 않는 것도 확인했습니다. 이제 검사 창의 가독성과 작은 화면 배치를 점검하겠습니다.

## 09. 도우미 · 원문

작은 창에서 결과 표가 너무 좁아지는 부분을 발견해 입력 영역의 여백을 줄이고 있습니다. 검증 로직은 통과했으며, 결과를 충분히 읽을 수 있는지까지 확인한 뒤 배포 파일을 만들겠습니다.

## 10. 도우미 · 원문

검사 창은 기본 크기와 최소 크기, 두 테마 모두에서 표와 버튼이 잘리지 않도록 정리했습니다. 정식 배포 검사를 진행하면서, 전송 오류가 나더라도 쿠키·토큰 값이 오류 문구에 드러나지 않는지도 확인하고 있습니다.

## 11. 도우미 · 원문

결과는 `쿠키별 결과`와 `검증 요청` 탭으로 나눴습니다. 검사를 실행하는 것만으로 계정 설정이 바뀌지는 않으며, `검증 결과 적용`을 눌렀을 때 해당 계정의 쿠키 조합과 비교 전 검사 설정을 반영합니다.

## 12. 도우미 · 원문

정식 배포 검사 2,398개가 통과했습니다. 새 쿠키·세션 검사 50개에는 만료 시 비교 요청 차단, SCOPE 변경 시 중단, 오류 문구의 인증값 가림도 포함됩니다. 이제 배포 JAR 기준으로 전체 화면과 새 검사 창을 최종 확인하겠습니다.

## 13. 도우미 · 원문

새 검사 창을 포함한 화면 266개도 통과했습니다. 소스와 0.36.0 설치 파일, 사용법·검증 기록을 GitHub에 반영하고 있습니다. 원격 검사까지 통과하면 main에 병합하겠습니다.
