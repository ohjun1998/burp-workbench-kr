# Workbench 공개 전환 — 2026-10-17

## 사용자 요청 원문

1. “github action 사용 못하는데 다른 대안 없을까?”
2. “현재 github에서 개발중인 프로젝트 중에 github action이 필요한게 뭐가 있어?”
3. “burp workbench 로컬말고 공개로 전환하는건 어때?”
4. “그럼 공개로 전향해줘”

## 사용자에게 전달한 답변 요약

- 첨부 알림은 계정의 포함 Actions 2,000분 소진 안내임을 설명했다.
- 로컬 빌드, Self-hosted Runner, 공개 저장소의 표준 GitHub-hosted Runner를 비교했다.
- 연결된 저장소 5개의 공개 범위와 워크플로를 확인했다. Workbench·ScopeFlow는 비공개, Passive Scan 계열 3개는 공개였다.
- Workbench의 빌드·화면·Windows·내구성·Docker 검증 역할을 설명했다. 공개 저장소의 표준 Runner 실행 시간은 무료지만 대형 Runner와 저장 공간에는 별도 과금 조건이 있음을 알렸다.
- 공개 전환 시 코드, 과거 커밋, 대화 기록 및 기존 Actions 로그가 공개될 수 있어 공개 범위를 먼저 확인한다고 안내했다.
- 사용자가 Workbench 저장소의 공개 전환을 명시적으로 요청했다.

## 수행한 확인

- 대상: ohjun1998/burp-workbench-kr. ScopeFlow 및 다른 저장소의 공개 범위는 변경하지 않는다.
- 검사 기준 main: f94e303fad32bd3c577f99bf8e9a72a2394e2a0c.
- 지정한 텍스트 확장자의 main 파일 762개를 기본 인증정보 패턴으로 검사했다.
- 453개는 로컬 파일의 Git blob SHA가 원격 main과 일치함을 확인하고 검사했으며, 나머지 309개는 해당 원격 커밋에서 읽어 검사했다.
- 키 형식 탐지값은 실습용 가짜 데이터/테스트 예제임을 문맥으로 확인했다. 이 검사는 실제 서비스에 키를 전송해 유효성을 확인하는 방식이 아니다.
- 최근 Docker 검증 및 Chromium 검증의 작업 로그 2건도 같은 주요 패턴으로 검사했고 해당 패턴 탐지는 없었다.
- 과거 모든 커밋·태그·브랜치, 바이너리·압축파일 및 모든 과거 Actions 로그를 전수 검사한 것은 아니다. 개인정보/민감정보 부재에 대한 보증이 아니다.
- 기능 소스, 기존 배포물 및 0.21.0 소스는 수정하지 않았다.

## 공개 전환 결과

GitHub 설정에서 공개 전환을 요청한 뒤 추가 본인 인증(sudo mode)을 진행했다. 사용자가 보안 인증 창에서 GitHub Mobile을 선택해 인증했으며, 이후 GitHub 설정 화면에서 `This repository is currently public.` 문구를 확인했다. Workbench 저장소의 공개 전환이 완료됐다.

기존 워크플로와 기능 소스는 유지했다. 공개 전환 후 새로운 빌드나 CI를 실행한 것으로 보고하지 않는다. 공개 상태 변경과 대화 기록만 이번 작업 범위에 포함한다.

인증정보·일회용 코드·원시 도구 출력은 이 기록에 포함하지 않는다.
