# Feature Mapper를 Workbench 11번째 메뉴로 통합

- 날짜: 2026-10-19 (Asia/Seoul)
- 작업: feature-mapper-integration

이 작업에서 확인 가능한 사용자 요청과 사용자에게 표시한 응답을 기록합니다. 과거 대화 전체나 내부 추론·도구의 원본 출력은 포함하지 않습니다. 요약한 항목은 별도로 표시합니다.

## 01. 사용자 · 원문

workbench 내 extension 화면들 이미지로 보여줘

## 02. 도우미 · 요약

Workbench 0.43.0의 실제 UI에 예시 데이터를 넣어 렌더링한 기존 10개 기능 화면과 ZIP을 제공했다. 최신 0.46.1의 새 실행 화면이라고 표현하지 않았다.

## 03. 사용자 · 원문

10개 외에 extension 하나 더 있을텐데, 그것도 workbench에 병합 시켜줘

## 04. 도우미 · 원문

추가 확장이 Feature Mapper인지 저장소에서 확인하고, Workbench 안에서 사용할 수 있도록 통합하겠습니다. 기존 기능과 배포 구성을 살펴본 뒤 검증까지 진행할게요.

## 05. 도우미 · 요약

추가 확장이 Feature Mapper KR임을 확인했다. Workbench의 11번째 메뉴로 넣고, 공통 OFF/SCOPE 수집 제어·프로젝트 저장과 복원·브라우저 연결·종료 흐름까지 통합하기로 안내했다.

## 06. 도우미 · 요약

Burp 탭과 HTTP 콜백 중복을 막기 위해 공유 작업 화면과 독립 진입점을 분리했다. 초기 통합 33개, 브라우저 버튼 이름 연결을 추가한 최종 통합 35개와 주요 기존 메뉴 회귀가 통과했다. 전체 회귀·HTTP 검사와 배포 생성을 진행 중임을 알렸다.

## 07. 도우미 · 요약

전체 회귀에서 값이 없는 인증 헤더가 Mapper의 추가 오류로 이어지는 사례를 확인했다. 원본은 보존하면서 분류에 사용할 수 없는 헤더 값을 건너뛰도록 보완하고 복구 회귀를 재확인한다고 안내했다.

## 08. 도우미 · 요약

최종 배포 검사 3049개, 내장 통합 36개, Mapper Java 94개 및 브라우저 도우미 Node 7개가 통과했다. 통합 화면 156개·안내 52개·독립 호환 화면 30개를 확인했고, 소스 ZIP을 새 폴더에서 재빌드한 JAR가 배포 JAR와 바이트 단위로 같았다. 실제 Burp GUI·실제 브라우저 DOM은 이번 실행과 구분한다.

## 09. 도우미 · 원문

소스 ZIP을 새 폴더에서 빌드한 JAR도 배포본과 바이트 단위로 일치합니다. 검증 기록과 날짜별 대화 기록을 함께 정리했고, 이제 PR을 올려 GitHub 검사와 main 병합을 확인하겠습니다.

## 10. 사용자 · 원문

남은 단계 계속 진행해줘

## 11. 도우미 · 원문

Feature Mapper 통합과 로컬 검증은 완료됐고, GitHub 반영과 main 병합이 남아 있습니다. 이어서 마무리하겠습니다.

## 12. 도우미 · 원문

검증한 JAR·소스·화면 자료를 GitHub에 반영하고 있습니다. 업로드한 파일이 로컬 검증본과 일치하는지 확인한 뒤 PR 검사를 진행하겠습니다.

## 13. 사용자 · 원문

github 병합과 메인 반영까지 마무리 해줘

## 14. 도우미 · 원문

PR #78까지 올라갔습니다. GitHub 검사 결과를 확인해 main에 병합하고, 완료 기록까지 반영하겠습니다.

## 15. 도우미 · 원문

빌드 검사와 Mapper 전용 검사는 통과했습니다. Linux 디스크 부족 복구 검사에서 오류 집계 검증이 실패해 원인을 확인하고 있습니다. 이 항목까지 해결한 뒤 병합하겠습니다.

## 16. 도우미 · 원문

검사가 트래픽 저장 오류와 Mapper 저장 오류를 같은 합계로 비교하고 있었습니다. 두 오류를 단계별로 검증하도록 고쳤고, 공간 확보 후 Mapper 수집도 다시 이어지는지 확인하는 검사를 추가했습니다. GitHub에서 재검증하겠습니다.
