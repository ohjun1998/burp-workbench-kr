# Workbench Next 0.52.1 안정화와 검증 종료조건

- 날짜: 2026-10-24 (Asia/Seoul)
- 작업: stability-0521

이 작업에서 확인 가능한 사용자 요청과 사용자에게 표시한 응답을 기록합니다. 과거 대화 전체나 내부 추론·도구의 원본 출력은 포함하지 않습니다. 요약한 항목은 별도로 표시합니다.

## 01. 사용자 · 원문

0.52.0 버전 내 개선방안들 최적화 및 고도화 해주는데, 얼마나 더 확인해야 개선 방안들이 더 이상 안나올까?

## 02. 도우미 · 원문

0.52.0에 남은 개선 항목과 실패한 검사를 확인해 우선순위가 높은 부분부터 수정하겠습니다. 개선안이 나오는 횟수보다, 이번 버전을 마무리할 수 있는 기준을 정하는 게 중요합니다. 확인된 결함·필수 검증·선택 개선을 구분하고, 어느 조건을 충족하면 배포를 마무리할지 함께 정리하겠습니다.

## 03. 도우미 · 원문

개선 아이디어가 완전히 안 나오는 시점은 사실상 없습니다. 대신 **같은 핵심 흐름을 반복해도 새 중대 결함이 없고, 필수 검사가 모두 통과하는 상태**를 이번 마무리 기준으로 삼겠습니다.

우선 Windows 검색과 브라우저 연동의 알려진 실패를 해결하고, 원본·설정·증거 연결을 확인하겠습니다. 기존 0.52.0 배포 파일은 보존하고, 수정본은 0.52.1 안정화판으로 구분하겠습니다.

## 04. 도우미 · 원문

원인 세 가지를 좁혔습니다. 검색은 타이머가 끝난 뒤 화면 갱신이 실행되기 전을 완료로 오인했고, 응답 분석 초기화에는 특정 순서에서 메모리 예약이 남는 문제가 있었습니다.

브라우저 검사는 Chrome API가 제공하지 않는 PATCH 본문까지 해시 일치를 요구하고 있었습니다. 이 부분은 관측하지 못한 본문을 ‘일치’로 표시하지 않도록 근거와 검사를 바로잡고 있습니다.

## 05. 도우미 · 원문

세 항목의 수정과 개별 회귀 검사가 통과했고, 교차 검토에서도 추가로 확인된 차단 결함은 없었습니다. 현재 최종 소스로 전체 배포 검사를 진행 중입니다. 이번에는 이 수정 범위를 고정하고, 남아 있던 Windows·실제 브라우저 실패가 해소됐는지까지 확인해 마무리하겠습니다.

## 06. 도우미 · 원문

최종 검사 중 로컬 체크아웃에서 검증용 파일 일부가 빠진 것을 확인했습니다. 해당 파일을 복원해 이어가겠습니다. 실제 Chrome 실행 파일도 준비됐으므로, 브라우저 연동은 자동 검사뿐 아니라 실제 브라우저로 확인하겠습니다.

## 07. 도우미 · 원문

이번에 수정한 세 문제는 재현 검사에서 수정 전 실패와 수정 후 통과를 확인했습니다. 다만 반복적인 경합 문제는 Linux 검사만으로 해결됐다고 단정하기 어려워 Windows 결과까지 보겠습니다.

마무리 기준은 “개선안 0개”가 아니라, **확인된 결함 해결·필수 환경 검사 통과·기존 기능 유지·배포물 일치**입니다. 이 기준을 충족하면 이번 안정화를 마치고 새 기능 제안은 다음 버전으로 넘기겠습니다.

## 08. 도우미 · 요약

개별 수정 범위를 고정하고 최종 release·실제 Chrome·Windows CI 및 배포 지문 확인을 진행한다. 개선 제안이 없어질 때까지 기능을 늘리지 않고 정한 필수 검증이 통과하면 안정화를 마무리한다.

## 09. 도우미 · 원문

로컬 배포 검사 **3,726개**, Mapper Java **136개·도우미 9개**, Workbench 화면 **342개** 검사가 통과했습니다. 실제 Chrome은 이 실행 환경의 소켓 제한으로 시작 단계에서 중단돼, 브라우저 통과 결과로 집계하지 않았습니다.

새 배포물을 별도 PR에 올리고 GitHub의 실제 브라우저·Windows 검사로 남은 필수 조건을 확인하겠습니다.

## 10. 도우미 · 원문

새 JAR·소스 ZIP과 검증 기록을 준비했습니다. 비교 부하 검사에서는 원본 유실·처리 오류·화면 스레드의 원문 복원이 모두 0건이었습니다. 실행 시간은 시나리오별로 차이가 있어 일괄적인 속도 향상으로 표현하지 않았습니다. 기존 0.52.0과 이전 배포 파일의 보존도 확인했습니다.
