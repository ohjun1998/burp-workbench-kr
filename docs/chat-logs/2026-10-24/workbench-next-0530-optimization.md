- 사용자가 전체 구현을 요청했다. 구현·검증·새 JAR/소스 제공을 진행한다.

## 빌드 준비
로컬 도구의 대형 바이너리 읽기 제한으로 저장소에 이미 포함된 공개 빌드 입력을 같은 저장소의 GitHub Actions artifact로 전달한다. 새 작업 브랜치만 사용하며 main·이전 배포·접근 설정은 변경하지 않는다. 이 준비 작업을 제품 검증 통과로 집계하지 않는다.

저장소의 빌드 의존성과 글꼴 10개는 원본 Git blob 해시로 확인해 작업·기준선 폴더에 복원했다. 전체 HTTP 검사는 기존 WAR의 라이브러리를 꺼낸 뒤 현재 실습 소스를 다시 컴파일하므로, 해당 WAR도 별도 artifact로 전달한다. 로컬 Java에는 컴파일러 모듈은 있지만 `--release 17`에 필요한 `ct.sym`이 없어 Temurin 21의 API 심볼과 버전·해시 기록을 별도로 전달한다. 시스템 Java를 변경하지 않고 작업 공간의 사본에서 검증하며, 공식 빌드의 릴리스 대상이나 의존성 해시 검사는 유지한다.

## 구현 및 검증 진행 · 공개 응답 요약
- 검색 예약 상태 경합을 재현하고 수정했다. JS 검색 캐시, 응답 분석 UI 일괄 갱신, 프로젝트별 인증 설정 보관, 비교 준비 목록 보존, 업무별 남은 점검 화면을 구현했다.
- 교차 검토에서 모달 도중 원본 목록 교체와 브라우저 요청 폭주 시 오래된 해시 오연결 가능성을 추가로 발견해, 오래되거나 모호한 결과를 거절하도록 보완했다.
- 핵심 수정과 추가 회귀 검사를 완료했다. 0.53.0 통합 빌드 및 Windows·실제 Chromium 검증을 시작하고, 최종 소스 성능을 다시 측정해 새 배포 파일에 반영한다.
- 로컬 Java 17 대상의 변경 전·후 공식 빌드는 성공했다. HTTP·실제 브라우저 검증은 로컬 loopback 소켓 제한 때문에 GitHub Actions에서 실행하며, 아직 통과로 집계하지 않는다.
