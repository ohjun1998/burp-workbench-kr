## 실제 발견·수정과 추가 안내 — 요약

실제 Chromium 페이지에서 지연 메뉴 누락·메뉴 동작 전 초기 링크 손실·탐색 한도의 잘못된 completed 표시를 재현했습니다. 6개 fixture의 수정 전 검사는 기존 결함 재현을 확인하며 수정 후 28개 검사도 통과했습니다. 전후 반복을 합산하지 않습니다. 운영 DOM/MAIN guard의 별도 17개 검사는 중첩되는 추가 근거입니다. 관리형 Chromium 정책이 unpacked extension 로드를 차단해 native MV3/DNR 실행은 검증하지 못했습니다. 정책을 바꾸지 않았고 service/API adapter와 실제 DOM 검사로 구분했습니다.

새 기준 시험에서 VulnBank 일반 사용자 신원은 정상인데 merchant API401로 전체 실행이 PAUSED 되는 사례를 확인했습니다. 새 인증·비로그인 신원 GET 대조(두 요청 모두 같은 Scope·공유 예산·원본 보관)를 수행하고 두 신원이 구분될 때 해당401 경로를 ACCESS 미확인으로 남겨 수집을 계속하도록 수정했습니다. 실제 만료·신원 불일치·공개 신원 응답·쿠키 변경·challenge·로그인 이동·예산 부족은 중단합니다. Runner 집중 검사는104→152개로 늘었으며 전체 검사와 중복 합산하지 않습니다.

백틱 문자열은 정적 cooked값과 rawText를 분리하고 동적 API는 RAW_TEMPLATE_INTERPOLATED / DYNAMIC_UNRESOLVED로 보존합니다. 식 평가·추정 URL 실행은 없습니다. Report 집중119개를 통과했고 같은 실제 Juice Shop 번들의 공식 JAR 대조는17→115행, 새 template64행(API4/PATH60)이었습니다. 전체 번들 구문과 모호한 경계 이후는 부분/미검사 상태를 유지합니다.

가이드 시각 검수에서 화면의 옛 helper0.4.0 안내를 발견해 버전 중립 문구로 수정했습니다. 이 표시 수정 전 a92 후보의 실행·캡처·증거는 별도 setup-attempts/후보 폴더로 옮겨 보존하고 최종 집계에서 제외했습니다. 최종 JAR SHA-256은 `a8dd345b44b4893a301bf3092817335585c15ebd67cb5e6508bd3847fee49400`이며 새14회 after 실행과112뷰 캡처·PDF는 이 파일 기준입니다. 최종 가이드는35쪽/28캡처이며 배치·구조·시각 검수를 통과했습니다. 새 helper0.4.1 설치도 필요합니다.

OopsSec 개발 서버의 신원 URL에서 실제500이 발생해 실행이 중단되는 별도 관측도 남겼습니다. 같은 고정 인증값의 새 신원 조회가200·기대 JSON으로 회복된 뒤 OopsSec만 수정 전2회/후2회의 한정 추가 대조를 순차 실행했습니다. 최초 관측과 원본 Next 개발 서버 오류 로그·보존 사유를 기록하고, 다시 실패하더라도 반복해 통과 결과만 고르는 방식은 사용하지 않습니다. 코드·고정 config·앱 소스는 바꾸지 않았습니다.

## 추가 진행 안내 — 원문

> 실제 사이트 재시험에서 추가 문제를 발견했습니다. 일반 사용자 로그인은 정상인데, 별도 가맹점 인증 API의 401 응답을 전체 세션 만료로 판단해 탐색이 멈췄습니다. 설정된 신원 확인 URL을 다시 조회해 로그인이 유지되는 경우와 실제 만료를 구분하도록 보완하겠습니다.

> 가이드 화면 검수에서 구버전 도우미 안내가 남아 있는 것도 발견해 수정했습니다. 보고서와 시험 결과가 최종 실행 파일을 기준으로 일치하도록, 수정 전 기준 결과는 보존하고 최종 JAR로 재시험과 캡처를 다시 진행하고 있습니다.

> 최종 가이드북은 **35쪽·28개 캡처**로 완성했고, 화면 배치 검사 112뷰도 모두 통과했습니다. OopsSec의 추가 전후 대조가 끝나면 전체 자동 검사와 패키지 검증을 마치고, 새 JAR·원문 분류 보고서·가이드를 함께 전달하겠습니다.

## 최종 검증과 설명 정정 — 요약

## 추가 설명 정정 — 원문

> VulnBank의 경로별 근거를 추가로 확인하니, 최종 자동 탐색에서는 문제의 가맹점 API를 방문하지 않았습니다. 따라서 실행 완료만으로 401 수정 효과를 입증했다는 앞선 설명을 정정합니다. 해당 경로를 직접 지정한 전후 대조를 별도로 추가해, 401 응답과 신원 재확인 동작을 확인하겠습니다.

> 별도 직접 경로 대조에서는 두 버전 모두 같은 가맹점 API의 401을 받았습니다. 1.3.1은 5회 전송 후 멈췄고, 1.3.2는 새 인증 신원 200·비로그인 대조 401을 확인한 뒤 탐색을 이어갔습니다. 자동 발견 성과와 구분해 보고서에 싣고, 거부된 API 자체는 ‘접근 권한 미확인’으로 유지합니다.
