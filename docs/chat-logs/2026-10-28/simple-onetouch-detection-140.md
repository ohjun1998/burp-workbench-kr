# Simple 원터치 주요정보 탐지 고도화 작업 대화

기준 날짜: 2026-10-28 (Asia/Seoul). 이 파일은 공개 작업 기록이며 인증값·원문 응답·숨겨진 추론·도구 원문을 포함하지 않습니다.

## 사용자 요청 원문

> 테스트 한 사이트별로 탐지한 주요정보들을 나열해서 뽑아줄래?

> 고도화가 필요한 부분이 뭐가 있을까?

> 원터치 extension에서 주요정보 탐지율을 높이기 위한 고도화 방안하고 추가로 필요한 기능들 안내해줘

> 적용시켜줘

이전 요청에서 기존 extension 8개·Next와 이전 Simple 파일을 유지하고 Simple이라는 별도 이름으로 제공하며 단계별 캡처 가이드북을 작성하도록 했습니다. 이번 요청은 아래 안내한 고도화의 구현 지시입니다. 이전 main 병합은 이미 완료된 별도 작업입니다.

## 적용 직전 안내 요약

다음은 assistant의 사용자 공개 답변 요약이며 원문 인용은 아닙니다.

- Katana·HTML/JS·브라우저의 메뉴·탭·iframe·지연 로딩 결과를 하나의 수집 흐름으로 연결합니다.
- 실제 Fetch/XHR 요청·응답 관측을 메뉴에 연결하고 동적 API 문자열의 발견과 실제 도달을 구분합니다. 동적 식을 임의로 평가하거나 인증값을 복사하지 않습니다.
- JSON·HTML·JS·헤더·쿠키·설정파일·API 명세를 문맥에 맞게 분석하고 보충 파서를 제품 탐지에 연결합니다.
- 비밀값 형태·개인정보·환경·주요 경로를 분류하되 공개/예시/데모/코드 조각/미확인을 구분합니다.
- Scope·계정·요청 예산·실행 상태를 유지하면서 미방문·실패·세션 만료 등의 이유와 선택 재점검·재개를 제공합니다.
- 메뉴→화면→API→응답→정보 관계와 원본 증거를 표시하고 이전 실행의 변경 이력을 제공합니다.
- 기존 도구8개와 원문 값 보존·보고서 저장을 유지합니다. 탐지율은 알려진 기대값·실제 방문·오탐·미확인을 나누어 검증합니다.

## assistant 진행 안내 원문

> 기존 extension 8개와 원본 버전을 유지하면서 Simple의 원터치 탐지 흐름에 적용하겠습니다. 먼저 현재 구조를 확인한 뒤, 탐색·분석·미확인 처리 기능을 개선하고 재테스트와 가이드 갱신까지 진행하겠습니다.

> 새 버전은 Simple 1.4.0으로 구분하겠습니다. 현재 코드를 확인해 보니 경로별 요청·분석 상태 표시와, 보고서에서만 추가 추출하던 정보를 extension 탐지에 통합하는 부분이 핵심입니다.
>
> 기존 배포 파일의 해시를 기록해 보존 여부를 확인하고 있습니다. 브라우저 수집, 탐지 엔진, 커버리지·재점검 화면, 가이드 작업은 나누어 진행 중입니다.
