## 공유 대화에서 읽은 내용 — 요약

Simple 1.3.0을 Juice Shop, BenchmarkJava, VulnerableApp, OopsSec Store, DVBank, VulnBank, LOOP Community에서 시험한 이전 대화입니다. 공개 본문에 정상 세션의 password 폼 오인 중단, `.env`와 대표 API 발견 누락, 표현식·소스맵 코드의 시크릿 오탐, 같은 실습 토큰의 중복·상이한 분류, 추정 경로의 예산 소모가 적혀 있습니다. 자동 발견과 직접 지정 대조, 권한 차이와 정책 판정, 가짜 200과 미확인 상태를 구분하도록 요구했습니다.

이전 대화의 “개선안 9개” 전체 원문은 별도 Library PDF/HTML/ZIP 링크에 있었고 현재 세션에는 그 파일이 제공되지 않았습니다. 이전 세션의 5,042개 통과·7개 재테스트 상태를 현재 검증 증거로 재사용하지 않습니다.

## 추가 확인 요청 — 원문

> 공유 대화에는 개선안 9개의 전체 목록이 없고 연결된 이전 보고서 파일도 현재 세션에서 열리지 않습니다. 추가로 꼭 반영할 항목이 있다면 항목명이나 내용을 적어주세요. 우선 본문에서 확인되는 문제부터 수정·검증하겠습니다.

## 진행 안내 — 원문

> 공유 대화에서 정상 세션을 만료로 오인하는 중단, `.env`·일부 API 누락, 변수 표현식의 시크릿 오탐, 중복 분류, 불필요한 경로의 예산 소모를 확인했습니다. 기록에 나온 7개 실습 사이트를 기준으로 재테스트를 준비하고, 보고서에는 실제 응답에서 추출한 원문 값과 제품의 탐지 결과를 구분해 싣겠습니다.

> 수정본은 **Simple 1.3.1**로 분리하고 있습니다. 원문 값을 담는 별도 ‘분류 보고서 저장’ 기능도 추가해, 값의 종류·발견 위치·응답 원본 ID와 제품 탐지/보고서 추가 파싱 여부를 확인할 수 있게 하겠습니다. 7개 사이트는 실제 원본 앱으로 준비 중이며, 앞선 대화의 검사 수치는 이번 결과에 합산하지 않습니다.

## 작업 범위 — 요약

기준은 Simple 1.3.0 커밋 `5d09640e918755174a450580ca05e209970ce71d`이며 새 브랜치 `account-a/simple-retest-values`에서 진행합니다. 기존 8개 도구와 원본 Next·기존 배포 파일을 보존합니다. 원문 값 보고서는 사용자가 지정한 로컬 파일로 저장하며 실행 인증값이 포함되는 재시험 원문 자료는 자동으로 공개 저장소에 게시하지 않습니다. 새 수정 소스·별도 배포·가이드·실제 검사·재현 자료와 한계를 PR로 전달합니다. main 병합은 이번 작업에서 수행하지 않습니다.

## 이후 진행 안내 — 요약

실제 원본 7개 앱의 별도 로컬 실행으로 수정 전 기준을 확보하고, 자동 발견과 직접 보호 API 대조를 구분했습니다. Java HTTP 어댑터의 HTTP/2 Upgrade 호환 문제로 무효가 된 준비 시도는 별도로 보존하고 본집계에서 제외했습니다. 원본 응답의 Content-Length 불일치는 미확인 전송으로 분리하며 단순 시도 수를 완료 응답 수로 표현하지 않습니다.

Juice Shop 대표 API가 기존 구간 뒤쪽에 있음을 원본 번들에서 확인했고, 동적 서버·필수 ID를 추측 호출하지 않는 후보로 보존하도록 보완했습니다. 실제 정상 계정의 password 폼 오인 중단을 3개 앱에서 재현해 세션·신원 실패와 구분했습니다.

원문 보고서 검토에서 문자열 연결식의 앞부분을 실제 값으로 오인할 수 있는 사례, 미지원 엔터티의 미확정 처리, className이 ssn 부분문자열 때문에 민감정보로 분류되는 문제를 발견해 보완했습니다. 집중 검사 후 수정 파일과 최종 보고서·재테스트의 JAR 지문을 일치시키고 있습니다. 이전 중간 JAR의 통과 수치는 최종 JAR 검증으로 합산하지 않습니다.

## 최종 검사와 전달 준비 — 요약

최종 Simple 1.3.1 JAR로 전체 기본 검사 5,104개(Workbench 4,799 / payload HTTP 136 / Mapper Java 145 / Node 24), 별도 실제 Katana 1.8.0 HTTP·HTTPS 검사 102개, 보고서 형식 단위검사 10개를 통과했습니다. 합성 데이터로 실제 Swing 컴포넌트를 렌더링한 112뷰·2,244개 컨트롤·120개 상태의 배치 게이트는 모두 0건입니다. 최종 35쪽 가이드는 28개 캡처를 포함하며 구조·시각 검수를 마쳤습니다. 실제 Burp 데스크톱 GUI를 조작한 결과는 아닙니다.

기본 검사 중 최초 JsArchivePagingTest의 5초 대기 시간 초과가 있었고, 동일 소스·동일 JAR의 단독 재시도 52개와 7개 앱 종료 뒤 전체 검사를 통과했습니다. 시간 한도나 소스를 완화하지 않았으며 정확한 부하 인과관계는 확정하지 않았습니다. 이 이력은 검증 JSON에 보존합니다.

7개 원본 앱에서 수정 전·후와 루트 자동 탐색·직접 seed 대조를 나눈 28회 실행을 완료했습니다. 수정 전 1,080회 전송 시도 중 완료 응답 1,076개·전송 오류 4개, 수정 후 1,203회 중 완료 응답 1,195개·전송 오류 8개입니다. 정상 인증 폼에 의한 루트 자동 중단은 3개 앱에서 0개로 줄었고, Juice Shop 대표 API 3종 복원과 VulnBank .env의 자동 수집을 확인했습니다. Benchmark의 요청 예산 도달과 OopsSec의 감사 하네스 105초 한도 중단, 전송 오류는 부분·미확인으로 기록했습니다. 모든 사이트의 전체 경로나 취약점을 검사했다는 의미는 아닙니다.

원문 값 보고서에는 20,281개 발견 위치별 기록을 API·민감정보·토큰·키·환경·DB·경로·내부·기타로 분류합니다. 제품 탐지 1,415개, 제품 보고서 보충 파싱 15,437개, 독립 보고서 보충 파싱 3,418개, 테스트 로그인 인증 11개를 구분합니다. 값·원문 표기·발견 위치·응답 지문을 함께 제공하며 예제·공개·미검증·동적 미확정도 표시합니다. 원문 보고서와 실행 인증값은 Git에 올리지 않고 로컬 첨부로 전달합니다.

최종 JAR SHA-256은 `9b50905cebb5485274e986445aefb198dbc56c3d0d9cb1bfeef69a0c4d0f969d`입니다. 별도 새 폴더에서 소스 ZIP을 풀어 strict JDK17로 빌드한 결과가 배포 JAR와 바이트 단위로 일치했습니다. 기존 Simple 배포·PDF 22개와 과거 가이드 보존 해시도 유지했습니다. Simple 1.3.1의 소스·문서·배포 입력은 고정했으며 후속 원격 검사 상태는 루트 인수인계와 PR에 기록합니다.

전달은 `account-a/simple-retest-values` → `account-a/simple-katana` 초안 PR로 진행합니다. 기반 Simple 1.3.0 PR이 아직 main에 병합되지 않아 이 기준으로 쌓으며 main과 다른 작업 브랜치를 덮어쓰거나 강제 push하지 않습니다.

## 추가 진행 안내 — 원문

> 최종 파일 그대로 전체 자동 검사 **5,104개**가 통과했습니다. 이전 배포 파일 22개도 해시가 모두 유지됐습니다. 분류 보고서는 원문 표기와 파싱값을 함께 제공하며, 전체 목록을 담은 ZIP·PDF 보고서·35쪽 가이드북을 첨부할 준비를 마치고 있습니다.

> 마지막으로 배포 ZIP을 별도 폴더에서 다시 빌드해 일치 여부를 확인하고, 보고서의 원문 값과 분류 결과를 검증하겠습니다. 기존 파일은 유지한 채 Simple 버전과 재시험 자료를 정리하고 있습니다.

> 배포 ZIP에서 따로 빌드한 JAR가 최종 검사본과 바이트 단위로 일치했습니다. 보고서는 API·민감정보·토큰·키·환경·DB·경로 등으로 나누고, 제품 탐지와 보고서 보충 파싱을 구분했습니다. 항목 수는 발견 위치별 기록 수이며, 고유 취약점 수를 뜻하지 않습니다.
