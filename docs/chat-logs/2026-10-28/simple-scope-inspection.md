# Workbench Simple 1.2.0 Scope 통합 점검 적용 및 캡처 가이드북

- 날짜: 2026-10-28 (Asia/Seoul)
- 작업: simple-scope-inspection

이 작업에서 확인 가능한 사용자 요청과 사용자에게 표시한 응답을 기록합니다. 과거 대화 전체나 내부 추론·도구의 원본 출력은 포함하지 않습니다. 요약한 항목은 별도로 표시합니다.

## 01. 사용자 · 원문

workbench에서 핵심 메인 기능만 주력으로 사용 할 수 있도록 최적화 및 재구성해서 생성해줘

- 꼭 필요하지 않은 부가적인 기능들은 제거해서 메인 기능에 집중할 수 있게해줘
- UI, UX도 핵심 기능 사용에 맞추어서 고도화해줘
- 기존 파일은 냅두고 Simple 버전 이름으로 새롭게 생성해서 구분해줘
- 사용 단계별로 이미지 캡쳐해서 가이드 북 작성해줘
- 기존 extension은 유지하는데 실행 과정들만 핵심만 포함하고 부가적인 기능들은 제거해서 사용자 편의성에 맞추어줘

## 02. 사용자 · 요약

원본 저장소: https://github.com/ohjun1998/burp-workbench-kr.git

## 03. 사용자 · 원문

이전에 extension 8개인거 유지하고 사용자 편의성 중심으로 핵심 및 주요 기능들은 유지하되 부가적인 기능들은 제외시켜서 재구성해줄래?

## 04. 사용자 · 원문

지금 아이디어가 하나 떠올랐는데, Scope 범위 지정한 URL를 대상으로 원터치 시 메뉴 및 기능들에 접근하면서 서버, was, db, api 등 기타 환경정보를 확인하고 이에 해당하는 주요 경로들을 자동으로 접근해서 응답 값 확인, API key, 민감정보, 주요정도 등 기타정보 확인, 이외에도 추가적으로 필요한 기능 제시해줘

## 05. 도우미 · 요약

Scope URL과 검사 계정을 기준으로 메뉴·동적 라우트·환경·주요 경로·API·민감정보를 한 실행에 연결하고, 계정별 차이·이전 실행 비교·커버리지·원본/증거 연결을 포함하는 통합 점검을 제안했습니다. 기존 8개 도구와 기존 배포 파일을 보존하는 Simple 별도 버전을 전제로 했습니다.

## 06. 사용자 · 원문

상기 내용 전체 적용해주고 가이드북도 첨부해줘

## 07. 도우미 · 요약

Simple 1.2.0에서 기존 8개 도구를 유지한 Scope 통합 점검을 구현하고 로컬 테스트를 진행했습니다. API 후보 출처 중복과 종료 상태 검증 문제를 수정하고, 전체 원본 읽기 전용 보기 및 프로젝트 전환 정리를 점검했습니다.

## 08. 도우미 · 요약

실제 Chromium DOM 검증 17개를 통과했습니다. 시스템 관리 정책 ExtensionInstallBlocklist로 확장 설치가 차단되어 MV3·DNR 통합 실행은 차단/미검증으로 별도 기록하고 정책을 바꾸지 않았습니다. 가이드 이미지는 운영 Swing 컴포넌트에 합성 패킷을 넣어 생성한 캡처이며 실제 Burp 수동 조작으로 주장하지 않습니다.

## 09. 도우미 · 요약

기존 Workbench 및 Simple 1.0.0·1.1.0 배포 파일의 해시를 보존했습니다. Simple 1.2.0 자동 검사 4,786개와 별도 실제 Chromium DOM 17개가 통과했고, 100개 운영 Swing 렌더 화면의 배치 검사를 통과했습니다. 수정된401 예제를 반영한31쪽·25캡처 가이드북을 구조·확대 검수했습니다. 배포용JAR·브라우저도우미ZIP·소스ZIP을 만들었고 독립 소스ZIP 재빌드 JAR가 바이트 단위로 일치했습니다. GitHub 작업 브랜치·PR 및 strict Java17 CI 확인을 진행한다고 안내했습니다.
