# Simple 도구별 디자인 적용 및 main 병합 대화

이 문서는 아래 사용자 요청 원문과 사용자에게 표시한 답변의 요약입니다. 내부 추론, 비공개 지침, 도구 원문 및 자격 증명은 포함하지 않습니다. 이전 작업은 `simple-classic-layout.md`, `simple-tool-captures.md`에 이어집니다.

## 답변 요약 · 설계 단계

현재 Simple 1.4.4의 합성 Swing 캡처를 검토하고 0.39.2의 폴더 구조를 유지하는 개선안을 제시했다. 공통 작업 조건·검색·실행 배치, 목록과 상세의 가변 분할, 도구별 레이아웃을 설명했다. 코드 수정 없이 도구 8개 각각에 이미지 시안을 생성했다. 요청에 따라 큰 본문 제목·소개 문구를 제거하고 확보한 공간을 목록·패킷·편집 영역에 배분한 8개 수정 시안을 보여줬다. 이때까지 이미지 시안만 만들었으며 코드·JAR는 변경하지 않았다고 명시했다.

## 답변 요약 · 구현 단계

사용자의 마지막 요청을 소스 적용과 main 병합 승인으로 받아 작업을 시작했다. 기존 Simple의 큰 본문 제목은 이미 숨겨져 있어 실제 패널 재배치와 상세 보기를 구현한다고 알렸다. 이전 배포 파일을 보존하고 새 Simple 1.4.5와 내장 Mapper 0.3.8로 준비했다.

계정 비교의 기준/계정 응답·요청·근거 상세, 응답 분석의 전체 폭 표·검색·관련 응답, 준비/결과 단계로 나눈 입력값 검사, 증거 목록 옆 패킷·영향·재현 절차를 구현했다. 인증 후보 원문은 목록에서 가리고 기존 계정 상세에서 확인하도록 했다. 사용자 시안 데이터는 제품에 넣지 않으며 실제 운영 모델에 연결했다.

검증 중 이전 행 높이·버튼 간격 가정, 사라진 환경 분할의 테스트 기대, 빈 선택 안내 문자열을 수정했고, 계정 비교의 이전 헤더가 잘림으로 잡힌 것을 정리했다고 알렸다. 선택·검색·정렬 뒤 원본 연결과 화면 전환 무전송을 새 회귀 검사로 확인한다고 설명했다. 실제 Burp GUI와 합성 운영 Swing 렌더링의 차이를 유지했다.

최종 검증 수치와 원격 병합 결과는 릴리스 안내 및 병합 기록에 별도 기록한다. GitHub API 접근 제한으로 PR API는 사용할 수 없으며, 명시적 main 병합 요청 범위에서 지원되는 Git 경로의 일반 병합을 사용한다. 강제 push나 보호 규칙 우회는 하지 않는다.

## 최종 검증 답변 요약

전체 검사 5,912개, 화면 132개, Katana 102개가 통과했고 JAR 해시가 일치한다고 사용자에게 알렸다. Simple 1.4.5 JAR·소스 ZIP을 확정한 뒤 일반 Git 병합으로 main에 반영한다고 안내했다. 실제 원격 결과는 후속 병합 기록에 기록한다.
