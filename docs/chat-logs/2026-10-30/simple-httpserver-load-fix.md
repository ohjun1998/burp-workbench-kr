# Simple 1.4.3 · Burp 확장 로드 오류 수정

- 날짜: 2026-10-30 (Asia/Seoul)
- 작업: simple-httpserver-load-fix

이 대화에서 확인할 수 있는 사용자 요청과 사용자에게 표시한 응답을 기록합니다. 요약은 별도로 표시하며 내부 추론·도구 원본 출력·자격 증명은 포함하지 않습니다.

## 01. 이전 설정 작업 · 요약

사용자가 `ohjun1998/burp-workbench-kr` main 저장소의 클라우드 환경 설정을 요청했습니다. 도우미는 Simple 1.4.2 개발 도구를 준비하고 회귀·HTTP·Mapper·Katana·합성 Swing 검증 결과와 실제 Burp GUI 미검증 범위를 보고했습니다. 클라우드 환경의 설치·시작 지침 초안을 저장했으며 게시 자체는 하지 않았습니다.

## 02. 사용자 오류 보고 · 요약

“extension 추가 하니까 아래와 같이 에러 뜬다.”라는 요청과 Java 예외 스택을 제공했습니다. `WorkbenchExtension.initialize`의 Swing 초기화 중 `FeatureMapperWorkspace.initialize` → `BrowserBridge`에서 `NoClassDefFoundError: com/sun/net/httpserver/HttpServer`가 발생했고, 원인은 `ClassNotFoundException`이었습니다.

## 03. 도우미 응답 · 요약

`jdk.httpserver`의 클래스 접근 실패를 확인하고, Burp 런타임의 모듈 누락과 확장 클래스 로더 접근 문제를 구분해 조사하겠다고 안내했습니다. 어떤 JAR와 Burp 버전을 사용했는지 물으며 Simple 1.4.2를 기준으로 독립 재현을 진행했습니다.

## 04. 사용자 환경 확인 · 원문

sample 1.4.2, burp suite Community Editor v2026.9.2

## 05. 도우미 진행 안내 · 요약

스택의 줄번호가 Simple 1.4.2와 일치하며 브라우저 도우미 연결 서버의 오류가 전체 확장 로드를 중단시키는 코드를 확인했습니다. 해당 서버를 사용할 수 없으면 원인과 복구 방법을 표시하고 일반 HTTP 점검·매핑은 초기화하도록 수정하겠다고 설명했습니다. 클라우드에 설치한 JDK와 사용자 PC에서 실행 중인 Burp의 Java는 별개임을 안내했습니다.

## 06. 도우미 재현·수정 안내 · 요약

`jdk.httpserver`가 없는 JVM에서 기존 1.4.2의 동일 오류를 재현했습니다. 이전 배포 파일을 보존하는 1.4.3을 준비하며, 모듈 누락·클래스 로더 접근 거부·정상 환경을 각각 검사한다고 안내했습니다. 브라우저 도우미·SPA 연결은 해당 모듈 접근 문제가 해소되어야 사용할 수 있으며, 사용자 PC의 실제 Burp GUI 로드 결과와 합성 API 검증을 구분합니다.

## 07. 도우미 추가 검토와 최종 검증 안내 · 요약

일부 HTTP 서버 클래스만 접근을 차단한 경우 초기화 중 서버 자원이 남는 문제를 재현하고 정리 처리를 추가했습니다. 최종 오류·자원 정리 회귀 119개와 기존 기능 집중 검사 116개를 통과했습니다. 이어 최종 JAR의 전체 검사 5,689개, 실제 Katana loopback 검사 102개, 합성 Swing 화면 128개가 통과했다고 안내했습니다. 집중 검사는 전체 회귀에도 포함되므로 고유 검사 합계에 중복으로 더하지 않습니다. 최초 1.4.3 후보의 중단한 전체 검사와 최종 이전 후보의 UI·Katana 결과는 최종 통과 결과와 구분했습니다.

최종 JAR와 독립 소스 ZIP을 준비하며 사용자 PC의 실제 Burp Community 2026.9.2 GUI 로드는 아직 확인하지 못했다고 명시했습니다. GitHub API는 현재 환경에서 접근을 거부해 PR 생성이 차단됐으며, 기존 Git 프록시를 통한 저장소 읽기는 정상임을 확인했습니다.
