# Workbench 확장 기능의 실사용 중심 최적화 및 사용성 개선

## 1. 작업 목표

Workbench의 확장 기능을 지정된 테스트 환경에서 실제로 사용하면서,
총 5회의 테스트·개선·재검증 사이클을 진행해라.

이번 작업의 핵심은 신규 기능을 많이 추가하는 것이 아니다.

현재 기능의 정확성과 안정성을 유지하면서 다음을 개선하는 것이 목표다.

- 사용자가 같은 작업을 더 적은 조작으로 완료할 수 있게 한다.
- 불필요하게 복잡한 설정과 사용 절차를 줄인다.
- 자주 사용하는 기능과 가끔 사용하는 관리 기능을 구분한다.
- 확장 기능마다 다른 사용 방식과 화면 구성을 일관되게 정리한다.
- 처리 속도, 메모리 사용, 화면 반응성, 오류 복구를 개선한다.

단순히 버튼을 줄이거나 화면을 예쁘게 바꾸는 것으로 끝내지 마라.
실제 작업 흐름이 이전보다 편리해졌는지 검증해라.

## 도우미 · 초기 안내 요약

각 회차에서 실제 작업의 현재 동작을 재현하고, 좁은 범위를 수정한 뒤 같은 작업을 재수행하겠다고 안내했다. 저장소와 실행 환경을 확인하는 cloud-environment-runtime 스킬 사용을 알렸다. 실제 Burp Suite가 설치되어 있지 않아 운영 Swing·HTTP 하네스 검증과 native Burp GUI 검증을 구분하겠다고 설명했다.

## 도우미 · 환경 질문 원문

이번 작업의 ‘지정된 테스트 환경’은 어디인가요? 현재 환경에는 실제 Burp Suite가 설치돼 있지 않습니다. 별도 대상이 없다면 저장소의 격리된 로컬 실습 서버와 운영 Swing·HTTP 하네스를 기준으로 진행하겠습니다.

## 사용자 · 답변 원문

저장소의 로컬 실습 환경 사용

## 도우미 · 계획·1~3회차 진행 안내 요약

로컬 환경을 기준으로 상세 읽기, 대상·계정 변경, 대량 결과 갱신, URL 후보 가져오기, 대시보드 결과 이동의 5회 비교 항목을 정했다. 조작·원본 연결·인증·처리 시간·할당량을 함께 확인하고, 기존 상단 도구와 별도 관리 메뉴 구조를 유지한다.

별도 메모리 H2와 홈을 사용하는 원본 LOOP 3.10.0 서버를 준비했다. 사전 HTTP 확인 13개와 기존 1.4.0의 운영 확장·통합 점검·대시보드·원본·Repeater 준비·증거·보고서·종료 흐름 25개를 통과했다. 동일 하네스를 개선판에 재사용하며 실제 Burp GUI나 OS 클릭 검증으로 표현하지 않는다.

1회차는 같은 결과 갱신 5번에서 상세 텍스트 재선택이 5→0회로 줄었다. 2회차는 대상 변경 후 계정 선택·시작이 6→4회 조작으로 줄고 실패 후 새로고침 과정이 없어졌다. 잘못된 URL·조회 실패 뒤 정상 입력의 복구와 서로 다른 로컬 대상의 인증정보 분리를 확인했다. 3회차는 합성 2,000개 결과와 2,000개 경로의 같은 내용 갱신에서 EDT 중앙값 약25→2.5ms, 모델 이벤트6,009→0을 기록했다. 정렬·열 너비·선택 원본을 보존하며 합성 부하·스레드 할당량과 실제 Burp 응답 시간·전체 메모리를 구분했다.

## 도우미 · 사전 조사 4~5개 사례 안내 요약

URL 1,000건 가져오기의 EDT 중앙값 약429→75ms·할당량 약144→56MB와 URL·출처·원본 유지, 작은 화면의 대시보드 6개 추가 스크롤 사례가 클릭 한 번의 목록·상세 표시로 바뀐 결과를 안내했다. 이를 당시 4~5회차 완료로 표현했지만 아래 사용자의 정정에 따라 **실제 5라운드 완료로 인정하지 않는다**. 기존 측정과 수정은 사전 조사로 보존한다.

## 도우미 · 정정된 5라운드 완료 안내 요약

사용자의 정정에 따라 기준 1.4.0부터 수정 하나씩을 적용하면서 전체 8개 도구의 실사용 흐름을 매 라운드 전후 새로 실행했다. 5라운드·10개 독립 JVM/프로필 실행에서 각각 115개 항목 통과·실패 0, 8개 도구 PASS를 확인했다. 이전 after 결과를 다음 before로 재사용하지 않았다. 사전 준비한 개선 패치를 단계별로 적용했다.

새로 측정한 결과는 상세 재선택5→0회, 대상 변경 조작6→4회, 같은 대량 결과 갱신의 EDT 중앙값25.21→2.90ms·모델 이벤트6,009→0, URL1,000건 가져오기316.07→111.96ms·필터1,000→1, 대시보드12조건 관측 중 추가 스크롤6→0회다. 사람의 작업 시간·전체 힙·실제 Burp GUI 성능과 구분한다. 독립 검토에서 실행·소스 체인과 최종 JAR 해시 일치, blocker 없음을 확인했다.

최종 패키지·전체 회귀 검사를 마무리한 뒤 PR 검증을 거쳐 main에 반영하겠다고 안내했다. 소유한 로컬 LOOP 서버를 종료하고 포트가 닫혔음을 확인했다.

## 도우미 · 최종 로컬 배포 검증 안내 요약

전체 회귀5,489개(143그룹5,179+payload HTTP136+Mapper Java145+helper Node29)가 모두 통과했다. 화면128개·컨트롤2,700개·시나리오568개 검사도 실패가 없다. 새 Simple1.4.1 JAR·소스ZIP·helperZIP의 CRC·체크섬·전체 소스 지문 검증을 통과했으며 소스ZIP을 별도 폴더에 풀어 빌드한 JAR가 최종 라운드 제품과 바이트 동일함을 확인했다. 검증 결과와 원본 대비 증거를 보존하고 PR 자동 검증 통과 후 main에 반영할 예정이다. 실제 Burp GUI·브라우저 DOM·Windows DPI/IME는 미실행이다.
