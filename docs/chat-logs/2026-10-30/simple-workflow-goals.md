# Workbench 실사용 목표 후속 기록

기준:2026-10-30 Asia/Seoul. 사용자에게보인요청·답변과요약만보존한다.

## 사용자 · 최신요청 원문

현재 기능의 정확성과 안정성을 유지하면서 다음을 개선하는 것이 목표다.

- 사용자가 같은 작업을 더 적은 조작으로 완료할 수 있게 한다.
- 불필요하게 복잡한 설정과 사용 절차를 줄인다.
- 자주 사용하는 기능과 가끔 사용하는 관리 기능을 구분한다.
- 처리 속도, 메모리 사용, 화면 반응성, 오류 복구를 개선한다.

단순히 버튼을 줄이거나 화면을 예쁘게 바꾸는 것으로 끝내지 마라. 실제 작업 흐름이 이전보다 편리해졌는지 검증해라.

## 도우미 · 진행안내 요약

1.4.1에서확인된읽기·갱신·일부조작개선과, 기존구조유지에그친설정절차·일상/관리구분을 나눠설명했다. 최신기준에맞춰불편을점검하고 부족한부분을실제수정하겠다고알렸다. 같은작업의전후조작과 원본·계정·SCOPE·요청한도유지를함께검증한다.

새격리LOOP서버를준비하고배포1.4.1의전체흐름을새로실행했다. 계정비교에필요한원본이검색목록에나타나지않는실패1건과그로인한전체완료실패를발견했다. 실패기록을보존하고제품오류와하네스대기문제를먼저분리하겠다고안내했다.

## 도우미 · 작업 흐름 재현과 수정 안내 요약

기존판에서 서버·경로의 대상과 계정을 바꾸어 GET 확인을 하려면 설정 창 두 곳을 거쳐 최소 6번 조작해야 했고, 다른 관측이 들어오면 읽던 요청·응답의 선택 영역이 사라지는 점을 재현했다. URL 대상 준비 오류가 화면에 보이지 않는 점도 확인했다. 기존 대상·계정 선택기를 기본 작업 화면에 두고, 고급 실행 조건·요청 한도와 저장 관리는 기존 설정·더보기에서 유지하는 방향으로 수정한다고 안내했다.

검색 실패를 조사하며 검색 조건을 준비하는 중에도 완료 상태로 읽힐 수 있는 경합을 별도로 재현했다. 원본 유실 증거는 없고, 첫 전체 실행 실패와 같은 원인인지 확정하지 않았음을 구분했다. 준비·검색·화면 반영 전에는 완료로 판단하지 않게 처리하고, 동결된 이전 검증 하네스와 실패 기록은 보존했다.

대상 준비에서는 Enter와 버튼이 같은 준비 동작을 수행하고, 오류를 같은 입력 창에서 바로 확인·교정하도록 했다. 준비만으로 수집·GET을 자동 실행하지 않으며, 적용하지 않은 입력이 현재 대상과 원본을 바꾸지 않도록 유지했다. 변경한 흐름과 주변 기능을 집중 회귀 검사로 확인한다고 안내했다.

## 도우미 · 최종 JAR의 전후 비교와 안정성 확인 요약

최종 1.4.2 운영 JAR에서 같은 고정 프로브로 비교한 결과, 대상·계정 선택 후 경로 확인은 필수 조작 6→4개, 별도 설정 창 2→0개였다. 같은/다른 대상의 관측 메타데이터를 재적용하는 동안 요청·응답 선택과 정확한 원본을 유지했고, 불필요한 표·문서 이벤트와 자동 HTTP는 0이었다. 시간·스레드 할당량은 로컬 진단값이며 사람의 작업 시간이나 잔존 힙·RSS로 해석하지 않는다.

잘못된 대상과 8탭 상한 오류를 같은 창에서 확인하고 교정·재시도했다. Enter 후 버튼을 추가로 누르던 준비 동작은 2→1개로 줄었고, 종료 뒤 남아 있던 버튼·직접 열기 동작이 탭을 다시 만들지 않았다. 검색 준비 구간 하나에서 완료 상태를 1,000번 읽는 결정적 재현은 잘못된 완료 1,000→0회였다. 이를 독립적인 1,000개 시험으로 세지 않는다.

같은 최종 JAR로 전체 8개 도구를 새 JVM·임시 프로필에서 5번 다시 수행했고 매번 115개 통과·실패 0, 엔진 GET42회와 별도 로그인 준비 POST2회를 확인했다. 이 반복은 안정성 확인이며 새 개선 전후 5라운드나 575개 고유 검사로 합산하지 않는다. 최초 기준 실행의 107개 통과·2개 실패 기록은 별도로 보존했다.

## 도우미 · 화면·운영 연동 및 릴리스 진행 요약

밝은·어두운 테마와 두 창 크기의 128개 화면, 2,708개 컨트롤, 568개 시나리오에서 화면 검사 실패가 없었고 실제 Katana 프로세스 검사 102개도 통과했다. 이 결과는 운영 Swing·어댑터 및 격리 loopback 범위이며 실제 Burp GUI·OS 클릭·브라우저 DOM·Windows DPI/IME 검증으로 표현하지 않는다.

전체 릴리스 회귀와 새 배포 묶음 생성은 진행 중이다. 완료 뒤 실제 검사 수와 배포 체크섬을 기록하고, 소스 ZIP 독립 재빌드와 원격 CI·main 병합 상태는 각각 완료된 근거로 구분해 안내한다.


## 도우미 · 전체 릴리스 검사와 새 배포 묶음 완료 요약

실제 전체 릴리스 검사가 완료됐다. strict Java17에서 146개 회귀 그룹5,260개, payload HTTP136개, Mapper Java145개, helper Node29개로 총5,570개가 통과했다. 일부 집중 검사 결과나 이전1.4.1 요약을 이번 전체 결과로 사용하지 않았고, 실제1.4.2·전체 프로필·실패 그룹 없음과 새 배포 디렉터리 생성을 확인했다.

새 JAR·독립 소스 ZIP·helper ZIP의 배포 묶음이 CRC·소스 지문·체크섬 검증을 거쳐 생성됐다. 최종 JAR는 전후 프로브·전체 흐름 재확인·화면·Katana 검사에 사용한 제품과 같다. 독립 소스 ZIP 재빌드와 원격 CI·main 병합은 각각 완료된 근거를 확인한 뒤 별도로 안내한다.

## 도우미 · 독립 소스 재빌드 안내 요약

배포 소스ZIP을별도폴더에풀어strictJava17로빌드한JAR가최종라운드·전후프로브·화면·Katana에사용한제품과바이트단위로일치했다. CRC·전체소스지문·체크섬검증도통과했다. 소스·설치파일·목표별전후근거를PR에올려원격검증통과후main에반영할예정이다. 실제BurpGUI·OS클릭·전체힙/RSS는검증범위와구분한다.
