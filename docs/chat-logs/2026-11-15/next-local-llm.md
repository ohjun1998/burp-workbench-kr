## 도우미 답변 · 요약

- 처음 Simple을 확인했다가 사용자의 정정에 따라 원래 Next0.53.4의 실제 소스로 확인 기준을 변경했다.
- 우선순위1은 응답 보안 검토와 계정 비교 해설, 우선순위2는 기능별 업무 로직과 JS/API 분석, 우선순위3은 근거 기반 보고서 초안으로 제안했다.
- Halogen OpenAI 호환 API에 직접 연결하고, 필요한 패킷과 기대 정책만 묶어 보내는 반자동 흐름을 설명했다. 제안과 기존 판정은 구분하고 대상 검증은 Repeater에서 사람이 수행하도록 안내했다.
- 사용자의 코드 적용 요청에 따라 Next 전용 작업 브랜치에서0.54.0으로 구현했다. 패킷 분류는 다중 기능과 미분류를 지원하고 원본 ID를 유지하는 방식으로 진행한다고 알렸다.
- 기능별 분류는 클라우드 LLM에도 맡기기 좋은 일반 데이터 분석이지만 서비스 정책과 맥락에 따라 처리될 수 있어 검열 여부를 보장할 수 없다고 답했다. 인증값/개인정보를 가린 분류와 로컬 상세 분석의 분담이 가능하며, 현재는 승인된 로컬 연결 구현을 이어간다고 안내했다.
- 후속 요청에 따라 기능 분류/보고서는 ChatGPT 구독(Codex CLI), 응답/인가/업무 로직/JS 검토는 로컬 기본 경로로 배정했다. 공식 문서에서 구독 로그인과 비대화형 호출을 확인했고, M5에서 최초 codex login이 필요하다고 안내했다. 검열 여부 보장이나 거절 후 자동 재전송은 하지 않는다고 설명했다.
- 후속 요청에 따라 자동 요청 실행 전 필수 확인을 추가했다. 대상·작업·요청 계획을 보여주고 기본 취소로 구성하며, 승인 거절 시 기준/대조 요청도 보내지 않는다고 안내했다.
- 기능별 분류 동작은 선택 패킷의 메서드/경로/필드/응답/Referer와 사용자가 적은 업무 설명을 읽어 기능을 추론하고, 기능 이름·원본ID·근거·불확실성을 JSON으로 반환한다고 설명했다. 공유API의 다중 분류와 미분류를 허용하며 실제 클릭을 직접 관측하거나 의미적 정확성을 보장하는 기능은 아니라고 안내했다.
- 첫 빌드 통과 후 격리 가상 LLM 서버와 기존 Next 전체 회귀 검사를 진행한다고 알렸다.

- 브라우저 조작 도구와 패킷 수집을 연결하면 클릭·화면 맥락을 이용한 탐색 중 분류가 가능하다고 설명했다. 백그라운드 요청과 상태 변경을 구분하고, 현재0.54.0 선택 패킷 분류와 별도 브라우저 에이전트 구현 범위를 구분했다.

- 실제 기존 Mapper의 Chromium 보조 확장은 클릭/제출 맥락과 요청 메타데이터를 Burp 원본에 연결하는 기반이 있음을 확인했다. 현재 AI는 그 이벤트/그룹을 자동으로 받거나 브라우저를 제어하지 않는다고 안내했다.

- 후속 질문에 브라우저 자동 조작 없이 수집 트래픽을 분류할 수 있다고 설명했다. 메서드·정규화 경로·파라미터·응답 구조로1차 묶고 대표 패킷만 LLM에 보내는 고도화를 제안했으며, 현재 선택 패킷 분류와 구분했다. 분류 자체의 대상 추가 요청은0회다.

## 구현 범위 · 작업 기록 요약

- Next 공통 AI 화면과 로컬 API 연결·설정, 원본과 가림 입력 준비, JSON/출처 검증, 단일 worker·취소·캐시·프로젝트 분리.
- 트래픽/Burp 메뉴, 응답·계정 비교·JS 분석·증거 보고서 진입점.
