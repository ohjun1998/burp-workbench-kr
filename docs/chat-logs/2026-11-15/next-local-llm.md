# Next 0.54.0 로컬 LLM 연동 작업

한국 시간 2026-11-15. 이 작업과 관련해 제공된 사용자 메시지와 사용자에게 전달한 설명만 기록합니다. 아래 원문/요약 구분을 따르며 자격증명·비공개 추론·원시 도구 출력은 포함하지 않습니다.

## 사용자 원문

> workbench Next 확장자에 로컬 LLM을 연동시켜서 효율적으로 버그바운티 할 수 있게 고도화 해줄래?

> 0.53.4 버전 이후로 업데이트 해줘

> github에 위치한 것, 여기 로컬로 복사하고 실행 및 테스트 할 수 있도록 설정하고, 완성된 파일은 github에 업로드 해줘

## 전달한 설명 요약

- main에서 확인한 Next 0.53.4를 출발점으로 선택한 요청·응답의 가설·재현 절차와 기존 SCOPE·Repeater·증거 정리를 연결하기로 했다.
- 사용자 확인에 따라 신규 기능 버전은 0.54.0으로 올리고 기존 배포본은 보존한다고 설명했다.
- 기본 모델 서버는 Halogen `/v1` 로컬 8731, 모델 ID는 `halogen-qwen3.8-flash-next`로 준비했다.
- 미리보기 확인·편집 후 수동 분석, 동시 분석 1개, 미검증 가설 표시, 자동 대상 요청 없음과 가용성 조건을 설명했다.
- `~/workbench-next-local-llm`에 소스를 준비했다. 직접 Git 네트워크 접속은 차단되어 GitHub 연결 도구로 소스를 가져왔다. Burp 동봉 JDK 26을 발견해 로컬 컴파일에 사용했다.
- 관리 환경은 socket 생성/loopback bind도 차단한다. 따라서 로컬에서는 Java 컴파일 및 네트워크 없는 검사 34개만 실행했으며, 전체 빌드·HTTP 검사는 CI로 추가 검증하기로 했다. 실제 Halogen·native Burp 검증을 했다고 주장하지 않았다.

## 현재 제출 범위

첫 CI에서 새 클라이언트/Swing/실제 loopback 44개 검사는 통과했습니다. 전체 빌드는 기존 가림 수집기의 SecretSet 타입과 새 연결부의 Set 타입 불일치로 실패해 연결부를 고쳤습니다. 실패 기록을 성공 검증으로 합산하지 않습니다.

후속 수정은 원본 읽기 전에 4개 선택 제한을 검사하고, 별도 분석 창에 Burp 테마를 적용하며, 응답을 읽는 동안에도 전체 시간 예산을 점검합니다. 최종 소스로 CI를 다시 실행합니다.

새 로컬 LLM 클라이언트·Swing 화면, 두 메뉴 진입점, 프로젝트/종료 수명 처리, 기존 증거 가림·원본 연결, 회귀 검사, 로컬 실행 스크립트, 사용 안내, 작업 브랜치에만 검증 산출물을 추가하는 CI. 전체 검증 결과와 잔여 제한은 PR 및 이후 작업 기록에 추가한다. main 자동 병합은 포함하지 않는다.

로컬 복사를 마치기 위해 검증 산출물의 임시 분할 전송본을 준비합니다. 연결 도구의 대용량 바이너리 읽기 제한에 대응하며, 원본과 조각의 SHA-256을 확인해 합칩니다. 가져온 뒤 작업 브랜치의 전송 조각은 제거하고 정상 JAR·소스 ZIP·체크섬만 유지합니다.

소스 ZIP에서도 같은 로컬 실행 명령과 새 집중 검사를 사용할 수 있도록 run-local.sh 및 tools/check_local_llm.py를 패키징 입력에 포함합니다. 설치 JAR의 기능 코드는 이 패키징 변경으로 바뀌지 않습니다.

전체 회귀 중 UiCleanupTest가 이전 메뉴 목록과의 완전 일치를 요구해 새 LLM 항목을 실패로 처리했습니다. 기존 항목·순서 검사는 유지하면서 승인된 새 항목을 기대 목록에 추가했습니다. 실제 동작 실패와 구분하며 전체 검사를 재실행합니다.

최종 작업 결과 요약: CI 전체4,825개와 Mapper Java134/Node15가 통과했고 JAR·소스 ZIP·체크섬을 작업 브랜치에 업로드했습니다. 로컬로 가져온 소스388개 지문과 파일 체크섬이 일치하며 JDK26 전체 빌드도 통과했습니다. 로컬 LLM34·증거 가림7·패키징5 검사 및 800×600 합성 패널 렌더링을 수행했습니다. 사용자에게 이 결과를 알리고 임시 분할 전송본을 정리했습니다. 실제 Halogen/native Burp와 main 병합은 미수행입니다. 일반 CI의 이전 실패는 배포 전 커밋에 manifest가 없어서 발생했고, 현재 작업 브랜치에는 검증 산출물이 있습니다. 상세 기록은 VERIFICATION_0.54.0_LOCAL_LLM.json에 보존합니다.

## 남은 검증 후속 작업

사용자 원문: "남은 작업 계속 진행해줘"

설명 및 수행 결과 요약: 최종 소스의 일반 CI, 배포 후보 재검증, Windows/Linux 내구성 검사가 모두 통과했습니다. 이전 manifest 누락으로 실패했던 인증 조합과 50업무 비교, 전체/집중 화면 배치 및 패키징 검증까지 완료했습니다. Windows 반복 저장소·창 조작과 양 OS 180초 수집, Linux 실제 ENOSPC 복구도 통과했습니다. 반복 실행 수를 고유 검사 수에 더하지 않습니다.

실제 Halogen 호출을 확인하기 위해 배포 JAR를 직접 호출하는 tools/check_live_llm.py와 안내를 추가했습니다. 컴파일은 통과했으나 관리 환경에서는 SocketException: Operation not permitted가 재현됐습니다. 사용자 터미널에서 한 번 실행해 결과 파일을 남겨 달라고 요청했습니다. 합성 자료로 모델에 1회 요청하고 실제 대상 사이트에는 요청하지 않는다고 설명했습니다. 아직 사용자 측 결과가 없어 실제 모델·Burp GUI는 미확인으로 유지합니다. 0.54.0 배포 파일과 소스 지문은 변경하지 않았습니다.

## 사용자 터미널 실모델 확인

사용자 원문: "실행 했어"

전달한 설명 요약: 저장된 결과를 확인해 배포 JAR 클라이언트의 Halogen 연결 성공을 알렸습니다. 한국어 답변 1,775자, 약 16.7초, 정상 종료(stop)였으며 검증 문서와 PR에 반영한다고 설명했습니다. 합성 입력으로 모델 호출 1회, 대상 사이트 요청 0회이고 JAR 체크섬도 일치했습니다. 실제 Burp GUI 확인은 아직 남아 있습니다.
