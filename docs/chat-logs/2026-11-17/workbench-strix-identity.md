# Workbench Strix 별도 제품명 분리

- 날짜: 2026-11-17 (Asia/Seoul)
- 작업: workbench-strix-identity

이 작업에서 확인 가능한 사용자 요청과 사용자에게 표시한 응답을 기록합니다. 과거 대화 전체나 내부 추론·도구의 원본 출력은 포함하지 않습니다. 요약한 항목은 별도로 표시합니다.

## 01. 사용자 · 원문

Strix 진단 에이전트 연동한 거 있지 않아?

## 02. 도우미 · 요약

다른 원격 브랜치 account-a/simple-strix-local에서 Simple 1.4.13 Strix 연동 후보와 사용 가이드를 확인했다. 기존 대화의 A 그룹형 Simple1.4.22와 별개 브랜치임을 안내했다.

## 03. 사용자 · 원문

Strix 진단 에이전트를 연동한건 다른 이름으로 수정해서 구분 지어줄래?

## 04. 도우미 · 원문

Strix 연동판은 **Workbench Strix**라는 이름으로 구분하겠습니다. 실행 화면의 이름, 설치 파일명, 문서와 사용 가이드를 함께 맞추고, 기존 Simple 배포 파일은 보존하겠습니다.

## 05. 도우미 · 원문

이름과 버전이 다시 섞이지 않도록 **Workbench Strix 1.0.0**으로 별도 배포하겠습니다. Strix 연동 기능은 유지하고, 기존 연동판의 설정과 진단 기록을 이어 쓸 수 있도록 저장 위치는 유지하겠습니다.

## 06. 도우미 · 원문

Burp 확장 목록·탭·우클릭 메뉴·창 제목에 새 이름을 연결했고, 설치 파일도 `burp-workbench-strix-1.0.0.jar`로 분리했습니다. 현재 전체 회귀 검사와 새 JAR의 Strix 화면 검사를 진행 중입니다.

## 07. 도우미 · 원문

Strix 진단 화면 28개와 기존 작업·통합 점검 화면 152개의 배치 검사를 통과했습니다. 새 그림 가이드도 준비했으며, 배포 파일과 가이드에 포함된 JAR가 같은 파일인지 확인하고 있습니다.

## 08. 도우미 · 요약

전체 검사 중 StrixClient의 중지 확인이 시간 초과했다. 클라우드 PID1의 좀비 자식 프로세스를 확인했고, 제품 코드 변경 없이 테스트용 subreaper에서 동일한 63개 검사를 통과했다. 해당 환경에서 최종 전체 검사를 다시 실행했다.

## 09. 도우미 · 요약

두 번째 전체 검사에서는 StrixClient63개가 통과했으나 닫힌 loopback 포트의 연결 거부 assertion이 실패했다. 운영 프록시는 변경하지 않고 이전 브랜치의 소스/목적 포트 구분 테스트 보정을 적용했다. 해당49개 집중 검사를 통과했고 최종 전체 검사를 다시 실행했다.

## 10. 도우미 · 원문

전체 자동 검사 **7,163개**와 화면 배치 검사 **180개**를 모두 통과했습니다. **Workbench Strix 1.0.0** 설치 파일·소스·사용 가이드의 체크섬 확인도 끝났으며, 지금 작업 브랜치에 업로드하겠습니다.

## 11. 도우미 · 요약

Workbench Strix1.0.0의 이름·탭·메뉴·창·설치 JAR·소스 ZIP·그림 가이드를 작업 브랜치에 게시했다. 자동7163개와 UI180개 및 가이드9그룹을 통과했다. 독립 소스 빌드의 JAR가 배포와 일치했고 공개 JAR/설치가이드ZIP의 전체 다운로드HTTP200·SHA·CRC를 확인했다. 기존 Simple과 데이터 저장 호환성을 유지했다. GitHub REST API Forbidden으로 PR은 생성하지 않았으며 main 병합도 하지 않았다.
