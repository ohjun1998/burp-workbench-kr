보류는 TN/FN과 겹치는 화면 판정입니다. 다른 집계에 더하지 않으며, TN을 안전 확정으로 읽지 않습니다. 수치는 같은 실습 서버의 공통 구현을 7개 인증 방식으로 반복한 결과이고 운영 서비스의 탐지 확률이 아닙니다.

## 판정별 사유

- **정탐 392건**: 권한표에서 금지한 계정에게 비공개 자료가 반환된 154건과, 실제 저장 버전·처리 횟수 증가 및 실행 계정이 관측된 쓰기 238건을 경고했습니다. HTTP 403 뒤 실제로 저장된 50번 기능의 7건도 유지했습니다.
- **이전 오탐 21건 해소**: 18번 개인정보 CSV의 관리자·Bob 14건과 42번 파일 다운로드의 Alice 7건은 HTTP 200이지만 오류 JSON만 반환했습니다. 기준 응답의 형식과 관계없이 설정된 오류 경로·값을 검사해 차단 근거를 인식합니다. 오류와 자료가 함께 있으면 보류합니다.
- **설정 후 미탐 0건**: 이번 데이터에서 놓친 사례가 없어 개별 사유를 만들지 않습니다. 설정 전에는 실제 위반 385건이 보류되었고 403 뒤 실제 쓰기 7건이 차단으로 표시되어 엄격한 집계의 미탐 392건입니다.
- **보류 91건**: 쓰기 후 지정 항목이 미변경이지만 404/410만으로 정상 차단을 확정할 수 없는 84건(404 63건·410 21건), 이동 위치와 로그인/업무 결과를 확인해야 하는 302 응답 7건입니다. 실제 위반은 없었지만 확장의 관측 범위에 맞춰 보류를 유지합니다.

## 검증과 근거

전체 회귀·HTTP 2,890개(신규 응답·쓰기 사유 39개 포함), 패키징 6개가 통과했습니다. 실제 Burp Community 2026.3.3/Java 21에 배포 JAR를 불러와 Montoya HTTP로 1,400개 비교 기록·기준 제외 4,200개 계정 대조를 실행했습니다. 별도 HTTP 2,800개·잘못된 인증 조합 33개·신원 검사 21개를 확인했습니다. 누락·중복·권한표·자료 표식·쓰기 전후 증거를 독립 재집계했으며 이전과 4,200개 대조의 메서드·기대 권한·응답 코드·정답이 일치합니다.

임시 Burp 프로필, loopback 서버와 H2 Oracle 호환 모드입니다. 헤드리스 Burp 시작의 ComponentUI 경고 2건이 있었고 실제 HTTP·판정·정상 종료를 확인했습니다. 이번 실행에서 실제 Burp GUI 클릭·Windows DPI/한글 입력·외부 OAuth/OIDC/SAML·실제 Oracle/Nginx 배포를 다시 검증하지 않았습니다. 과거 검증은 구분합니다.
