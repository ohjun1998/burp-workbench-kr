# 0.52.1 결정적 회귀 재현 근거

2026-10-24에 Linux/JDK 17의 격리된 클래스·테스트 경로에서 실행한 담당 에이전트의 조사 근거입니다. 기존 구현에 새 회귀를 적용해 실패를 확인한 뒤, 수정 구현에서 같은 조건을 통과했습니다. 아래 파일은 해당 실행의 관련 PASS·실패·집계 줄을 그대로 옮긴 발췌본이며, 생략된 일반 PASS와 공통 JVM 스택은 파일 상단에 표시했습니다.

| 회귀 | 재현 조건과 기존 실패 | 수정 후 격리 검사 | 근거 |
|---|---|---|---|
| 검색 예약 완료 판정 | EDT를 유지한 채 실제 비반복 타이머가 만료되도록 합니다. action이 아직 실행되지 않았는데 `idle()`이 완료로 판단해 그룹 펼치기 검사가 실패합니다. | `TrafficIncrementalSearchTest` **47개 통과**. 예약 경합 14개를 추가했고 기존 결과·평가 건수 검사를 유지했습니다. | [실패](search-before.txt) · [통과](search-after.txt) |
| 관찰 초기화와 동시 입력 수락 | 작업 실행을 유지한 채 취소 대기열의 스냅샷 직후 별도 producer가 입력을 추가합니다. 기존 직접 대기열 삭제가 그 작업만 제거하여 입력 보유 예약 반환 검사가 실패합니다. | `ResponseBudgetTest` **30개 통과**. 초기화 중 입력의 예약 반환, 이전 관찰 정리와 이후 관찰·원본 보존을 확인합니다. | [실패](response-before.txt) · [통과](response-after.txt) |

검색 수정은 타이머의 `isRunning()` 대신 명시적인 예약 상태를 추적합니다. 그룹 펼치기와 중요 표시 결과가 실제로 게시되기 전까지 완료로 판단하지 않으며, 취소·초기화 후 오래된 타이머가 결과를 게시하지 않는지도 검사합니다. 100,000개 기존 원본에 25개를 추가했을 때 정확히 25개만 평가하고, 100,025개를 독립적으로 전체 평가한 결과와 일치하는 조건도 유지했습니다. 기록된 실행 시간은 이 격리 실행의 관측값이며 다른 환경의 성능 보장이 아닙니다.

응답 분석 수정은 대기 작업 제거와 예약 반환을 같은 취소 경로에서 처리합니다. 제거에 성공한 예약 작업만 해제하고, 실행 중 작업은 종료 경로에서 해제합니다. 예약 없는 일반 작업도 초기화 대상에 포함하며 직접 대기열 전체 삭제를 없앴습니다. 반복 정리·실행 예외·언로드·실행기 거부 시 반환 검사도 함께 통과했습니다.

컴파일은 `java com.sun.tools.javac.Main --release 17`, 실행은 헤드리스 Swing 및 API 어댑터를 사용했습니다. 검색 조사는 `tmp/windows-search-stability/`, 응답 조사는 별도 `/tmp/response-budget-0521-6e3yfpns/` 경로를 사용했습니다. 이 조사를 위해 공유 `build/`·`dist/`와 기존 0.52.0 배포물을 변경하지 않았습니다.

**위 47개·30개는 조사 단계의 격리 실행 수치입니다. 최종 0.52.1 release 빌드·검사 집계와 합산하지 않습니다.** 최종 배포 검사는 주 담당자가 별도로 수행하고 기록합니다. 이 로그는 원격 Windows 실행이나 실제 Burp GUI 검사 기록이 아니며, 알려진 Windows 실패와 같은 예약 경합을 로컬에서 결정적으로 재현한 근거입니다. 검색 결과 계산 자체가 영구적으로 잘못된다는 결론은 내리지 않았습니다.
