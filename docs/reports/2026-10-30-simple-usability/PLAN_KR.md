# Simple 실사용 흐름 개선 · 5회 검증 계획

사용자가 회차의 뜻을 **매회 전체 기능의 실사용 흐름 검증 → 개선 → 전체 흐름 재검증**으로 명확히 했다. 앞서 작업별로 수행한 다섯 전후 비교는 **사전 조사 사례**이며 완료한 5라운드로 세지 않는다. 아래 개선을 기준 1.4.0의 별도 격리 소스에 하나씩 적용하며 전체 라운드를 새로 수행한다. 원래 작업 디렉터리의 수정은 보존한다.

각 라운드는 동일한 고정 공통 하네스로 **8개 도구의 실제 기능 수행과 원본·계정·증거 연결을 수정 전후 모두** 확인한다. 라운드별 문제의 전후 지표도 따로 실행한다. 총10회의 전체 흐름은 각각 새 JVM·새 임시 프로필·독립 로그를 사용하며, 이전 라운드의 after 결과를 다음 before 실행으로 재사용하지 않는다. 단순 화면 열기나 같은 회귀 명령 반복만으로 전체 기능 검증·개선 완료를 표시하지 않는다.

사용자는 2026-10-30(Asia/Seoul) 별도 외부 대상 대신 **저장소의 로컬 실습 환경 사용**을 선택했다. 기준 소스는 main `81b48defb81db7c656e913a8ebd6848e30621cf1`의 Simple 1.4.0이다. 개선판은 1.4.1로 분리하고 이전 배포 파일과 Next 소스는 보존한다.

매 회차를 **전체 흐름과 현재 문제 재현 → 격리 소스에 해당 수정 적용·새 JAR 빌드 → 같은 전체 흐름과 문제 재수행 및 정확성·복구 확인** 순서로 진행한다. 순서가 끝나기 전에 다음 회차의 격리 제품 수정을 적용하지 않는다. 독립적인 환경 준비·원인 조사만 병렬로 한다. 통과한 기존 검사를 5회 실행한 것으로 대체하지 않는다. 사전 조사의 수정안과 지표는 근거로 활용하되, 새 라운드의 실측 결과와 혼합하지 않는다.

| 회차 | 수행할 사용자 작업 | 비교 기준 |
|---|---|---|
| 1 | 결과가 갱신되는 동안 상세 근거를 읽고 복사 | 같은 원본·내용의 caret·선택 텍스트 유지, 다른 내용·실행의 올바른 교체 |
| 2 | 대상 URL을 직접 바꾸고 계정을 선택해 시작 | 실패 후 목록 새로고침·재시작 제거, 다른 대상의 인증정보 미전송 |
| 3 | 결과가 많은 실행에서 목록 정렬·선택·원본 확인 | EDT 시간·할당량·모델 이벤트, 동일 행·정렬·정확한 원본 유지 |
| 4 | 서버·경로의 URL 후보를 대량 가져오고 필터링 | 한 묶음의 필터 반복 계산 감소, URL·메서드·출처·정렬·상한 보존, 자동 전송 없음 |
| 5 | 대시보드 숫자에서 해당 결과와 원본으로 이동 | 숫자 클릭 후 목록 접근에 필요한 추가 스크롤 감소, 빈 조건 복구·기존 조건 유지 |

사용자 조작은 클릭·명시적 입력·스크롤 동작을 구분해 기록한다. 사람이 사용 시간을 측정한 자료로 표현하지 않는다. CPU·EDT 할당량은 동일 JVM 조건의 합성 부하를 사용하며 실제 네트워크 성능이나 전체 프로세스 메모리 절감률로 일반화하지 않는다.

격리된 loopback HTTP fixture로 회귀를 수행하고, 저장소 원본 LOOP Community 앱에서도 최종 운영 패널·Runner·결과 전달 흐름을 실행한다. API 어댑터·headless 운영 Swing 조작은 실제 Burp GUI 조작과 구분한다. 새 메뉴나 스캔 기능을 늘리지 않으며 기존 실행 조건·SCOPE·요청 예산·인증·원본·증거 계약을 보존한다. 자주 사용하는 진입점은 기존 상단에 유지하고 관리·설정은 기존 별도 메뉴/창을 사용한다.
