# Simple 후속 실사용 목표 검증

사용자의 최신 기준은 같은 작업의 조작 감소, 설정·절차 단순화, 일상 기능과 관리 기능 구분, 속도·메모리 할당·반응성·오류 복구 개선이다. 이전 Simple1.4.1의 전체 흐름5라운드와 배포 기록은 그대로 보존한다. 이번 후속에서는 기존 구조 유지에 그친 항목을 실제 작업으로 다시 점검하고 확인된 불편만 수정한다. 새 스캔 기능이나 별도HTML 대시보드를 추가하지 않는다.

기준 main은65ae9273d3b58d47ddf7e3b96d0e118875bb15b3, 기준제품은배포Simple1.4.1이다. 변경은account-a/simple-workflow-usability에서만 진행하며, 기존버전과Next원본을 보존하고 기능변경 배포 시1.4.2를 사용한다. 사용자가 선택한 원본LOOP3.10.0 격리로컬실습환경과 운영Swing·HTTP어댑터를 재사용한다.

1. 전체8개 도구의 새 기준 실행과 작업별 불편을 먼저 기록한다. 실패를통과로세거나 이전실행을재사용하지않는다.
2. 검색·원본전달 실패가 제품오류인지 검증하네스의 대기조건 문제인지 분리한다. 동결된 이전하네스와 실패기록은 바꾸지않는다.
3. 실제로 반복하는 대상·계정 선택, 결과읽기, 오류수정 흐름에서 필요한UI동작과 별도설정창 진입수를 측정한다. 선택·설정·조회만으로 요청을 보내지않는다.
4. 개선후 같은 작업에서 조작·불필요한재작업·EDT비용을 비교하고 원본ID·계정·SCOPE·요청한도·중지·증거 저장을 재확인한다.
5. 최종전체흐름과 적절한회귀·화면·배포지문검사를 통과한 결과만 PR로 전달한다. 실제BurpGUI·OS클릭·브라우저DOM·잔존힙/RSS와 어댑터·스레드할당량의 범위를 구분한다.

첫 새전체기준실행은107통과/2실패이며 계정비교에 쓸새원본의 검색목록가시성에서 실패했다. 이 실패를 보존하고 원인을조사한다. 기존1.4.1의115통과기록은과거실행근거로만 읽는다.
