# 로컬 은행 실제 웹 화면

VulnBank 고정 소스 `4bb7cd5f46921959f034455e5615782481966177`를 loopback에 실행하고, 새 Chromium 154 프로필에서 실제 로그인 폼으로 Alice 계정에 로그인해 캡처했습니다. 원본 앱의 HTML·CSS·응답을 바꾸거나 그림을 편집하지 않았습니다.

| 원본 PNG | 내용 |
|---|---|
| [로그인](01-login.png) | 원래 로그인 폼. 비밀번호는 입력 전이며 원래 password 필드입니다. |
| [Alice 계좌 · 라이트](02-dashboard-light.png) | 가짜 실습 계좌 `1791279111`, 당시 실제 표시 잔액 `$1000.0` |
| [이체 양식](03-transfer-form.png) | Bob 계좌 `3902391125`로 `1.00`을 입력한 **제출 전** 실제 화면 |
| [거래 내역](04-transactions.png) | 캡처 당시 실제 거래 0개와 앱의 빈 상태 표시 |
| [Alice 계좌 · 다크](05-dashboard-dark.png) | 은행 원래 테마 버튼으로 바꾼 화면 |

웹 준비·읽기 동작 6개를 통과했고 원본 PNG는 5장입니다. 이 캡처는 은행 프런트엔드 확인 자료이며 취약점 탐지 결과나 실제 Burp 브라우저 검증으로 계산하지 않습니다. 도구 실행 전 계좌 상태를 캡처했으므로 이후 진단 중 생성한 거래·잔액과 다를 수 있습니다.

브라우저는 앱의 교육 안내에서 실제 `Got it` 버튼을 눌러 닫았습니다. 이체·프로필 저장 등 상태를 바꾸는 동작은 수행하지 않았습니다. 토큰·실습 암호가 보이는 DOM 텍스트가 없는지 확인하고 실제 그림도 검토했습니다.

외부 요청은 모두 차단했습니다. Google Fonts CSS 요청 두 번이 차단되어 console error 두 개가 기록됐으며 로컬 HTTP 오류·로컬 리소스 전송 오류·page error는 각각 0입니다. 로컬 대체 글꼴로 표시된 실제 화면입니다. 브라우저 helper 확장은 이 캡처에 로드하지 않았습니다.

실행 시각·상태·응답 경로·이미지 크기·SHA-256은 [검증 JSON](verification.json)에 있습니다. 첫 실행은 원본 앱의 교육 안내가 메뉴 클릭을 가려 중단했으며, 실제 버튼을 처리하도록 준비 절차를 고친 후 새 디렉터리의 최종 실행을 통과했습니다. 중간 파일은 작업환경의 `browser-captures/run-001`에 보존하고 통과 수에 포함하지 않습니다.

재현 도구: `audit/bank-simple-1.4.21/capture_bank.mjs`. 로컬에서 준비한 private-state JSON과 새 출력 경로를 전달합니다. 인증 상태 JSON은 Git에 추가하지 않습니다.
