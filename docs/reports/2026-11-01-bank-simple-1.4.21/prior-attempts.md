# 최종 근거와 중간 준비 이력

최종 도구 값은 core003의 단일 완주, 별도 음수 이체 business001의 단일 완주를 사용합니다. 독립 대조는 truth002의10요청, 은행 브라우저는 마지막 성공 실행의6검사·5PNG입니다. 중간 요청을 최종 카운트에 더하지 않습니다. 개인 인증 원문·전체 실행 로그는 Git 밖에 보존했습니다.

- 초기 Java 어댑터는 Montoya 하위 인터페이스가 재선언한 Method를 기본 request/response proxy에 호출해 `IllegalArgumentException`이 발생했습니다. 기존 제품 테스트와 같은 기본 인터페이스 메소드 위임으로 수정했습니다. 수집 실패가 JS·응답·Mapper로 전파되던 준비 오류이며 제품 소스는 바꾸지 않았습니다.
- 비동기 구조 비교·관측 큐는 실행 직후 결과가 아직 게시되지 않았습니다. EDT 밖에서 실제 종료·결과 게시와 각 작업 큐의 drain을 기다리도록 교정했습니다. 결과가 없는데 성공하도록 조건을 완화하지 않았습니다.
- core001의 기능 실행 후 scope 창을 열 때 테스트가 임시로 사용한 dialog opener를 복원하지 않아 캡처가 중단됐습니다. 복원 후 core002는 기능13개와 기존 형태의26장 캡처를 완주했습니다.
- core002의 SQL 후보가 스크롤 밖에 있고 상세가 미선택이며 계정 비교가 동일 계정 화면에 머물러 시각적 근거가 부족했습니다. core003은 실제 기존 행·비교 계정·원문을 선택해 원본을 다시 캡처했습니다. 데이터·결과 모델을 만들거나 수정하지 않았습니다.
- core003의 JS 첫 선택 경로는 `/login`입니다. helper 메타데이터의 method 열 혼동은 별도 정정 노트로 처리했으며 추가 HTTP/네 번째 core 실행을 하지 않았습니다. 향후 helper 열 변환 수정은 컴파일만 확인했고 원본 캡처·JSON은 유지했습니다.
- 은행 브라우저 초기 실행은 원본 training notice가 클릭을 막아 중단됐습니다. 실제 Got it 버튼을 눌러 닫은 후 마지막 새 출력 폴더에서 성공했습니다. 원본 DOM/CSS·이미지를 고치지 않았습니다.
- 독립 대조의 첫 health 호출에서는 Python Request의 메소드 접근을 교정했습니다. 새 private 출력 폴더에서 완주한 최종10요청만 보고합니다.

- 결과 HTML의 file URL은 관리형 Chromium 정책으로 차단됐습니다. 임시 loopback 정적 서버로 같은 파일을 검증했습니다. 처음에는 화면 아래의 lazy image까지 즉시 로드를 기대해 대기가 끝나지 않았고, 검증용 페이지에서 eager 로드를 지정해 검색·필터·13개 라이트/다크 원본 이미지가 모두 로드됨을 확인했습니다. 은행·제품 요청을 추가하지 않았습니다.
