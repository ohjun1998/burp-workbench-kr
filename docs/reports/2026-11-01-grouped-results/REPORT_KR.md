# Workbench Simple 1.4.22 · 전체 결과 목록 A 그룹형

URL·경로가 반복되던 결과 목록을 **접이식 유형 그룹 → 짧은 기능명 → 관측 건수**로 탐색한다. 선택한 원본 URL·ID는 `원본 정보 보기`와 각 도구의 기존 상세에서 확인한다. Simple은 1.4.22, 내장 Mapper는 0.3.22이며 브라우저 도우미는 0.4.1이다.

## 적용 범위

13개 도구와 보조 창을 조사했다. URL 결과 목록은 아래처럼 연결했다.

| 화면 | 적용한 목록 | 원본 연결 |
| --- | --- | --- |
| 통합 점검 | 경로·응답, 발견 사항 9개 탭, 브라우저 관측 | 원래 finding·packet ID, 줄·offset, 선택 상세 |
| 대시보드 | 관측 경로와 API·명세·환경·DB 등 모든 카드의 결과 | 원래 projection 행과 카드별 계정·중요도 조건 |
| 요청·응답 | 짧은 업무명과 기존 비슷한 요청 묶기 | 기존 디스크 기반 비동기 그룹·검색·원본 ID |
| 기능 자동 매핑 | 업무별 그룹, 기능별 요청 건수 | 원래 feature ID·primary·links·편집 이름·상태·메모 |
| JS에서 API 찾기 | API 후보, 분석 이력, 도메인, 클라우드, 소스맵, 복원 원본 | 개별 호출 위치와 소스 문서·offset, 분석 결과 |
| 서버·경로 탐색 | 후보 경로와 변경 기록 | 원래 URL·계정·판정·요청/응답 |
| 외부 노출·CVE 조사 | 가져온 노출 URL | 원래 출처·선택 상세·명시적 조회 |
| 계정 권한 비교 | 실행 이력 | 원래 실행 번호·기준/비교 패킷 |
| 응답 보안 분석 | 응답 관찰, API 문서, 저장/조회 연결 | 원래 finding key·문서·쓰기/조회 URL |
| 점검 진행 현황 | 관측 URL과 미확정 경로 | 원래 작업·출처·상태 |
| 재현·증거 정리 | 재현 흐름, 증거, 보조 OAST 목록 | 원래 evidence/flow/OAST ID·패킷 |
| URL 후보 수집 보조 창 | 수집 목록과 기존 패턴 요약 | 원래 후보·대표 선택·GET 검증·Repeater |

입력값 검사 결과는 실제 검사값, 데이터 변환·비교는 실제 값과 JSON 필드 경로가 주된 내용이다. 이 두 화면의 값을 URL 목록처럼 바꾸지 않았다. CVE 목록도 식별자 중심 표시를 유지한다. 대상 URL 입력란, 계정의 origin 식별 정보, Raw 요청/응답은 원래 용도로 사용한다.

## 데이터와 기존 동작

`GroupedResults`는 기존 JTable의 모델·열 모델·정렬기를 재사용한다. 원본 모델에 그룹 헤더 행을 넣거나 URL 값을 바꾸지 않는다. 그룹과 기능 선택은 기존 외부 필터에 결합하는 view filter이며, 같은 유형의 관측은 건수만 합산한다. 각각의 원본 행·판정·선택 ID는 별개로 남는다. 원래 검색 조건과 정렬을 유지하고, 짧은 표시명으로도 검색한다.

API·명세 후보는 계정·인증, 핵심 업무, 문서, 정적 리소스 등의 경로 유형과 짧은 기능명으로 나눈다. 환경·DB는 Flask/Werkzeug 등 같은 내용의 관측 건수를 묶는다. 원래 제목·URL·개별 판정은 분리해서 유지한다.

폭이 좁고 높이에 여유가 있는 카드에서는 그룹을 위, 표를 아래로 배치한다. 짧은 결과 영역은 표 높이를 유지하며, 표의 열은 강제로 압축하지 않고 가로 스크롤로 읽는다. 기존 사용자 열 너비·순서도 유지한다.

기능 자동 매핑은 `FeaturePresentation`을 통해 원래 이름과 별도의 표시명을 만든다. 사용자가 편집한 이름은 그대로 보존한다. 그룹을 접어도 보고 있던 기능·요청 필터를 풀지 않는다. 동일한 짧은 이름이 서로 다른 원본을 가리키면 안정적인 식별 접미사로 구분한다.

폴더를 접으면서 발생하는 임시 선택 이벤트만 구분해서 처리한다. 사용자가 명시적으로 기능 선택을 해제하면 원래처럼 필터와 열린 업무 검토의 출처 유효성을 해제한다. 두 동작의 차이는 기존 업무 연결 검사와 새 그룹 탐색 회귀에서 함께 확인한다.

JS의 동일 URL 호출은 기능별 건수를 합산하되 호출 위치별 선택 ID를 구분한다. 소스 위치 탐색으로 숨겨진 행을 여는 동작과 원문 문서를 유지한다. 변경 없는 갱신은 원문 읽기 위치와 선택을 건드리지 않는다.

요청·응답 목록은 대량 디스크 메타데이터를 EDT에서 다시 전수 조회하지 않도록 기존 `TrafficBrowser` 비동기 그룹 엔진을 재사용한다. 수집 설정 메뉴의 **A 그룹형으로 보기**로 기존 접기·펼치기 조건을 선택한다. 저장해 둔 그룹 조건은 보존한다. 표시명 검색도 기존 비동기 검색 안에서 수행한다.

그룹 선택·접기·펼치기·원본 확인으로 검사를 시작하거나 HTTP 요청을 보내지 않는다. 기존 명시적 실행·취소·SCOPE·계정·Repeater·증거 동작은 유지한다. 표시명이나 유형 그룹은 정상 기능 또는 취약점 확정 판정이 아니다.

## 검증 기록

`python3 simple/dev.py release`와 `python3 simple/dev.py verify`를 완료했다. JDK 17.0.21에서 `--release 17`로 컴파일했으며 Java 17 API 호환 검사도 통과했다.

| 최종 검사 | 결과 |
| --- | --- |
| Workbench 전체 회귀 | 183개 그룹 · 7,911개 검사 통과 |
| 페이로드 loopback HTTP | 136개 통과 |
| Mapper Java | 213개 통과 |
| 브라우저 도우미 Node | 29개 통과 |
| 자동 검사 합계 | 8,289개 통과 |
| 실제 Linux Swing 창 | Metal/Nimbus × 라이트/다크 × 3크기 · 1,632개 검사 통과 |
| 실제 창 캡처 | 13개 화면 × 12구성 · 156개, PNG CRC·치수·SHA 확인 |
| 그룹 탐색 중 자동 HTTP / 점검 시작 | 각각 0회 |
| 패키지 검증 | JAR·소스 ZIP·도우미 ZIP의 SHA, 소스 지문, ZIP 내용/CRC 통과 |

자동 검사는 [check-summary.json](check-summary.json), 창 검사는 [native/verification.json](native/verification.json), 패키지는 [artifact-verification.json](artifact-verification.json)에 기록했다. 자세한 실행 로그는 [release.log](release.log)와 [package-verification.log](package-verification.log)다. 자동 검사와 창 검사의 수치를 서로 다른 고유 테스트 수로 합산하지 않는다.

설치 JAR와 실제 창 검사에 사용한 JAR는 동일하며 SHA-256은 `d5ac13a818d0fd641c72cd093cd86c21c3fea7793e01e3cc5b8da25900f0ff7c`다. [설치 JAR](../../../simple/downloads/1.4.22/burp-workbench-simple-1.4.22.jar) · [독립 빌드 소스 ZIP](../../../simple/downloads/1.4.22/burp-workbench-simple-1.4.22-source.zip) · [패키지 manifest](../../../simple/downloads/1.4.22/manifest.json).

창 검사는 합성 데이터와 실제 production Swing을 사용했다. 네이티브 fixture의 계정 비교 이력과 응답 분석은 빈 결과 경로를 확인했으며, 이들 도구의 데이터/선택 동작은 전체 회귀와 공통 그룹 검사로 보완했다. Windows Burp 본체·DPI/IME, 실제 브라우저 도우미 조작, Docker 스택과 외부 서비스는 이번 검사 범위가 아니다.

앞선 전체 검사에서 발견한 작은 창 표 높이 문제를 실제 레이아웃에서 수정했다. JS의 서로 다른 호출 위치가 하나의 표시 ID를 공유하던 문제도 개별 호출 위치 ID로 수정했다. 이전 전체 URL 표시와 JScrollPane 직접 캐스팅에 대한 검사 두 곳은 사용자 승인한 그룹형 표시·컴포넌트 구조에 맞춰 갱신했으며, 원본 URL·실제 컨트롤·ID·문서·무전송 검사는 유지했다.

닫힌 loopback 포트에 TCP self-connect가 성공할 수 있는 Linux/JDK 현상을 별도 프로브로 재현했다. 프록시 앱 소스는 변경하지 않고 `ScopeKatanaProxyTest`의 연결 소스 포트를 명시적으로 할당해 목적지와 겹치는 경우를 배제했다. 기존 Scope·TLS·취소·종료 assertions는 유지했으며, 개선된 검사는 별도 직렬 실행 3회에서 각각 49개를 통과했다. 이전 실패 당시에는 endpoint 로그가 없어 직접 원인은 확정하지 않았다. 근거는 `prior-attempts/closed-port-probe/`에 기록했다.

`prior-attempts/`와 별도의 이전 Mapper 전용 보고서 폴더는 중간 후보의 기록이다. 이 수치를 최종 전체 검증과 합산하지 않는다. 실제 Linux Swing과 합성 Burp API 어댑터 검증은 실제 Windows Burp 본체·DPI/IME 검증이 아니다. 은행 1.4.21의 기존 결과 HTML·ZIP과 이전 설치 패키지는 보존했다.

보고서에 복사한 위 콘솔 로그는 줄끝 공백만 정규화했다. 검사 원본 출력은 실행 작업 공간에 보존했으며, 검사 결과와 패키지·이미지의 SHA 검증 값은 바꾸지 않았다.
