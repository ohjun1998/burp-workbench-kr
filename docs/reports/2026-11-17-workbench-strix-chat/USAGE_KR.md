# Workbench Strix 1.1.0 · 대화 사용 안내

Strix 진단 중 관찰된 동작·판정 근거·추가 확인이 필요한 부분을 같은 에이전트에게 물어볼 수 있습니다. 기존 메인 화면은 Simple1.4.21 배치를 유지하고, 대화는 별도 Strix 진단 창에서 진행합니다.

## 준비

기존 Simple/Strix 확장을 언로드하고1.1.0 JAR를 로드합니다. 설정·기록 경로를 이어 사용하므로 이전 판과 동시에 로드하지 않습니다. Linux/macOS의 Python3와 호환 Strix CLI가 필요하며 실행 파일은 기존 `~/.strix/bin/strix` 래퍼입니다. Windows의 대화 연결은 지원하지 않으며 기존 비대화형 흐름의 Windows 실행도 이번 검증에 포함하지 않았습니다. Strix의 로컬 모델 또는 자체 ChatGPT 구독 인증을 그대로 사용하고, 별도 대화용 모델을 선택하거나 인증값을 복사하지 않습니다.

현재 프로젝트의 원본을 선택해 **선택 원본으로 Strix 진단 준비**를 누릅니다. 대상·SCOPE·모델을 확인하고 대화 연결을 켭니다. 별도 Strix 창의 네 번째 **원본·테스트 정책** 탭에서 **테스트 계정·기대 정책**을 작성하고 **진단 입력 미리보기**를 읽습니다. 중앙은 선택한 대화·로그·보고서·정책 화면이 넓게 사용하며 메인 메뉴·도구 배치는 유지합니다. 원본 ID·메서드·가림 처리된 URL 등의 제한된 자료만 준비하며 패킷 본문·쿠키·토큰을 자동 전달하지 않습니다.

## 진단과 질문

1. **실행 계획 확인·진단 시작**에서 조건을 확인하고 실행합니다. 준비나 창 열기만으로 진단을 시작하지 않습니다.
2. 대화의 연결 상태와 현재 대상을 확인합니다. 연결 대기·실패·종료 상태이면 전송하지 않습니다.
3. 질문을 입력합니다. 예: “이 결과는 실제 응답에서 확인한 사실인가요? 추정인 부분과 근거 원본을 구분해 설명해 주세요.”
4. 전송 확인창에서 대상·내용을 읽고 승인합니다. 기본 선택은 취소입니다. 에이전트가 추가 도구·대상 요청을 수행할 수 있음을 함께 확인합니다.
5. 대화에서 전송 수락과 답변을 구분해 읽습니다. 기록 갱신은 확정된 메시지를 반영하며 토큰 단위 실시간 스트리밍은 아닙니다. 기다리는 중 같은 질문을 반복 전송하지 않습니다.
6. 질문을 이어가거나 **중지**합니다. 프로젝트·원본·SCOPE가 바뀌면 다시 현재 자료로 준비합니다.

초기 진단 작업이 완료된 뒤에도 이번 Strix 프로세스가 살아 있고 실행 시간 상한 안이면 같은 에이전트와 대화를 이어갈 수 있습니다. 후속 질문으로 에이전트가 재개되면서 초기 턴 예산이 늘어날 수 있습니다. 최대 에이전트 턴은 전체 대화의 엄격한 턴 상한이나 HTTP 요청 예산이 아닙니다. 처음 시작한 실행 시간 상한은 후속 질문으로 초기화되지 않습니다.

## 전송할 수 없는 상태

연결 실패·모델 제한·세션 종료·프로젝트 변경을 답변으로 표시하지 않습니다. 현재 진단을 소유한 프로세스가 종료되면 연결을 끝내며 자동 새 진단이나 자동 재전송을 하지 않습니다. Python3 또는 대화 가능한 Strix가 없다면 기존 비대화형 진단을 선택해 실행·로그·보고서를 사용할 수 있습니다.

Strix 창을 닫는 동작과 진단 중지·확장 언로드의 의미는 상태를 확인하며 사용합니다. 중지는 이미 대상 서버에서 실행한 작업을 되돌리지 않으며 별도 Docker 작업의 완전한 종료를 보장하지 않습니다.

## 기록과 민감 정보

대화는 같은 에이전트의 세션 기록을 사용합니다. 창은 모든 에이전트를 합한 최근 대화 최대200개·128Ki자 안에서 현재 선택한 에이전트의 내용을 표시합니다. 오래된 내용이 표시 범위 밖으로 밀려도 Strix 실행 폴더의 원본 이력은 유지됩니다. 질문을 별도 독립 LLM 작업으로 보내지 않습니다. 대화 내용에 필요한 설명을 적되 쿠키·비밀번호·토큰·원본 인증 헤더를 붙여넣지 않습니다. 화면의 가림 처리를 원본 Strix 기록 전체의 비밀 제거 보장으로 해석하지 않습니다.
