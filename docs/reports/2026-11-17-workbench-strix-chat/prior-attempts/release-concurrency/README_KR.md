# 배포 전 검사 재실행 기록

최종 전송 상태 문구를 수정하는 동안 배포 검사와 별도 빌드가 같은 테스트 출력 폴더를 동시에 사용했습니다. 별도 빌드가 검사 중의 클래스 디렉터리를 초기화해 앞선 release 시도에서 `NoClassDefFoundError`가 발생했습니다. 이는 배포 전 검증 실행의 중복으로 생긴 실패이며 제품의 정상 실행 결과나 통과한 검사로 기록하지 않습니다.

최종 문구는 “전달 확인 · Strix 응답은 대화 이력에 표시됩니다.”입니다. 답변이 이미 도착한 뒤에도 계속 대기 상태로 보이는 표현을 수정했습니다. 해당 수정 후 완전한 클래스 빌드에서 release를 한 번씩 순서대로 실행하고, 실제 창 캡처도 같은 최종 JAR로 다시 생성합니다.

이전 native 캡처의 JAR SHA-256 `513677d6c287b8ed7da02bf3aedcce243586358679271ec0d1d5c1c8f9e7a907`은 최종 배포 근거로 사용하지 않습니다. 상태 문구 수정 후 JAR SHA-256은 `1984ee6014de648a6308ae8e0b0ee4d8a55c3ae38ddc4d5830beb0fdd5175f5b`이며, 최종 배포 manifest와 캡처 manifest의 실제 일치를 다시 검사합니다.

현재 검사 통과 수·패키지 상태는 상위 검증 기록과 최종 결과 파일을 기준으로 확인합니다. 이 실패 시도의 검사 수를 최종 수에 합산하지 않습니다.
