Workbench Next 0.54.2
이미지로 따라 하는 사용법

사이트를 직접 사용해 모은 요청·응답을 AI로 검토하고, 근거를 확인한 뒤 증거와 보고서 초안으로 정리합니다. 처음에는 원본 한 개로 연결을 확인하고, 그다음 같은 기능의 원본을 묶어 분석하세요.

0.54.2 전체 CI 검증 완료자동 검사 5,199개 통과실제 Burp·모델 추론 확인 필요
이 가이드의 화면과 확인 범위

실환경 점검 중 0.54.1이 Codex CLI 0.169.0에서 지원하지 않는 옵션을 전달해 구독 분석이 중단되는 문제를 발견했습니다. 이를 수정한 최종 적용 대상은 0.54.2입니다. 기존 0.54.1 배포와 검증 기록은 보존합니다. 수정본 0.54.2의 전체 5,199개 검사와 Windows/Linux 내구성 검사가 통과했습니다. 개별 회귀 검사 수치는 전체에 포함되므로 합산하지 않습니다.

이미지는 0.54.2 실제 운영 UI를 합성 자료로 렌더링한 예시입니다. 새 JAR로 AI 패널 28개 화면을 확인했으며 배치 위반은 0건입니다. 사용자 Burp 캡처는 아니며 이미지 생성 중 모델·대상 호출도 없습니다. 구독 클라이언트 98개·실행 승인 53개 회귀 검사가 통과했고, 실제 클라이언트의 ChatGPT 로그인 확인도 성공했습니다. 수정 후 미지원 설정 오류가 사라진 것은 확인했지만, 다음 CLI 초기화가 이 환경의 읽기 전용 파일시스템에 막혀 모델 응답을 받지 못했습니다. Halogen 포트 접근과 사용자 Burp 화면 접근도 제한되어 실제 추론·Burp 사용 흐름은 마지막 단계에서 확인해야 합니다.

0.54.2 설치 JAR GitHub 배포 폴더 ↗ 상세 사용 안내

이 문서는 Next 0.54.2 기준입니다. Custom AI Agent 내장 0.56.0 후보와 Workbench Simple은 별도 버전입니다. HTML과 assets, CSS·JS 파일을 함께 보관하면 인터넷 없이 읽을 수 있습니다.

01

먼저 한 번

설치하고 버전 확인하기

  1. 현재 쓰는 Workbench JAR와 Burp 프로젝트·설정을 보관합니다.
  2. 위 링크에서 burp-workbench-kr-0.54.2.jar를 준비합니다. 소스 ZIP은 개발·재빌드용이며 설치 파일은 JAR입니다.
  3. Burp의 Extensions → Installed에서 이전 Workbench를 언로드한 뒤 Add → Java → Select file로 새 JAR를 선택합니다.
  4. 확장 오류가 없는지 보고 Workbench 화면의 버전이 0.54.2인지 확인합니다. 기존 버전과 새 버전을 동시에 로드하지 않습니다.

Burp의 확장 설치 화면은 Burp 버전별로 조금 다릅니다. 이 단계는 메뉴 경로로 안내하며, 실제로 촬영하지 않은 Burp 설치 화면을 예시로 만들지 않았습니다.

다운로드 파일을 체크섬으로 확인하려면

GitHub 배포 폴더의 SHA256SUMS와 파일 해시를 비교합니다. Linux 터미널에서는 JAR와 SHA256SUMS가 있는 폴더에서 실행하세요.

sha256sum -c SHA256SUMS

소스 ZIP까지 함께 내려받았다면 두 파일 모두 OK가 표시됩니다. 일부 파일만 받았다면 해당 파일의 해시를 개별 비교하세요.

02

분석 재료 준비

SCOPE 지정하고 트래픽 모으기

  1. 허가된 테스트 사이트의 프로토콜·호스트·포트를 확인합니다. SCOPE 목록에서 필요한 URL·경로만 포함하고 수집 체크를 확인합니다.
  2. Workbench의 수집 상태를 SCOPE로 전환합니다. OFF이면 새 트래픽을 수집하지 않습니다.
  3. Burp를 거치는 브라우저에서 테스트 계정으로 로그인하고 기능 하나를 사용합니다. 예를 들어 “내 주문 열기”를 수행합니다.
  4. 요청·응답 목록에 해당 요청과 응답이 보이는지 확인합니다. 인증·계정·소유 관계도 함께 메모합니다.

이미 Burp HTTP history에 원본이 있다면 해당 항목을 우클릭해 Extensions → Workbench Next → AI 메뉴로 준비할 수도 있습니다. AI 기능은 수집한 자료를 사용합니다. AI가 브라우저를 열거나 사이트 전체를 탐색해 자료를 모으지는 않습니다.

03

사용할 AI 선택

로컬 Halogen과 ChatGPT 구독 연결하기

재현·증거 정리 → AI 검토 → AI 설정을 엽니다. 작업별 자동은 작업에 맞는 경로를 선택합니다. 로컬로만 처리하려면 실행 경로를 로컬 Halogen으로 직접 바꾸세요.

작업작업별 자동의 기본 경로

로컬 Halogen

  1. Burp와 Halogen이 같은 PC라면 주소에 http://127.0.0.1:8731/v1을 입력합니다. 다른 PC의 Halogen을 사용하면 그 PC의 사설 IP·실제 포트와 인증을 지정해야 합니다.
  2. 로컬 연결 확인으로 서버 지원 정보를 조회하고, 로컬 모델 목록에서 사용할 모델 ID를 확인합니다.
  3. 기본 모델 ID는 halogen-qwen3.8-flash-next입니다. 목록과 다르면 실제 ID로 수정합니다.
  4. 처음에는 기본값인 출력·추론 예산 8192, 추론 low, 제한 시간 180초를 사용합니다. 서버가 추론 옵션을 지원하지 않으면 추론 입력을 비워 필드를 생략합니다.

ChatGPT 구독

  1. Burp를 실행하는 PC의 터미널에서 공식 Codex CLI의 ChatGPT 로그인을 확인합니다. 필요하면 codex login으로 로그인합니다.
  2. AI 설정의 Codex 실행 파일에 codex 또는 절대 경로를 지정합니다. 이 PC의 경로 예시는 /home/kwonohjun/.local/bin/codex입니다.
  3. 모델 입력을 비우면 CLI 기본 모델을 사용합니다. 구독 로그인 확인을 눌러 상태를 확인합니다.
codex --version
codex login status

로그인 확인 성공과 실제 분석 성공은 별도입니다. 분석 시 해당 계정의 모델 지원·사용 한도가 적용됩니다. 구독 경로를 선택하면 가림 처리한 입력이 OpenAI 서비스로 전송됩니다. API 키 인증은 구독 작업에 사용하지 않으며, 오류나 거절 시 다른 서비스로 자동 전송하지 않습니다.

04

의미 있는 질문 만들기

원본과 기대 정책 준비하기

  1. 요청·응답 목록에서 같은 사용자 행동과 관련된 원본 1~24개를 선택합니다. 처음에는 한 개로 시작합니다.
  2. 우클릭하여 선택 패킷 AI 보안 검토 또는 선택 패킷 AI 기능별 분류를 선택합니다.
  3. AI 화면에서 작업·실행 경로·연결된 원본을 확인하고 기대 정책·기능 설명을 입력합니다.
붙여 넣어 사용할 설명 예시
계정 A가 본인의 주문 내역을 열었을 때 수집한 요청입니다.
정책: 주문 소유자만 상세 내용을 조회할 수 있어야 합니다.
기능별로 분류하고, 관찰된 사실과 가설을 구분해 주세요.
현재 자료로 판단할 수 없는 점과 다음 최소 검증을 설명해 주세요.
실제 계정 B 비교는 아직 수행하지 않았습니다.

화면 이름, 직전 클릭, 계정·테넌트, 객체 소유 관계, 기대 결과를 적을수록 분석 맥락이 분명해집니다. “취약점 찾아줘”만 입력하는 것보다 확인할 정책을 함께 제공하는 편이 유용합니다.

05

전송 전에 한 번 읽기

미리보기를 확인한 뒤 분석하기

  1. 전송 내용 미리보기 탭에서 전송 대상이 로컬 Halogen인지 ChatGPT 구독인지 확인합니다.
  2. 원본 ID·작업·가림 처리 결과를 확인합니다. 모든 업무 민감정보가 자동으로 가려지는 것은 아니므로 필요한 내용을 직접 점검합니다.
  3. 입력과 경로가 맞으면 AI 분석을 누릅니다. 중단하려면 중지를 사용합니다.
  4. 처리 시간·토큰 탭과 상태 문구에서 완료 여부를 확인합니다. 오류·잘린 응답은 분석 완료로 취급하지 않습니다.

원본을 준비하는 동작과 AI 분석은 대상 서버로 추가 HTTP 요청을 보내지 않습니다. 모델에는 제한된 미리보기가 전달되며, 부분 분석 표시가 있으면 전체 본문을 읽은 결과로 해석하지 마세요.

06

제안을 근거와 연결

결과를 원본과 대조하기

분석·기능 분류 제안에서 관찰·가설, 불확실성, 다음 검증을 읽습니다. 같은 원본은 여러 기능에 포함될 수 있고, 분류할 수 없는 원본은 미분류로 남습니다. AI 결과만으로 기존 권한 판정이나 점검 상태가 바뀌지 않습니다.

  • 원본 위치: 해당 제안에 연결된 원본의 Raw 미리보기를 확인합니다. 여러 원본이 연결됐으면 연결 원본 선택상자에서 고릅니다.
  • 원본 → Repeater: 원본을 Burp Repeater에 준비합니다. 값·인증·검증안을 검토한 뒤 Send는 직접 실행합니다.
  • 계정 비교 해설: 실제 계정 비교를 수행한 다음 종료된 History 결과에서 AI 해설을 요청합니다. 기대 정책과 실제 응답 차이를 함께 확인합니다.

예를 들어 계정 B도 200 응답을 받았다는 사실만으로 접근제어 취약점이 확정되지는 않습니다. 응답이 실제 A의 비공개 데이터인지, 해당 정책에서 B에게 허용되지 않는지, 재현 가능한지를 확인해야 합니다.

07

보고 가능한 형태로 정리

증거와 보고서 초안 만들기

  1. 보관할 제안을 선택하고 선택 제안 → 증거를 누릅니다. 완전한 원본과 미검증 AI 메모가 함께 전달됩니다.
  2. 증거 묶음에서 재현 절차·기대 결과·실제 결과·영향을 직접 정리합니다.
  3. 증거 화면의 AI 초안으로 보고서 입력을 준비하고 전송 경로·미리보기를 확인한 뒤 분석합니다.
  4. 보고서 초안 탭에서 사실·원본 ID·영향을 검토한 뒤 보고서 초안 추가를 누릅니다. 기존 재현 설명 아래에 추가됩니다.

원본이 없거나 현재 SCOPE 밖이거나 증거 패킷 합계가 128KiB를 넘으면 전달을 중단합니다. 초안 준비 후 프로젝트·증거·계정·메모 등을 바꾸면 다시 준비해야 합니다. AI 초안은 자동 제출되지 않으며, 검증하지 않은 내용을 확정된 취약점으로 작성하지 마세요.

08

검사가 실제 요청을 보낼 때

실행 계획과 영향을 확인하기

퍼징, 환경·경로 탐색, URL GET 확인, 계정 비교, 쿠키·세션 조합, 여러 요청 재현, JS 소스맵 탐색 등의 자동 전송은 실행 전 확인창이 열립니다. 기본 선택은 취소입니다.

  1. 대상과 경로가 허가 범위인지 확인합니다.
  2. 요청 수·간격·계정·상태 변경 가능성을 읽습니다. 쓰기 동작이 포함되면 실제 영향과 복구 방법을 먼저 확인합니다.
  3. 검토한 계획을 실행할 때만 확인 후 실행을 선택합니다. 취소·창 닫기는 전송을 시작하지 않습니다.
  4. 새 실행과 재개에는 다시 확인이 필요합니다. Workbench 밖의 Burp 도구는 해당 도구에서 따로 제어합니다.
09

실제 PC에서 확인할 마지막 단계

연결 검사 결과와 Burp 동작 확인하기

함께 제공한 점검 도구는 배포 파일·실행 환경·연결 상태를 확인합니다. --live를 붙이면 합성 자료로 모델 분석을 시도합니다. 실제 테스트 사이트에는 요청하지 않습니다.

python3 ~/workbench-next-0542/tools/check_next_0542_runtime.py --live --provider both --timeout 180

한 경로만 확인하려면 --provider local 또는 --provider subscription을 사용합니다. 구독 검사도 실제 계정의 사용량을 사용하며, 성공 여부는 생성된 결과 JSON에서 확인합니다. 도구가 성공해도 Burp 내부의 실제 UI·원본 연동까지 검증한 것은 아닙니다.

현재 작업 기록: 배포·코드·화면 검증과 사용자 PC의 실사용 검증은 구분합니다. 이 문서의 체크박스를 누르거나 예시 결과를 읽는 것으로 실제 검증 상태가 바뀌지 않습니다.

AI 메뉴나 설정이 보이지 않음로드한 JAR가 Next 0.54.2인지, 이전 확장과 중복 로드했는지 확인합니다. Custom AI Agent 메뉴는 별도 0.56.0 후보의 기능입니다.

구독 로그인 확인 실패Burp를 실행하는 사용자로 codex login status를 확인합니다. 실행 파일 절대 경로를 지정하고 ChatGPT 로그인인지 확인합니다. API 키 인증이면 구독 경로에서 중단합니다.
로그인은 되지만 구독 분석 실패미지원 설정 오류가 있던 0.54.1 대신 0.54.2 JAR인지 확인합니다. 수정 후 해당 오류는 사라졌으나 이번 환경에서는 CLI 초기화가 읽기 전용 파일시스템에 차단됐습니다. 실제 PC에서는 CLI 버전·지원 옵션·모델·계정 한도를 확인하고 점검 도구를 실행하세요. 로그인 확인은 추론 성공과 별개이며 실패 시 다른 서비스로 자동 전송하지 않습니다.
시간 초과·빈 답변·JSON 오류분석 미완료입니다. 원본을 작게 나누고 토큰 예산·추론 수준·제한 시간을 점검합니다. 실제 서버가 추론 옵션을 받지 않으면 추론 수준을 비웁니다.
