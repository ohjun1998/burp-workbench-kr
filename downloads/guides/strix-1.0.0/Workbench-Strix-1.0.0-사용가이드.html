Workbench Strix로 진단하기
모델 선택부터 보고서까지

Burp에서 관찰한 원본을 선택하고 기대 정책을 작성합니다. 로컬 Halogen/Qwen 또는 Strix의 ChatGPT 구독 경로를 고른 다음, 실행계획을 확인하고 기존 Strix CLI를 실행합니다.

Workbench Strix 1.0.0 연동 기능실제 패널 · 합성 화면실제 사용자 Burp·모델 추론은 별도 확인
이미지가 보여 주는 범위

아래 7장은 지정한 배포 JAR의 실제 Strix 패널과 실행 확인 내용을 합성 자료로 캡처한 화면입니다. 사용자 Burp 캡처가 아니며, 로그인·진단 중·완료·보고서 상태는 주입한 가짜 Runner의 예시입니다. 캡처 과정에서 실제 Strix CLI·모델·대상 호출은 없습니다. 실제 사용자 환경의 OAuth·추론·진단 성공을 증명하는 이미지로 해석하지 마세요.

Workbench Strix 1.0.0 설치 JAR짧은 사용 안내실제 검증 상태·제한

이 가이드는 Workbench Strix 1.0.0 기준입니다. 이 제품은 기존 Simple 1.4.13 Strix 연동 후보의 별도 명칭 배포판입니다. 일반 Simple 1.4.22의 A 그룹형이나 기능 중심 HTML 시안이 합쳐진 버전은 아닙니다. Next와 Custom AI Agent 내장 후보도 별도입니다. HTML·CSS·JS·assets 폴더를 함께 두면 오프라인에서 읽을 수 있으며, 이미지를 누르면 원래 크기로 확대합니다.

처음 한 번

설치하고 진단창 열기

설치·메뉴·창에는 Workbench Strix라는 이름이 표시됩니다. 저장 호환성을 위해 기존 simple.* 설정과 .burp-workbench-simple 폴더는 유지합니다. 독립된 새 저장 공간으로 옮긴 것은 아닙니다.

  1. 기존 Simple 또는 Strix 연동판 JAR와 Burp 프로젝트·설정을 보관합니다.
  2. 이전 Simple 확장을 언로드한 뒤 Extensions → Installed → Add → Java에서 burp-workbench-strix-1.0.0.jar를 로드합니다.
  3. 화면에 Workbench Strix 1.0.0이 표시되는지 확인합니다. 이전 연동판을 언로드한 뒤 새 제품을 로드하며, 일반 Simple과 동시에 사용하지 않습니다. 기존 설정·진단 기록을 삭제하거나 이동할 필요는 없습니다.
  4. 실행 파일 경로는 Strix 실행 파일 탭에서 확인합니다. 이 통합은 기존 ~/.strix/bin/strix 실행 래퍼만 지원합니다. 기존 Strix CLI가 설치되어 있어야 합니다. 진단창의 기본 실행 파일은 ~/.strix/bin/strix입니다. 기존 Strix 설치·래퍼·모니터를 새로 교체하는 기능은 아닙니다.
  5. 요청·응답 목록에서 원본을 선택하고 우클릭 → 선택 원본으로 Strix 진단 준비를 누릅니다. 공통 설정 창의 Strix 진단 열기로 창을 다시 열 수도 있습니다. 기존 8개 도구 경로와 Guide/F1은 유지합니다.
01

관찰 자료와 실행 대상을 구분

원본과 SCOPE 준비하기

  1. 허가된 사이트의 기능 하나를 직접 사용해 요청·응답을 수집합니다.
  2. 현재 프로젝트의 관련 원본 1~24개를 선택한 뒤 우클릭 → 선택 원본으로 Strix 진단 준비를 누릅니다.
  3. 대상 URL·원본 수·진단 입력 미리보기를 확인합니다. 선택한 URL의 Origin을 기본 대상으로 준비하며 SCOPE를 자동으로 넓히지 않습니다.
  4. 테스트 계정·기대 정책에 계정의 역할, 리소스 소유 관계, 허용 범위와 기대 결과를 적습니다. 비밀번호·쿠키·토큰은 입력하지 않습니다.

전달하는 것은 원본 ID·메서드·URL 등 제한된 메타데이터와 가림 처리한 정책 설명입니다. 원본 본문·인증값은 자동 전달하지 않습니다. 로그인 뒤의 요청을 선택해도 Strix가 그 세션을 자동으로 사용하는 것은 아닙니다.

경로 하나만 허용한 SCOPE에 사이트 전체 Origin이 포함되지 않으면 실행이 차단될 수 있습니다. 현재 승인받은 검사 범위를 먼저 확인하세요. 가이드를 따라 하기 위해 범위를 임의로 넓히지 마세요.

02

로컬 모델을 사용할 때

Halogen + Qwen 3.8 선택하기

  1. 진단창의 모델·Strix 설정 탭을 열고 모델 실행 경로 → 로컬 Halogen + Qwen 3.8을 선택합니다.
  2. 로컬 모델 설정 확인을 눌러 기존 Strix의 로컬 모델명·API 주소·유형을 확인합니다.
  3. 실제 Halogen 서버가 동작하는지 확인합니다. 설정을 읽었다는 사실과 서버 연결·추론 성공은 별도입니다.
  4. 대상·진단 조건 탭에서 사용할 모드·최대 에이전트 턴·실행 상한을 정한 뒤 다음 단계에서 실행계획을 검토합니다.

전역 Strix 모델 설정을 덮어쓰지 않고 실행별 설정을 사용합니다. 진단창에 표시한 모델·주소가 의도한 로컬 환경인지 확인하세요. 제공자를 변경하면 모델과 실행계획을 다시 확인해야 합니다.

03

구독 모델을 사용할 때

Strix의 ChatGPT 구독 인증 확인하기

  1. 모델·Strix 설정 탭에서 모델 실행 경로 → ChatGPT 구독 · Strix 자체 인증을 선택합니다.
  2. Strix 구독 모델에 chatgpt/<model> 형식을 지정합니다. 화면의 chatgpt/gpt-5.4는 입력 예시이며 실제 계정의 사용 가능 모델을 확인해야 합니다.
  3. 필요한 경우 터미널에서 아래 인증을 직접 수행합니다. Codex CLI 로그인과는 별도입니다.
  4. Strix 구독 로그인 확인을 다시 실행합니다. 로그인 확인 성공만으로 실제 추론이 확인된 것은 아닙니다.
strix auth login chatgpt
strix auth status

화면의 미로그인 상태는 합성 예시입니다. 실제 로그인 상태는 사용자가 실행한 Strix 자체 인증 확인 결과를 기준으로 판단합니다. 이 연결은 upstream Strix 자체의 OAuth 연동이며 OpenAI 공식 지원 대상 구독 API로 설명하지 않습니다. 연결부가 자격 파일이나 토큰을 읽어 표시·복사하는 기능은 없습니다.

오류·거절·한도 초과 시 Halogen이나 다른 제공자로 자동 전환하지 않습니다. 선택한 모델의 정책과 사용량이 적용됩니다.

04

실제 요청을 보내기 전

실행계획을 읽고 한 번 승인하기

정책 설명 예시 · 인증값 입력 금지
계정 A/B는 서로 다른 일반 사용자입니다.
각자 소유한 주문만 조회할 수 있어야 합니다.
현재 원본은 A가 내 주문을 열었을 때의 메타데이터입니다.
원본 인증값은 제공하지 않았습니다.
관찰된 사실·가설·추가 확인이 필요한 점을 구분해 주세요.
과부하·대량 반복·삭제·비가역 변경은 하지 말고,
그런 검사가 필요하면 중단하고 사용자 확인을 요청하세요.
  1. 진단 입력 미리보기를 읽고 대상·제공자·모델·모드·턴·시간·정책을 확인합니다.
  2. 실행 계획 확인·진단 시작을 누릅니다.
  3. 확인창에서 실제 대상 요청과 영향을 검토한 경우에만 확인 후 실행을 선택합니다. 기본 선택은 취소입니다.

최대 에이전트 턴은 HTTP 요청 횟수가 아닙니다. 모드·턴·시간 상한으로 전체 HTTP 요청 수가 강제 제한되지는 않습니다. 현재 CLI에는 이 연결부가 강제할 hard HTTP 요청 예산이 없습니다.

SCOPE는 실행 전에 원본·대상을 검사하는 조건입니다. Strix의 모든 통신을 격리하는 네트워크 샌드박스가 아닙니다. 가용성 영향 검사를 하지 말고 추가 확인을 요청하라는 내용도 에이전트에 전달하는 지시문이며, 요청 수나 무영향을 기술적으로 보장하지 않습니다.

05

진단이 시작되면

진행 상태와 로그 확인하기

승인 뒤 기존 로컬 Strix CLI를 실행합니다. Strix는 실제 대상에 요청하고 선택한 모델을 사용합니다. 창의 진행 로그에서 현재 상태·경과 시간을 확인합니다. 새로운 진단을 동시에 시작하지 않습니다.

로그 화면은 최근 일부만 표시하므로 전체 기록이 아닙니다. 모델·대상·정책을 바꾸면 이전 승인을 재사용하지 않습니다. 프로젝트나 실행 조건이 바뀌면 중지 요청을 하고 새 실행을 준비합니다. 오류가 나면 해당 경로의 오류로 표시하며 다른 모델로 조용히 재시도하지 않습니다.

06

원할 때 멈추기

중지하고 남은 실행 확인하기

  1. 중지를 누르면 연결된 진단 프로세스의 종료를 요청합니다. 창을 닫거나 프로젝트를 전환하거나 확장을 종료할 때도 연결 상태를 정리합니다.
  2. 중지 요청 뒤 프로세스가 끝났는지 상태와 로그를 확인합니다.
  3. 보고서의 컨테이너 정리 상태가 미확인이면 기존 Strix 관리 도구에서 남은 작업을 확인합니다.

중지는 이미 대상 서버에서 시작한 작업을 되돌리지 않습니다. Strix가 별도 컨테이너·백그라운드 작업을 만들었다면 UI의 중지 표시만으로 모두 종료됐다고 판단하지 마세요. 이 연동은 기존 Strix 모니터를 수정하지 않습니다.

07

결과를 근거로 확인

이번 실행 보고서 검토하기

  1. 이번 실행 보고서 탭에서 실행 폴더·보고서 경로와 종료 코드를 확인합니다.
  2. 첫 보고서 가림 미리보기를 누릅니다. 이번 실행 소유 보고서인지 확인한 뒤 텍스트로 보여 줍니다.
  3. 실제 요청·응답, 기대 정책, 재현 조건, 영향과 반증 조건을 검토합니다.

새 결과는 ~/.burp-workbench-simple/strix-runs/run-*/strix_runs/ 아래에 보관되며 기존 ~/strix_runs와 별도입니다. 현재 실행의 128 KiB 이하 보고서를 미리보기로 표시합니다. 큰 파일·이전 실행은 해당 폴더에서 확인하세요. 미리보기는 Workbench Strix의 추가 자료이며 기존 Strix 전역 지침도 별도로 적용됩니다.

원문 HTML을 자동으로 브라우저에서 실행하지 않습니다. 종료 코드 0이나 보고서 파일의 존재만으로 취약점이 검증된 것은 아닙니다. 로그인하지 않은 상태, 인증값 미전달, 공개 데이터처럼 결과에 영향을 주는 조건도 함께 확인해야 합니다.

새 진단의 기본 보관 위치는 ~/.burp-workbench-simple/strix-runs/run-*/strix_runs/입니다. 기존 ~/strix_runs와 별도이며 화면에는 이번 실행의 실제 경로를 표시합니다. 큰 보고서나 이전 실행은 해당 실행 폴더에서 확인하세요.

가이드와 검증 기록

Workbench Strix 1.0.0 사용 안내 · 실제 검사·배포·제한

가이드 자체는 외부 리소스를 불러오거나 모델·Strix·대상을 실행하지 않습니다. 외부 링크를 선택했을 때만 해당 주소를 엽니다. 실제 사용자 패킷·인증값·모델 응답 원문은 이 문서에 포함하지 않습니다.

화면 확대
