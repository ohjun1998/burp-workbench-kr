# Feature Mapper KR 0.2.0

사이트를 사용하는 동안 요청·응답을 기능별로 자동 연결하는 독립 Burp 확장입니다. 기능마다 세션·실행 사례·원본 패킷·매핑 근거·점검 상태를 함께 관리합니다. 기존 Workbench와 함께 설치할 수 있습니다.

## 설치하고 사용하기

1. `dist/feature-mapper-kr-0.2.0.jar`를 Burp **Extensions → Add → Java**로 추가합니다. **기능 자동 매핑** 탭이 생깁니다.
2. Burp를 통해 사이트를 사용합니다. 수집한 요청의 메서드·URL·본문 동작과 응답의 ID 연결로 기능 목록이 자동 생성됩니다. 필요하면 **Burp Scope만 수집**을 켭니다.
3. 왼쪽 기능을 선택하면 관련 요청들을 볼 수 있습니다. **실행 / 세션 / 검색**으로 사례를 좁히고 아래 **매핑 근거**에서 연결 이유를 확인합니다.
4. 원본을 직접 점검하려면 요청을 선택하고 **Repeater에 준비**를 누릅니다. Repeater의 Send는 직접 실행합니다.
5. **기능 이름·상태·메모**로 기록을 남깁니다. 분류가 잘못되었을 때만 **선택 패킷 분류 수정**을 사용합니다. 동일 요청 구조와 화면 출처에 대한 수정 규칙을 프로젝트에 저장합니다.
6. **프로젝트 저장**으로 `.fmkr` 파일을 남기면 기능·사례·메모·수정 규칙과 전체 원본을 다음 실행에서 불러올 수 있습니다.

`.fmkr`에는 실제 원본 요청·응답이 포함되므로 쿠키·토큰·본문도 저장됩니다. 외부 공유용으로 민감값을 자동 제거하는 파일은 아닙니다. 원본이 필요한 로컬 프로젝트 용도로 사용하세요.

## 화면의 버튼 이름으로 자동 매핑하기

1. `dist/feature-mapper-browser-0.2.0.zip`을 별도 폴더에 풉니다.
2. Chrome의 `chrome://extensions` 또는 Edge의 `edge://extensions`에서 개발자 모드를 켜고 **압축해제된 확장 프로그램 로드**로 `manifest.json`이 있는 폴더를 선택합니다.
3. Burp 탭의 **브라우저 연결**을 누르고 표시된 **연결 주소와 토큰**을 보조 확장의 팝업에 입력합니다. **연결 확인·저장**을 누릅니다.
4. 분석할 사이트 탭에서 보조 확장의 **현재 사이트 활성화**를 누르고 페이지를 새로고침합니다.
5. ‘게시글 등록’, ‘내 정보 수정’ 같은 버튼을 평소처럼 누릅니다. 화면 동작과 일치한 요청에 기능 이름과 브라우저 실행 사례가 자동 연결됩니다.
6. 분석을 끝낸 사이트는 **현재 사이트 해제**로 끕니다. Burp를 다시 로드하면 새 연결 주소·토큰으로 연결합니다.

보조 확장은 선택한 사이트의 화면·버튼 이름·요청 메타데이터를 로컬 Burp에 전달합니다. 입력칸 값을 읽거나 요청을 차단·수정하지 않습니다. JSON 요청 본문은 매칭용 SHA-256만 전달합니다. 본문 원본 수집은 Burp가 담당합니다.

## 자동 연결 기준

- 메서드·정규화된 URL·본문의 action / operation / operationName을 조합합니다.
- GraphQL은 같은 `/graphql` 안에서도 동작 이름과 query/mutation 이름을 구분합니다. 배열 배치의 동작 조합도 유지합니다.
- 관측한 응답의 ID가 이후 같은 출처·세션의 요청에 사용되면 업로드→생성→후속 조회를 연결합니다. 다른 기능에 필요한 선행 패킷은 여러 기능에서 참조합니다.
- 관측한 OpenAPI 응답의 summary / operationId를 기능 이름에 활용합니다.
- 브라우저의 탭·프레임·버튼·화면 경로와 요청 URL·메서드·시각·본문 해시를 맞춥니다. 이벤트가 늦게 도착해도 이미 수집한 요청을 보강합니다.
- 구분할 수 없는 동시 동일 요청은 브라우저 기능 매핑을 보류하고 기존 패킷 분류를 유지합니다.
- JS·CSS·이미지·세션 확인 등은 **공통 요청**으로 보관합니다. 원본을 삭제하지 않습니다.
- 반복 실행은 가까운 시각·세션·기능으로 추정하며, 브라우저 동작이 있으면 클릭별 실행으로 구분합니다. 세션 표시는 인증 자료의 프로젝트별 지문이며 실제 사람이나 역할을 증명하지 않습니다.

## 보관과 현재 범위

고정된 250건·128KiB 보관 제한은 없습니다. 원본은 전용 임시 디스크에 보관하고 선택 시 읽습니다. 확장 해제와 새 프로젝트 생성 시 임시 파일을 삭제합니다. 오래 남길 데이터는 `.fmkr`로 저장하세요. 비정상 프로세스 종료 시 임시 파일이 남을 수 있습니다.

기능 매핑은 추정입니다. 버튼과 가까운 시각에 발생했다는 사실만으로 JavaScript의 인과관계를 확정하지 않습니다. 브라우저 행동 관련성이 애매하면 **중간/낮음** 근거를 확인합니다. 점검 완료와 취약점 판정은 사람이 기록합니다.

자동 분석은 512KiB 이하 본문의 JSON·폼 필드가 중심입니다. 더 큰 본문의 원본은 그대로 보관하지만 구조 분석은 생략합니다. multipart의 바이너리 내부, 압축된 본문의 자동 해제, WebSocket, SPA hash만 달라지는 화면, 정확한 사람·역할 판별은 이번 버전의 자동 매핑 범위 밖입니다. 기존 HTTP history 전체를 자동 이관하는 기능도 제공하지 않으며 로드 이후 수집한 응답을 처리합니다. 프로젝트 메타데이터 가져오기 파서는 128MiB까지 읽습니다.

## 개발과 검증

JDK 17+와 Python 3.10+, Node 20+가 필요합니다. 확장 자체는 Java 17 대상으로 빌드합니다. 실제 Burp 실행은 별도로 설치한 Burp의 Java 요구사항에 따릅니다.

```sh
python build.py --test
```

이 명령은 Java 자동 분류/저장/실제 loopback 연결 검사와 브라우저 보조 코드의 Node 검사를 실행하고 JAR·보조 확장 ZIP·소스 ZIP 및 SHA256SUMS를 생성합니다. deps의 Montoya API는 고정 SHA-256을 확인합니다. 배포 JAR에 API 클래스를 넣지 않습니다.

실제 Burp 회귀 검사는 별도 설치 JAR와 Java 21을 지정합니다. 개인 프로필을 사용하지 않으며 테스트가 전용 포트 18182를 사용하므로 해당 포트가 비어 있어야 합니다.

```sh
python tests/run_native.py --burp-jar /path/to/burp-community.jar --java /path/to/java21 --accept-community-license
```

`--accept-community-license`는 첫 실행 시 Community 라이선스에 동의할 때만 사용합니다. 실제 브라우저 검증은 설치한 Playwright Core와 Chromium/Chrome for Testing 실행 파일을 지정합니다. 이 검사는 프로덕션 Mapper와 Bridge를 실제 브라우저·로컬 fixture로 검증하며 Burp 실행 검사와 구분합니다.

```sh
npm install --no-save playwright-core@1.64.0
PLAYWRIGHT_MODULE="$PWD/node_modules/playwright-core" python tests/run_browser.py --browser /path/to/chrome
```

검증한 범위와 CI 결과는 저장소의 `docs/RELEASE_0.26.0_KR.md` 및 PR을 기준으로 확인합니다.

## 0.2.0 성능 개선

기능별 패킷과 브라우저 요청 후보를 인덱스로 조회합니다. 프로젝트 저장은 일관된 메타데이터/원본 스냅샷을 확보한 뒤 긴 복사·압축을 수집 잠금 밖에서 수행합니다. 스냅샷 복사 자체의 짧은 잠금은 남습니다. 화면은 바뀐 행만 갱신하고 선택을 보존하며, 프로젝트 교체 시 이전 패킷 상세를 지웁니다. 미리보기는128KiB로 제한해도 전체 원본은 보존합니다.

검증 결과와 한계는 [0.26.0 통합 릴리스](../docs/RELEASE_0.26.0_KR.md)를 참고하세요. 설치 파일은 [버전별 다운로드](../downloads/feature-mapper/0.2.0/)에서 받습니다. 기존 0.1.0 자료는 보존합니다.
