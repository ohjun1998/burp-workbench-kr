# Burp Workbench KR 0.17.2

기존 기능을 유지하고 JS 추출·환경 탐색·URL 수집의 URL 및 대상 입력을 별도 대상 설정 창으로 옮겼습니다. 메인 화면에는 현재 대상 요약과 대상 설정 버튼을 표시합니다.

## 설치

기존 Workbench 확장을 내린 뒤 `burp-workbench-kr-0.17.2.jar`를 Java 확장으로 추가하세요. 기존 확장과 함께 중복 로드하지 않는 것이 좋습니다. 기존 프로젝트의 Multi-API 진입점과 Payload Runner 통합을 유지했습니다. JAR은 Java 17 대상으로 빌드했습니다.

이번 검증은 JDK 24에서 Java 17 대상으로 컴파일하고 HTTP fixture·Burp API 어댑터·Swing 렌더링으로 수행했습니다. 실제 Burp GUI에 JAR을 로드하는 검증은 수행하지 않았습니다.

## 트래픽에서 SCOPE 지정

1. 트래픽에서 URL을 선택하고 오른쪽 마우스 버튼을 누르세요. 여러 행도 선택할 수 있습니다.
2. **SCOPE 지정 → 선택 URL 경로 추가** 또는 **선택 도메인 전체 추가**를 선택하세요.
3. 트래픽 상단 **SCOPE 목록**을 누르면 별도 창에서 등록 URL과 범위를 확인할 수 있습니다. 트래픽 목록·선택 행·요청/응답 화면은 그대로 유지됩니다.
4. 필요 없는 등록은 **선택 SCOPE 삭제**로 삭제하세요.

URL 경로 등록은 해당 경로 및 하위 경로를 포함합니다. `/api`는 `/api`와 `/api/users`에 적용하며 `/apievil`에는 적용하지 않습니다. 도메인 전체 등록은 같은 프로토콜·호스트·포트의 모든 경로에 적용합니다. 다른 서브도메인은 각각 등록해야 합니다. 쿼리 값과 fragment는 SCOPE에서 제외합니다.

등록한 Workbench SCOPE는 권한 비교, JS History 분석 및 소스맵 요청, 환경 탐색, URL 수집 GET 검증, 활동 추적, 페이로드 검사에 공통 적용합니다. Burp의 전역 Target Scope는 변경하지 않습니다. 등록을 처음 만들기 전에는 기존 Burp Scope를 사용하며, Workbench SCOPE를 등록한 이후에는 등록 목록이 기준입니다. 마지막 등록을 삭제하면 대상은 없는 상태로 유지됩니다. SCOPE는 Burp 프로젝트의 확장 저장소에 저장하고 다시 로드할 때 복원합니다.

처음부터 URL을 선택할 수 있도록 트래픽의 **Scope만** 기본값을 OFF로 변경했습니다. ON으로 바꾸면 이후 수집하는 트래픽을 현재 SCOPE로 제한합니다. 트래픽 목록은 최근 250행을 유지합니다. 수집 OFF나 목록 비우기는 SCOPE 및 활동 추적 기록을 지우지 않습니다. 범위를 추가하면 보관된 트래픽 중 새 범위에 속하는 요청을 권한·환경·활동 추적에 반영하고 JS History를 다시 검토합니다. 기존 결과는 감사 이력으로 남으며, 범위 삭제는 이후 전송 자격을 즉시 제거합니다.

## 설정 창

상단 **설정**을 누르면 현재 도구 화면과 선택 상태를 유지한 채 별도 설정 창만 열립니다. 설정 페이지로 화면이 전환되지 않습니다. 창이 이미 열려 있으면 기존 창을 앞으로 가져옵니다. SCOPE 창과 설정 창은 비모달 창이므로 창을 열어둔 상태에서도 원래 화면에서 작업할 수 있습니다. 확장을 내리면 두 창도 닫힙니다.

## 대상 입력 화면 정리

- **JS 추출:** JS 원본 영역의 **대상 설정** 창에서 등록된 SCOPE를 선택하거나 기준/출처 URL을 입력합니다. 트래픽에서 응답을 가져오면 출처가 자동 연결됩니다. 메인 화면에는 출처 요약만 표시합니다.
- **환경 탐색:** **대상 설정**에서 관찰된 대상을 선택합니다. SCOPE에서 선택한 대상에 관찰된 응답이 없으면 트래픽에서 먼저 관찰하도록 안내합니다. 앱 접두 경로는 기존 **후보 설정**에서 지정합니다.
- **URL 수집:** **대상 설정 → 대상 열기**로 SCOPE의 URL 또는 직접 입력한 도메인을 준비합니다. 이후 **대상 수집 시작**을 누르면 현재 선택된 대상 탭에서 수집합니다. 대상 결과 화면의 중복 도메인 입력칸도 요약 표시로 바꿨습니다.
- **활동 추적:** 대상은 공통 SCOPE를 사용합니다. 입력칸은 **기록 검색**으로 표시하여 대상 URL 입력과 구분합니다.

대상 설정 창은 현재 도구 화면을 유지하는 비모달 창입니다. 창을 여는 것만으로 분석이나 대상 요청이 실행되지 않습니다. 새 URL 수집 대상도 **대상 열기** 단계에서는 수집하지 않습니다.

## 활동 추적

**활동 추적** 탭에서 URL·메서드별 진행 상태와 선택한 URL의 파라미터를 확인할 수 있습니다.

- Proxy 및 다른 Burp 도구의 실제 요청을 관찰합니다. 트래픽 수집 스위치·250행 제한과 별도로 동작합니다.
- **History 가져오기**로 기존 Proxy History를 기록할 수 있습니다.
- Repeater에서 실제 요청을 보냈을 때 작업 이력을 기록합니다. Repeater에 보내기만 한 경우는 작업 수행으로 계산하지 않습니다.
- URL·본문·쿠키 등 Montoya API가 제공하는 파라미터의 값 변경과 삭제를 기준값과 비교합니다. 중복 이름의 값들도 묶어서 비교합니다.
- HTML 링크·폼, 관찰한 JS 응답 및 JS 추출 탭의 분석 결과에서 실제 URL과 파라미터 이름을 가져옵니다. URL 수집에서 발견한 주소도 연결합니다.
- URL과 파라미터를 각각 **완료 / 해제**할 수 있습니다. **미완료 URL**, **미완료 파라미터**, **Repeater 작업**, **점검 완료** 필터와 검색을 제공합니다.
- **Excel 내보내기**는 엔드포인트·파라미터·상태 설명 시트를 만듭니다. **기록 저장 / 불러오기**는 JSON 파일로 작업을 이어갈 수 있게 합니다. 불러오기는 현재 기록을 교체합니다.

“Repeater 작업”과 “변경 관찰”은 작업의 근거이며 점검 완료나 취약점 확정이 아닙니다. 완료 표시는 진단자가 직접 지정합니다. 메서드가 알려지지 않은 발견 항목은 `?`로 표시하고 실제 요청을 관찰하면 알려진 메서드에 연결합니다. 프로토콜·호스트·포트·메서드가 다른 요청은 구분합니다. 미해결 동적 JS URL은 기존 JS 추출 화면에서 확인하며 활동 추적에 자동 추가하지 않습니다.

파라미터 원문 대신 세션별 salt를 사용한 해시로 변경을 비교합니다. 저장·내보내기에 원문 값이나 비교 해시는 넣지 않습니다. JSON을 복원한 뒤에는 새로 관찰한 요청이 새 세션의 비교 기준값이 됩니다. 관찰 요청 수에는 가져오기 등 기록 이벤트도 포함됩니다. 발견하지 못한 주소까지 포함하는 완전성 수치는 아닙니다.

한도는 엔드포인트 10,000개, 엔드포인트당 파라미터 200개, 전체 파라미터 100,000개입니다. 처리 대기열은 256개로 제한하며 대기열 누락과 엔드포인트 한도 제외는 하단에 표시합니다. 활동 기록 JSON은 32MB까지 읽습니다. 자동 응답 분석은 512KiB를 넘는 응답을 제외합니다.

## URL 수집 / Passive scan 개선

기존 **URL 수집** 탭에 다음 기능을 추가했습니다.

- waybackurls·gau·내장 Wayback 결과에 Burp Proxy History 및 기록된 HTML·JS 응답에서 추출한 URL을 병합합니다.
- **Burp History / JS** 소스는 외부 수집 도구 없이 기록된 응답만 분석합니다.
- 관리자/내부, 자금/결제, 인증, 파일 처리, 객체 접근, 기타로 분류합니다.
- 파라미터 이름, 민감 파일·관리 경로·인증정보 파라미터 등 검토 후보, 숫자 ID·UUID·해시 경로 패턴, 신규/이전 여부를 표시합니다.
- 검색·분류·정적 파일 숨김·패턴별 대표 5건 필터를 제공합니다. 원본 URL을 버리지 않고 화면에서 필터링합니다. 가로 스크롤로 추가 열을 확인할 수 있습니다.
- **더보기 → 이전 URL DB 가져오기**로 기존 `master_url_db.txt` 형식의 한 줄 한 URL 파일을 병합합니다. 가져온 URL은 이전으로 표시합니다.
- **더보기 → URL DB 저장**으로 다음 작업에 재사용할 원본 URL DB를 저장하고, **Excel 내보내기**로 쿼리 값을 제외한 분류 결과를 저장합니다. 원본 URL DB에는 쿼리 값이 포함됩니다.
- 일괄 검증은 현재 필터로 보이는 URL을 실행합니다. **미검증만 실행**을 선택하면 이미 응답을 확인한 항목을 제외합니다.
- logout/delete/remove 등 상태 변경 경로는 기본적으로 GET 검증에서 제외합니다. 도구 설정의 해당 옵션으로 명시적으로 포함할 수 있습니다.
- 검증은 현재 공통 SCOPE를 검사하고, 자동 리다이렉트를 따르지 않으며, 10초 응답 타임아웃을 사용합니다. HTTP 429를 받으면 나머지 검증을 중지합니다.

수집·선택·분류·활동 기록은 대상 서버에 요청을 보내지 않습니다. URL 수집 버튼은 선택한 아카이브/CLI 소스에 조회할 수 있으며, **단일 시작 / 일괄 시작**이 대상 서버 GET 검증을 실행합니다. 수집 URL은 대상 탭마다 최대 1,000개, 대상 탭은 최대 8개입니다. 출처를 합쳐 중복을 줄이고 실제 요청에는 원본 URL을 사용합니다.

참고 저장소의 수집 병합·동적 경로 분류·기능 우선순위·이전 DB 활용 방식을 Java 확장에 맞게 구현했습니다. 저장소 전체의 GitHub Actions 분산 실행, Katana 자동 크롤링, 클라우드 AI 분석 및 Discord 전송 파이프라인을 설치하거나 실행한 것은 아닙니다.

## 빌드

수정 소스 ZIP을 풀고 프로젝트 폴더에서 Python 3 및 JDK 17 이상으로 실행하세요.

```powershell
python build_all.py --test
```

Windows의 Java PATH 별칭이 잘못 연결된 경우 실제 JDK 경로를 지정할 수 있습니다.

```powershell
python build_all.py --java "C:\Program Files\Java\jdk-24\bin\java.exe" --javac "C:\Program Files\Java\jdk-24\bin\javac.exe" --test
```

출력은 `dist/burp-workbench-kr-0.17.2.jar`입니다. API 및 Rhino 의존성은 소스 ZIP에 포함했습니다. Windows CLI fixture 테스트는 Windows .NET Framework C# 컴파일러를 사용하며 Linux/macOS는 shell fixture를 사용합니다.
