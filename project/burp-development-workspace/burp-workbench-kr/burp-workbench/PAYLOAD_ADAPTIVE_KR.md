# Payload Runner KR 1.3.0 — 적응형 검사

이 버전은 외부 스캐너나 LLM 없이, 기존 Burp 요청 전송 API를 사용하는 자체 검사 스케줄러를 추가했습니다. 사용자는 검사할 입력 위치 한 개와 취약점 유형을 선택합니다. 모든 공격 유형/입력 위치를 스스로 찾아 검사하는 종합 스캐너는 아닙니다.

## 사용법

1. 이전 Payload Runner를 비활성화하고 1.3.0 JAR를 Extensions에 추가합니다.
2. History/Repeater 요청을 가져오고 값 하나를 `§PAYLOAD§`로 표시합니다. 원래 값을 기준값에 입력합니다.
3. 유형, 인코딩, Burp Scope, 요청 한도를 확인합니다. 기본 검사 방식은 **적응형 · 탐색/재검증/조기 종료**입니다.
4. 업로드 재조회는 기본 켜짐입니다. SSRF 로컬 HTTP 콜백은 선택 사항이며, 로컬 실습 서버에서 사용할 때 체크하고 콜백 포트 19112를 지정합니다. 이 모드에서는 목록 대신 고유 URL 두 개로 검증합니다.
5. Start를 누르면 백그라운드에서 실행됩니다. 작업 창, Stop, Repeater 전송, CSV 저장은 그대로 사용할 수 있습니다.
6. 추가 변형까지 모두 확인하려면 **전체 목록 · 기존 방식**을 선택합니다. 이 모드는 이전 버전과 동일합니다.

## 검사 방식

| 단계/유형 | 처리 |
|---|---|
| 기준 | 원래 값으로 비교 기준을 수집하고 한 번 더 요청해 안정성을 확인합니다. 업로드는 두 번째 기준 요청을 하지 않습니다. |
| 중복 | 동일 목록 항목과 원래 값과 동일한 입력을 생략합니다. 작업 간 캐시는 사용하지 않아 로그인·데이터 변경에 따른 오래된 판정을 피합니다. |
| XSS | 고유 문자열의 HTML 반사 여부를 먼저 확인합니다. 반사한 지점 주변의 태그/따옴표를 보고 후보 순서를 조정합니다. 후보가 반복 재현되면 나머지 변형을 생략합니다. 일반 HTML 텍스트 위치에서 전체 태그 입력이 메타문자까지 인코딩되어 반사되면 남은 정형 태그 변형을 생략합니다. script/style/textarea/태그 속성 위치는 이 생략에서 제외합니다. 다른 우회 가능성은 검사하지 않았다고 표시합니다. |
| XSS 생략 | 현재 응답이 HTML이 아니거나 완전한 응답에 문자열 반사가 없으면 현재 응답의 HTML 반사 검사를 생략합니다. stored/DOM XSS와 후속 화면은 검사하지 않았다고 표시합니다. 잘리거나 해석 불가능한 응답에서는 이 생략을 하지 않습니다. |
| SQLi | 작은따옴표가 목록에 있으면 먼저 한 번 보내 DB 고유 오류를 탐색합니다. 오류가 재현되고 기준에는 없으면 나머지 검사를 생략합니다. 오류가 없으면 사용자 목록의 완전한 참/거짓 쌍을 검사합니다. 기준이 두 번 동일할 때만 조건 차이를 판단합니다. 거짓→참 역순 재검증과 마지막 기준 응답까지 맞으면 후보로 표시합니다. 오류 검사도 유지합니다. |
| SSTI | 마커 사이의 산술식 평가를 관찰하면 다른 산술식(731×919 → 731×920)과 새 마커로 재검증합니다. 고정 숫자나 요청문 반사만으로 판정하지 않습니다. |
| XPath·LDAP·NoSQL | 사용자 목록에 준비된 조건 쌍이 있으면 안정적인 기준 응답에서 차이를 비교하고 역순 재현합니다. 특정 엔진 오류도 반복 검증합니다. 조건 차이는 검색 기능이 정상적으로 지원하는 연산자일 수도 있어 인젝션 확정으로 표시하지 않습니다. |
| 기타 직접 증거 | 파일 내용, 실제 헤더 삽입, Location 목적지, 명령 출력, 특정 엔진 오류 후보가 나오면 한 번 재검증하고 기준 응답을 다시 확인합니다. 파일/LFI/파일 XXE는 존재하지 않는 파일을 추가 대조하고, 리다이렉트는 다른 목적지 호스트, 명령 출력은 PR_CMD/PR_CTRL 두 조합을 비교합니다. 반복 관찰 후 같은 유형의 변형 검사를 중단합니다. |
| 업로드 | 2xx 수락 후 JSON의 단순 상대 `url`이 있으면 같은 대상에서 GET으로 재조회합니다. 원래 UTF-8 내용의 정확한 일치, MIME, Content-Disposition을 확인합니다. HTML/SVG inline 제공은 후보로 표시하고 나머지 변형을 생략합니다. 브라우저/서버 실행과 다른 계정 접근은 검증하지 않습니다. 외부·프로토콜 상대 URL과 리다이렉트는 추적하지 않습니다. 파일을 더 생성하는 자동 재전송은 하지 않습니다. 원래 기준 요청도 파일을 생성할 수 있습니다. |
| SSRF | 기본은 응답 문자열 관찰입니다. 선택형 로컬 HTTP 콜백 모드는 127.0.0.1에 수신기를 열고 서로 다른 고유 URL 두 개에 대한 GET 수신을 비교합니다. 확장은 콜백 URL에 스스로 접속하지 않습니다. 원래 서버의 응답이 동일해도 수신 여부를 확인할 수 있습니다. 기본 대기는 요청 후 최대 3초이며, DNS/SMTP/HTTPS나 더 늦은 콜백은 검증하지 않습니다. |
| 사용자 정의 | 기대 문자열이 지정되면 새로운 요청으로 재현하고 기준 응답에 없는지 확인합니다. 요청문 반사는 제외합니다. 사용자 조건 재현이며 취약점 자동 확정은 아닙니다. 기대 문자열이 없으면 관찰만 합니다. |
| 중단 | 401/403/429/503, 연속 전송·분석 실패 3회, Stop, 총 요청 한도로 중단합니다. 차단/중단은 안전하다는 판정이 아닙니다. |

**재현은 자동 확정과 다릅니다.** XSS 실행, DB 실제 처리, 템플릿 엔진, 명령 실행 위치, 파일 권한 등을 수동 확인해야 합니다. 동적 응답의 타임스탬프·토큰을 임의로 지우지 않으므로 SQLi 조건 비교는 보수적이며 일부 미탐이 가능합니다. 지연 기반 SQLi, 원격/public OAST·DNS/SMTP 콜백 연동, 브라우저/DOM 실행, 저장형 XSS의 다른 화면 이동, 자동 크롤링, 자동 입력점 추출은 포함하지 않습니다. 로컬 HTTP 콜백은 같은 PC/네트워크 네임스페이스의 실습 서버용입니다. 원격 서버에서 127.0.0.1은 해당 원격 서버 자신을 뜻하므로 이 모드를 원격 대상 검증에 사용하면 안 됩니다. Docker 컨테이너에서도 호스트의 127.0.0.1과 다릅니다. 수신기는 검사 종료/오류/확장 해제 시 닫히며, 포트 충돌은 검사 중단으로 표시합니다.

요청 한도는 기준·탐색·재검증·대조 요청과 전송 실패까지 모두 포함합니다. 시간 지연만 보고 판정하지 않습니다. 데이터 변경을 일으키는 POST 요청은 기준/재검증도 변경을 반복할 수 있으므로 테스트용 데이터에 사용하세요.

SSRF 콜백은 서버 측 네트워크 요청의 관찰 근거입니다. 의도된 URL 미리보기, 보안 장비, 중계 서버도 요청할 수 있으므로 접근 정책과 실제 요청 출처를 확인해야 합니다. 업로드 재조회는 원래 세션을 유지한 같은 대상의 조회입니다. 수평/수직 권한 검증은 별도 계정으로 수행해야 합니다. 모든 후속 요청에도 Burp Scope를 다시 적용합니다.

## 결과 읽기

결과 행은 실제 요청 관찰과 후속 판정 설명을 함께 표시합니다. 재판정 행은 같은 `#`와 요청을 다시 표시하므로 **표의 행 수는 실제 요청 수가 아닙니다.** 상태 표시의 `실제 요청 N회`가 전송 횟수입니다. `목록 생략/중복`에는 탐색으로 불필요해진 변형과 중복 항목이 포함됩니다. 요청 수를 줄이는 대신 재검증을 추가하므로 작은 목록이나 음성 응답에서는 기존 방식보다 요청이 늘어날 수 있습니다.
