# Payload Runner KR 1.3.0

Burp에서 요청 하나를 가져와 지정한 값에 16개 프로필의 페이로드를 순서대로 넣고 응답 근거를 비교하는 독립 Java 확장입니다. 기존 Workbench와 별개로 설치합니다. Java 17 이상이 필요합니다. Community/Professional의 Extender API용으로 만들었습니다. 실제 Burp Community 2026.3.3-47134와 Java 21에서 네이티브 JAR 로드 및 요청 전송을 검증했습니다. Professional과 Windows는 미검증입니다.

## 설치와 첫 검사

기존 1.0.0/1.1.0/1.1.1 확장을 제거하거나 비활성화한 후 1.3.0 JAR를 추가하세요.

1. Burp의 Extensions → Installed → Add에서 Extension type을 Java로 선택하고 `payload-runner-kr-1.3.0.jar`를 불러옵니다. 구버전 메뉴 이름은 Extender일 수 있습니다.
2. Proxy HTTP history 또는 Repeater의 **요청**에서 교체할 파라미터 값만 선택한 뒤 우클릭 → **Extensions → Payload Runner KR → 선택한 요청 값에 Payload Runner 표시**를 누릅니다. 전체 요청을 가져오려면 **Send to Payload Runner KR**를 누른 다음 탭 안에서 값을 선택하고 **선택 영역 → §PAYLOAD§**를 누릅니다.
3. **Payload Runner KR** 탭에서 유형을 고릅니다. 유형 변경은 페이로드 목록과 인코딩을 기본값으로 바꿉니다. 먼저 유형을 선택한 후 원래 값을 표시하면 URL/RAW 기준값을 올바르게 가져올 수 있습니다.
4. 요청에 `§PAYLOAD§`가 정확히 하나 있는지, 호스트·포트·HTTP/HTTPS·Host 헤더·기준값을 확인합니다. URL 값은 기준값에 디코딩된 원래 값을 넣습니다. 원래 값이 빈 문자열이면 기준값도 비웁니다. JSON 기준값은 JSON escape를 풀어 넣습니다.
5. Target Scope에 검사 주소를 추가합니다. 기본으로 **Burp Scope 내 요청만**이 켜져 있습니다. 범위는 Start 시 기준 URL에 대해 확인합니다. 경로 자체를 바꾸는 다운로드 검사에서는 페이로드별 URL 범위 재검사는 하지 않습니다.
6. 페이로드 목록, 간격, 총 요청 한도를 확인하고 **Start**를 누릅니다. 기준 요청 1회가 먼저 전송됩니다. SQLi는 기준 응답 안정성을 보기 위해 기준 요청을 한 번 더 전송합니다. 둘 다 요청 한도에 포함됩니다.
7. 결과 행을 선택하면 실제 전송한 요청과 응답 본문, 근거를 볼 수 있습니다. **선택 요청 → Repeater**로 재현하고 **CSV 내보내기**로 결과를 저장합니다.

**Stop**은 다음 요청을 중단합니다. 진행 중인 Burp 요청은 반환될 때까지 기다리므로 즉시 연결을 끊는 기능은 아닙니다. 전송 자체의 타임아웃은 Burp의 네트워크 설정을 따릅니다.

## 백그라운드 작업 창

Start는 별도 작업 스레드에서 요청을 순차 전송합니다. Proxy/Repeater 등 다른 Burp 탭을 사용해도 검사합니다. **작업 창 열기**를 누르면 모델리스 독립 창에서 결과, 진행률, Stop, Repeater 전송 및 CSV 저장을 사용할 수 있습니다. 창을 닫아도 검사는 계속됩니다. 다시 열면 같은 결과를 보여줍니다. 완료된 결과는 다음 Start 또는 결과 지우기까지 보관합니다. 확장을 해제하면 작업 종료를 요청하고 창도 정리합니다.

한 번에 한 검사이며 여러 검사 동시 실행/작업 대기열은 제공하지 않습니다. 실행 중에는 이 확장의 요청 편집만 잠그고 Burp 전체를 잠그지 않습니다. 완료 시 팝업이나 강제 탭 전환은 없습니다. 진행 중인 HTTP 요청은 Stop 후에도 Burp가 반환할 때까지 기다립니다.

## 유형과 인코딩

| 유형 | 표시할 위치 | 기본 인코딩 | 결과 의미 |
|---|---|---|---|
| XSS | 검색어, 글 내용 등 입력값 | URL | HTML에 입력이 그대로 반사됐는지 확인 |
| SQL Injection | 검색어, ID 등 SQL 관련 입력값 | URL | 새 SQL 오류와 참/거짓 응답 차이 후보 |
| 파일 업로드 · 파일명 | multipart의 `filename="..."` 안 파일명 | RAW | 확장자·경로형 파일명을 서버가 수락하는지 확인 |
| 파일 업로드 · 내용 | multipart의 파일 본문 일부 또는 전체 | RAW | 무해한 텍스트·HTML·SVG 내용을 수락하는지 확인 |
| 파일 다운로드 | 파일 경로·파일명 파라미터 | URL | 파일 내용 서명 또는 지정한 기대 문자열 발견 |

### 새 프로필 사용법

| 프로필 | 표시할 위치 / 기본 인코딩 | 자동으로 표시하는 근거 |
|---|---|---|
| SSTI / 표현식 삽입 | 템플릿으로 처리될 입력값 / URL | 고유 마커 사이 `731*919`, `731*920`의 계산 결과 |
| 경로 탐색 / LFI | 파일 경로 값 / URL | 파일 서명 또는 지정한 기대 내용 |
| 오픈 리다이렉트 | next, returnUrl 같은 이동 URL / URL | 3xx Location의 호스트가 전송값의 호스트와 일치 |
| CRLF / 응답 헤더 삽입 | 응답 헤더에 쓰이는 쿼리 값 / URL | 실제 응답 헤더 X-PR-Probe의 고유 마커 |
| XML 엔티티 / XXE | XML 요청 본문 전체 / RAW | 내부 엔티티 확장 관찰, 기대 파일 내용 |
| XPath Injection | XPath에 쓰일 입력값 / URL | 새 XPath 구문/평가 오류 |
| LDAP Injection | 검색/인증 필터의 입력값 / URL | 새 LDAP 검색 필터 오류 |
| NoSQL Injection | JSON 값 또는 객체 전체 / RAW | 새 MongoDB 오류 |
| SSRF | 서버가 가져올 URL 값 / URL | 지정한 기대 응답 문자열; 성공 판정은 수신 로그 확인 |
| 명령어 삽입 | 서버 명령의 인자가 될 입력값 / URL | printf가 별도로 조합한 고유 마커 출력 |
| 사용자 정의 | 원하는 입력값 / URL | 지정한 기대 문자열 또는 일반 응답 변화 |

XXE는 `<r>§PAYLOAD§</r>`의 r 값이 아닌 **XML 본문 전체**를 표시하세요. 기본 XXE 페이로드는 전체 XML 문서입니다. 기준값에는 원래 XML 본문을 넣고 Content-Type을 유지합니다. 내부 DTD가 허용된다는 것과 외부 엔티티를 읽는다는 것은 별개입니다. 기본 외부 엔티티 경로는 `file:///tmp/payload-runner-fixtures/download-marker.txt`입니다. 본인이 관리하는 실습 서버에 고유 문자열을 담은 파일을 만들어 경로를 맞추고 기대 응답 문자열을 설정하세요. 해당 경로를 실제로 읽었다는 응답 내용이 없으면 후보로 판정하지 않습니다. 외부 콜백/재귀 엔티티 폭탄은 기본 목록에 없습니다.

NoSQL은 `{"user":§PAYLOAD§}`의 값이나 조건 객체 전체를 표시하고 RAW를 사용합니다. `{"user":"§PAYLOAD§"}`의 문자열 안이라면 JSON 인코딩으로 바꾸세요. URL 폼 파라미터라면 URL 인코딩과 폼에 맞는 자체 목록이 필요합니다. 객체 수락이나 참/거짓 차이만으로 NoSQL 인젝션/로그인 우회를 확정하지 않습니다.

SSRF 기본값은 `127.0.0.1/localhost:19089`의 **직접 관리하는 수신 실습 서버**용 URL입니다. 진단 대상 서버의 localhost는 Burp PC가 아니라 그 서버 자신을 뜻합니다. 실제 환경에서는 본인이 관리하는 수신 URL로 교체하세요. 목록의 `{{MARKER}}`를 수신 로그에서 찾고 요청 출처와 시간을 비교해야 합니다. 확장이 수신 서버를 띄우거나 OAST 콜백을 조회하지는 않습니다. 내부망 열거/클라우드 메타데이터 경로는 기본 목록에 없습니다. 기대 내용이 응답에 없으면 인밴드 탐지는 근거 없음으로 끝날 수 있습니다.

CRLF 목록은 한 줄을 유지하도록 `{{CRLF}}`/`{{LF}}`를 씁니다. URL 모드에서 실제 제어문자를 각각 `%0D%0A`/`%0A`로 인코딩합니다. 목록에 이미 `%0d%0a` 또는 `%2f`가 들어간 항목은 URL 모드에서 이중 인코딩되어 이중 디코딩 여부를 검사합니다. RAW로 실제 CRLF를 요청 헤더에 삽입하는 것과 구분하세요.

SSTI 기본값은 여러 템플릿 문법의 산술식만 사용합니다. 단순 `49` 같은 숫자 출현이 아니라 요청별 고유 마커 사이의 정확한 결과를 봅니다. 사용자 정의 산술식으로 목록을 바꾸면 자동 판정은 기본 두 산술식에만 적용됩니다. 엔진 종류 및 서버/클라이언트 어느 처리 단계에서 평가됐는지는 자동 확정하지 않습니다.

명령어 삽입 기본값은 POSIX 셸의 printf 출력만 확인합니다. 입력에 없는 `PR_CMD_` + 마커의 조합 출력이 있어야 후보로 표시합니다. Windows 전용 구문, 시간 지연, 역방향 셸, 파일 쓰기는 기본 목록에 없습니다. 응답에 명령 출력이 나오지 않으면 미탐할 수 있습니다.

오픈 리다이렉트는 Location 목적지 제어 후보이며 그 이동이 정책상 금지된 것인지까지 판단하지 않습니다. 기본 example.invalid는 테스트용 예약 이름이며 확장은 목적지로 이동하지 않습니다. XPath/LDAP/NoSQL은 특정 오류의 새 노출만 탐지하며, 오류 없는 인젝션 성공은 자동 판정하지 않습니다. 모든 유형에서 근거 없음은 안전하다는 뜻이 아닙니다.

- **URL**: UTF-8 percent encoding. 쿼리와 `application/x-www-form-urlencoded` 값에 사용합니다.
- **RAW**: UTF-8 바이트 삽입. multipart 파일명/내용에 사용합니다. JSON에 RAW를 쓰면 따옴표로 JSON이 깨질 수 있습니다.
- **JSON**: JSON 문자열 내용의 escape 처리. `"q":"§PAYLOAD§"`처럼 템플릿에 바깥따옴표를 직접 둡니다.
- 사용자 목록은 한 줄에 한 페이로드입니다. 공백만 있는 줄은 건너뛰며, 최대 500줄입니다. 기본 목록은 `payloads/`에도 있습니다. 텍스트를 복사해 목록을 교체할 수 있습니다.
- `{{BASE}}`는 기준값, `{{MARKER}}`는 요청별 고유 문자열, `{{CRLF}}`/`{{LF}}`는 줄바꿈 제어문자로 치환합니다.
- 업로드는 원래 잡힌 multipart boundary와 쿠키를 그대로 사용하며, 표시한 위치 밖의 바이너리 바이트도 보존합니다. 전체 multipart 구조를 임의로 다시 만들지 않습니다. 요청 Content-Length는 자동 재계산합니다.

## 판정 해석과 제한

**후보는 확정된 취약점이 아닙니다.** XSS는 `text/html` 응답에 `<`를 포함한 페이로드가 그대로 있는 경우만 반사 후보로 표시합니다. 실제 브라우저 실행, 출력 컨텍스트, CSP, stored/DOM XSS는 검사하지 않습니다. 기본 XSS 이벤트 코드는 console.log만 사용합니다.

SQLi는 기준에 없던 DB 오류 문자열을 찾거나, 두 번 동일했던 기준과 참 조건 응답이 같고 거짓 조건만 다른 경우를 후보로 표시합니다. 단순 입력 반사 차이는 정규화합니다. 동적 페이지·WAF·조건별 일반 로직은 여전히 오탐을 만들 수 있습니다. 시간 지연, UNION 데이터 추출, 파괴적 SQL은 기본 목록에 없습니다.

업로드의 2xx는 **수락 후보**입니다. 실제 저장, 다운로드 가능성, MIME, 권한, 스크립트 실행까지 확인한 결과가 아닙니다. 기본 페이로드는 webshell을 포함하지 않습니다. 검사로 저장된 테스트 파일은 직접 정리하세요.

다운로드는 passwd/win.ini 형태의 내용 또는 사용자가 지정한 기대 문자열을 비교합니다. 기대 문자열은 기준 응답에 없어야 하고 전송 페이로드 자체에도 없어야 합니다. IDOR처럼 파일 경로가 아닌 객체 ID 검사는 해당 ID 목록과 테스트 파일의 고유 기대 문자열을 넣어 사용할 수 있습니다. 권한 정책에 대한 최종 판정은 별도 재현이 필요합니다.

401/403은 세션·권한 확인, 3xx는 리다이렉트로 표시하며 자동 추적하지 않습니다. 5xx만으로는 취약점을 확정하지 않습니다. 상태·길이·시간은 보조 정보입니다. 전송 오류는 결과 행에 기록하고 다음 페이로드로 진행하지만 기준 요청 실패 시 검사를 중단합니다.

쿠키와 CSRF 토큰은 가져온 요청의 값을 재사용하며 갱신하지 않습니다. 일회성 토큰이거나 업로드 후 상태가 바뀌면 새 요청을 가져오세요. 동일 요청을 순차 전송하므로 글쓰기·업로드는 데이터를 여러 개 만들 수 있습니다.

HTTP/1.0·1.1 raw 템플릿을 지원합니다. chunked 요청과 압축 요청 본문은 먼저 일반 요청으로 바꿔야 합니다. gzip·deflate·chunked 응답을 해석하고, 그 외 압축은 판정 불가로 표시합니다. 본문은 UTF-8로 해석합니다. 다른 문자 인코딩에서는 미탐 가능성이 있습니다. 응답 분석은 최대 256 KiB, 결과 본문/원본 응답 보관은 최대 64 KiB이므로 이후 내용은 누락될 수 있습니다. CSV에는 원본 쿠키·응답을 넣지 않지만 페이로드와 오류 근거 자체에 민감한 값이 있을 수 있습니다.

## 빌드와 테스트

JDK 17에서 `python3 build.py` 또는 `mvn package`로 빌드합니다. build.py는 컴파일러 클래스를 사용하며, `deps/burp-extender-api-2.3.jar`를 참조합니다. 없으면 첫 빌드 시 Maven Central에서 다운로드하고 고정 SHA-256으로 검증하므로 인터넷 연결이 필요합니다. API 클래스는 결과 JAR에 포함하지 않습니다. 기본 테스트는 `python3 test.py`입니다. Swing과 Burp API 콜백을 모의하고 실제 로컬 HTTP fixture에 요청을 전송합니다.

추가 커뮤니티 검사는 기존 Spring/Tomcat/H2 실습 서버를 켠 후 `python3 test.py 19088`로 실행했습니다. 서버 및 로그인 경로가 해당 실습 사이트 형식과 같아야 합니다. 이 소스 배포에 기존 실습 서버는 포함하지 않습니다. 현재 1.3.0 자동 검사는 72개이며 실제 Burp 검증은 별도로 수행했습니다. 검증 내역은 `VERIFICATION_KR.md`, `validation/test-results.*`, `validation/actual-burp/`를 보세요.

공식 API: https://portswigger.net/burp/extender/api/ · Maven 좌표: `net.portswigger.burp.extender:burp-extender-api:2.3`. API 의존성 원본은 https://repo.maven.apache.org/maven2/net/portswigger/burp/extender/burp-extender-api/2.3/ 입니다.

## 버전 변경

- 1.3.0: 독립 모델리스 작업 창, 실시간 결과·진행률·Stop·Repeater·CSV, 창 닫기 후 검사 유지, 확장 해제 시 창 정리. 실행 중 요청 가져오기 안내를 비차단 상태 메시지로 변경했습니다. SQL 오류 문자열 자체가 입력 반사된 경우 오류 후보에서 제외했습니다. 실제 Burp에서 탭 전환·독립 요청·창 닫기/재열기와 전체 추가 페이로드 41개를 검사했습니다.

- 1.1.1: 실제 Burp에서 추가 기본 페이로드 41개 전체를 재검증했습니다. NoSQL의 `$eq`/`$ne` 기본값에 JSON 객체 기준값을 넣었을 때 JSON이 깨지던 문제를 고유 마커 사용으로 수정했습니다. 원래 JSON 객체는 기준 요청에 그대로 사용하고 기본 비교 페이로드에는 중첩하지 않습니다.

- 1.1.0: 기존 5개 프로필에 SSTI·경로 탐색/LFI·리다이렉트·CRLF·XML 엔티티/XXE·XPath·LDAP·NoSQL·SSRF·명령어 삽입·사용자 정의를 추가했습니다. 유형별 사용 힌트, XXE/NoSQL RAW 기본값, 기대 응답 문자열 입력, CRLF 매크로, 유형별 근거 분석 및 오탐 방지 검사를 추가했습니다.
- 1.0.0: XSS·SQLi·파일명/내용 업로드·다운로드, 요청 표시와 순차 전송, Stop, Repeater, CSV 제공.
