# Workbench KR 0.13.0

## 설치와 변경

기존 Workbench 확장을 언로드한 뒤 `burp-workbench-kr-0.13.0.jar`를 Java 확장으로 다시 불러옵니다.

- 도구 가이드와 원본 엔진을 제거했습니다. 원본 엔진의 로딩, 메뉴 등록, 번들 JAR 및 Jython 런타임도 설치 파일에서 제외했습니다.
- 트래픽, 인가 비교, 변환, JWT, JS 분석, 환경·경로, Passive Scan, Payload Runner KR의 8개 탭을 제공합니다.
- 상/하 배치는 목록을 왼쪽에 두고 요청·응답을 오른쪽에서 위아래로 보여줍니다. 좌/우 배치는 목록을 위에 두고 요청·응답을 아래에서 나란히 보여줍니다.
- 초기 표시, 숨겨진 탭의 첫 표시, 배치 전환 및 창 크기 변경에서 현재 방향에 맞는 분할 비율을 적용합니다. 요청·응답은 기본 50:50이며, 마우스로 조정한 비율은 크기 변경 시 유지합니다. `배치 초기화`로 기본 비율을 복원합니다.
- 버튼과 옵션을 왼쪽으로 정렬하고 좁은 화면에서는 행을 줄바꿈합니다. 환경·경로와 JS 분석의 대상·옵션 행과 실행 행을 나눴습니다.
- 인가 비교의 History 및 환경·경로 표는 사용 가능한 폭에 맞춰 컬럼을 배치합니다. 긴 값은 툴팁과 패킷에서 확인할 수 있습니다.
- Payload Runner의 요청 준비와 검사 후보를 탭으로 나눴습니다. 실행 방식은 본 화면에 표시하고, 작업 창·CSV·초기화는 더보기에 모았습니다. 결과 표의 판정·상태를 앞으로 옮기고, 선택한 결과의 관찰 및 요청 선정 근거를 패킷 위에서 확인할 수 있게 했습니다. 작업 창도 선택한 패킷 배치를 따릅니다.

## 응답 기반으로 검사하는 방법

Payload Runner에서 요청을 가져온 뒤 검사 위치에 `§PAYLOAD§`를 지정하고, 원래 입력을 기준값에 넣습니다. 검사 유형을 고르고 실행 방식을 기본값인 **응답 기반 · 적응형**으로 두고 시작합니다. 결과를 선택하면 실제 요청·응답과 단계별 근거를 확인할 수 있습니다.

현재 적응형 엔진은 규칙 기반입니다. 후보 목록을 모두 전송하지 않고 기준 응답, 탐색 결과, 대조 요청, 반복 검증에 따라 후보 순서를 조정하거나 이후 요청을 생략합니다.

| 검사 예시 | 응답에 따른 다음 행동 |
|---|---|
| XSS | 고유 문자열 반사와 응답 MIME을 관찰하고 인접 태그·따옴표에 따라 후보 순서를 조정합니다. 현재 응답에서 반사가 없거나 HTML이 아니면 해당 반사형 후속 검사를 생략합니다. DOM·저장형 XSS까지 부재를 판정하지 않습니다. |
| SQL | 새 DB 오류를 반복 및 기준 요청으로 대조하거나, 참·거짓 조건과 역순 재검증으로 차이를 관찰합니다. 기준 응답이 불안정하면 조건 차이를 증거로 사용하지 않습니다. |
| SSTI | 서로 다른 계산값과 마커를 이용해 출력 평가가 반복되는지 확인합니다. 단순 반사와 계산 결과를 구분합니다. |
| 공통 | 총 요청 한도에 기준·대조·재검증을 포함합니다. 인증·차단·부하 응답과 연속 전송 오류에는 중단합니다. 후보 판정을 취약점 확정으로 표시하지 않습니다. |

임의의 응답을 해석해서 새로운 API 요청을 생성하거나 여러 화면의 업무 흐름을 연결하는 LLM 에이전트는 포함하지 않았습니다. 이런 방식으로 확장하려면 응답에서 관찰 사실을 추출하고, 가설과 다음 요청을 선정한 뒤 실제 전송 결과를 다시 입력하는 계획 모듈이 필요합니다. 그때도 요청 패킷, 선정 이유, 대조 결과와 중단 조건을 기록하는 구조가 적합합니다.

## 검증 범위

로컬 가짜 Burp 호스트와 HTTP 테스트 서버에서 기능 회귀 450개 검증과 화면 배치 1005개 검증을 통과했습니다. 전체 관리 탭을 1000·1280·1600px 폭에서 열고, 두 배치를 반복 전환하며 실제 분할 비율과 버튼의 화면 내 배치를 검증했습니다. 미리보기 이미지는 실제 Swing 컴포넌트의 렌더링이며 예시 데이터입니다. 실제 Burp 환경에서의 최종 확인은 별도입니다.
