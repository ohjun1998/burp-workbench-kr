# Burp Workbench KR 0.17.3 사용 안내

Java 17 이상 대상 JAR. 기존 확장을 교체하여 로드합니다. 이번 검증은 API 어댑터, HTTP 테스트 서버, headless Swing 화면을 사용했습니다. 실제 Burp GUI에서의 로딩/통합 동작은 확인하지 않았습니다.

## JS 추출과 활동 추적

1. 트래픽 우클릭 → SCOPE에서 대상 경로 또는 도메인을 등록합니다.
2. JS 추출에서 History 자동 분석을 사용하거나 선택 응답/수동 원본을 분석합니다.
3. 활동 추적에서 **JS 발견 · 요청 미관측** 필터를 선택합니다. JS 분석은 화면에서 선택하지 않은 파일도 즉시 등록합니다.
4. 대상 행을 선택하고 **발견 근거**를 누르면 별도 창에서 JS 출처·줄·추출 맥락을 확인합니다. **원본 보기**는 JS 추출 탭의 해당 원본으로 이동합니다. Source Map에서 찾은 항목은 복원 원본을 엽니다.
5. **Repeater 초안**으로 메서드·쿼리 이름·본문 키를 준비합니다. JS 추출의 **선택 URL → Repeater**도 동일한 초안 방식을 사용합니다.
6. 쿼리와 본문 값은 `REPLACE_ME`입니다. 실제 값, 인증, Content-Type 및 본문 구조를 확인하고 수정한 후 전송합니다. 이름만으로 본문을 복원한 JSON 템플릿이므로 실제 요청 형식과 다를 수 있습니다.
7. 동적 URL은 JS 추출의 **동적 값 확정** 창에서 실제 경로로 바꾼 후 준비합니다. 확정한 대상도 SCOPE 검사를 통과해야 합니다. 메서드가 미확정인 항목은 초안 생성이 제한됩니다.

초안 준비는 서버 요청을 보내지 않으며 요청 횟수나 완료 상태를 올리지 않습니다. 인증값·원래 쿼리값을 자동 복사하지 않습니다.

| 상태 | 의미 |
|---|---|
| 발견만 함 | 경로 발견, 해당 메서드 요청 미관측 |
| 요청 관측 | 요청을 관측했지만 완료 표시 없음 |
| Repeater 작업 | Repeater에서 실제 전송 관측, 완료 확정 아님 |
| 재검토 필요 | 권한 비교의 의심/보류 결과가 연결됨 |
| 점검 완료 | 진단자가 수동 완료 표시 |

파라미터의 **변경 관찰**은 값 변경/삭제를 관측했다는 의미입니다. 취약점이나 검토 완료를 뜻하지 않습니다. URL과 파라미터 완료 표시는 독립적입니다.

JS 결과 목록의 필터: 전체 API / 요청 미관측 / 동적 값 미해결. 동적 미해결 후보는 JS 목록에 남아 있으며, 값을 확정하기 전에는 정적 활동 추적 항목에 합치지 않습니다. 요청 관측은 메서드·정규화한 경로 기준으로 연결합니다.

활동 기록은 JSON 버전 2로 저장합니다. 이전 버전 1 기록을 불러올 수 있습니다. JS 근거는 엔드포인트당 최대 8개이며, 출처 URL의 쿼리값은 저장하지 않습니다. 파라미터 값/변경 비교 해시도 기록 파일에 저장하지 않습니다. Excel에는 JS 근거와 재검토 근거가 추가됩니다.

## 권한 비교

1. 대상 계정으로 발생한 트래픽에서 인증 후보를 수집합니다.
2. 후보를 우클릭하여 인가 1·2·3에 지정하거나 비로그인 프로필을 지정합니다. 프로필들은 같은 Origin이어야 합니다.
3. **비교 설정** 창에서 각 슬롯의 이름을 관리자 / 사용자 A / 사용자 B처럼 지정합니다. 창은 modeless이며 현재 메인 탭을 유지합니다.
4. 필요하면 JSON 비교 제외 필드를 지정합니다. 기본값은 비어 있으며, 원본 요청·응답은 수정하지 않습니다.
5. 소유 JSON 경로와 계정별 소유값을 입력하면 타인 객체 접근 후보를 구분할 수 있습니다.
6. 선택 요청 비교 또는 Record로 비교합니다. History에 계정별 결과 열이 나타납니다. 긴 결과는 마우스를 올리거나 하단 판정 근거에서 확인합니다.
7. 판정 근거의 JSON 필드 경로별 차이를 검토합니다. 의심/보류 결과는 활동 추적의 재검토 필요 항목으로 연결됩니다.

### 예시 설정

```
계정 2 이름: 사용자 B
계정 2 소유값: B
소유 JSON 경로: $.ownerId
JSON 비교 제외: $.requestId, $.meta.timestamp
```

원본과 사용자 B 응답 모두 `ownerId=A`라면 대상 계정의 소유값과 다른 객체에 대한 접근 의심으로 표시합니다. 공개/공유 객체, 정상 관리자 권한 등 허용 정책은 진단자가 확인합니다. 계정 소유값은 응답 필드와 같은 기준이어야 하며 비로그인 슬롯은 비워두는 것이 적절합니다.

비교 제외 규칙은 쉼표로 구분합니다. `$.requestId`는 정확한 경로, `timestamp`는 동일 이름의 말단 필드에 적용합니다. `$.items[0].timestamp`처럼 배열 인덱스를 지정할 수 있습니다. 정규식·와일드카드는 지원하지 않습니다.

차단 규칙은 행별 `JSON 경로=값`이며 OR 조건입니다. 값 비교는 대소문자를 구분합니다. 기본 규칙:

```
error=FORBIDDEN
error=UNAUTHORIZED
```

대상 서비스에서 `success=false`가 인증/인가 차단을 뜻한다는 것을 확인했다면 규칙으로 추가할 수 있습니다. 일반 업무 오류도 false를 반환하는 서비스에서는 차단 근거로 사용하지 않습니다.

| 결과 | 의미 |
|---|---|
| 타인 객체 접근 의심 | 원본 소유 필드가 다른 계정 응답에 그대로 남고 대상 계정 소유값과 다름 |
| 우회 의심 | 비교 제외 후 JSON 필드가 같거나 비 JSON 성공 본문이 완전히 같음 |
| 차단 근거 확인 | HTTP 401/403 또는 설정한 JSON 차단 규칙 일치 |
| 판정 보류 | 다른 데이터, 리다이렉트, 빈 응답, 구조 제한, 기준 응답 오류 등의 수동 검토 대상 |
| 원본과 동일 인증 · 교차 인가 미검증 | 인증이 실제로 바뀌지 않아 교차 계정 판정에서 제외 |
| 전송 세션 변경 · Burp 규칙 확인 | Burp 세션 규칙 등으로 전송 인증이 지정값과 달라짐 |

모든 결과는 관찰/후보 분류입니다. 취약점 확정이나 보고서 심각도 자동 결정을 의미하지 않습니다. JSON 차이는 최대 100개 필드, 각 값 미리보기는 최대 160자입니다. 기존 원본 패킷 뷰는 유지합니다.

계정 이름·소유값·판정 규칙은 비교 시작 시 복사해 기록별로 유지합니다. 설정을 나중에 바꿔도 기존 결과의 의미는 바뀌지 않습니다. 설정은 이번 확장 세션에서 유지되며 자동으로 프로젝트에 저장하지 않습니다.

검토 후 활동 추적에서 URL 완료를 다시 표시하면 재검토 근거가 해제됩니다. 자동 판정으로 완료 처리하지 않습니다.

## 기존 기능의 실행 방식

- SCOPE 목록과 공통 설정은 기존처럼 별도 창으로 열리며 현재 메인 화면을 유지합니다.
- JS/환경/URL 수집의 URL 입력은 대상 설정 창에 유지합니다.
- 권한 비교의 쓰기 요청 재전송 허용은 기본 OFF입니다.
- URL 수집은 수집 단계와 대상 GET 확인을 분리합니다.
- 환경 탐색은 비로그인 GET 후보 검증과 없는 경로 기준 비교를 사용합니다.
- 페이로드 검사에는 요청 예산과 중지 기능이 있습니다. 기존 진단 엔진은 이번 버전에서 변경하지 않았습니다.
