# Workbench Simple 1.3.1 변경 안내

공유 대화에서 확인한 SCOPE 통합 점검의 발견 누락·오탐·중단 문제를 수정하고, **파싱한 값을 원문 그대로 분류하는 로컬 보고서**를 추가했습니다. 기존 8개 도구, Katana 1.8.0과 helper 0.4.0, 원본 Next 및 Simple 1.0.0–1.3.0 배포·가이드·검증 기록은 보존합니다.

## 수정한 동작

- 일반 화면에 비밀번호 폼이 있다는 이유만으로 정상 계정의 점검을 세션 만료로 중단하지 않습니다. 계정의 신원 확인 근거와 실제 401·신원 실패·보안 확인은 구분합니다.
- 관측 링크·JS·문서 참조를 추정 경로보다 우선합니다. 시작점의 SPA 공통 화면에서도 실제 참조는 분석하고, 범위 안의 제한된 `.env` 후보를 없는 경로 대조·내용 판별과 같은 요청 예산으로 확인합니다.
- 통합 점검에서 큰 JS 번들의 API를 분석하고 실제 원문 위치로 연결합니다. 변수 표현식·소스맵 코드의 시크릿 오탐과 예제/토큰의 중복 분류를 보완합니다.

## 원문 값 분류 보고서

점검 완료 또는 중지 후 **분류 보고서 저장**을 누릅니다. 선택한 새 로컬 ZIP에는 API·민감정보·토큰·키·환경·DB·내부 경로 등의 값과 출처를 저장합니다.

| 파일 | 내용 |
|---|---|
| `report.html` | 종류·값·공개/예제/미검증 분류·제품 탐지/추가 파싱·원본과 위치를 읽는 보고서 |
| `report.json` | 정확한 문자열 값과 분석·응답·원본 메타데이터 |
| `values.csv` | 스프레드시트용 목록; 수식 실행 보호가 붙는 셀의 정확한 값은 JSON에서 확인 |
| `manifest.json` | 보고서 형식·생성 버전·원문 포함 여부·분석 범위 |

현재 실행의 응답 원본을 저장 시점에 읽습니다. 요청 Cookie·Authorization을 별도 덤프로 넣지 않으며, 화면·이력·기존 증거의 가림은 유지합니다. 저장은 대상 요청이나 키 유효성 검증을 하지 않고, 기존 파일을 덮어쓰지 않습니다. 원본 누락·분석 한도·부분 실행은 보고서의 제한으로 남습니다. 문자 위치는 디코딩한 본문 또는 정규화한 헤더의 UTF-16 문자 기준으로 읽습니다. 소스맵의 복원 위치를 현재 응답에 확정할 수 없으면 부분 상태로 남깁니다. 한도는 응답 원본 8 MiB·디코딩 본문 5 MiB/응답·값 64 Ki 문자·최대 10,000개이며, 제외한 값은 잘라서 실제값처럼 싣지 않습니다.
