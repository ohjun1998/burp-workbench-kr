# Workbench Simple 1.4.13 · Strix 진단 연결

선택한 요청·응답의 메타데이터와 기대 정책을 준비한 뒤, 실행계획을 확인하고 기존 로컬 Strix CLI로 진단하는 기능입니다. Strix 설치·실행 래퍼·모니터를 수정하지 않으며 원본 Next, Simple의 기존 8개 도구 경로·Guide/F1·이전 배포를 보존합니다.

설치 파일은 [버전별 배포 폴더](../downloads/1.4.13/)에서 확인합니다. 단계별 이미지는 [HTML 사용 가이드](../../docs/reports/2026-11-16-simple-strix-local/guide/index.html), 실제 검사·배포 상태와 제한은 [검증 기록](../../docs/reports/2026-11-16-simple-strix-local/README_KR.md)을 확인하세요. 이 문서의 사용법 설명은 실제 사용자 Burp와 모델 추론 검증을 완료했다는 뜻이 아닙니다.

## 1. 선택 원본과 SCOPE 확인

허가된 사이트를 직접 사용해 요청·응답을 수집합니다. 현재 프로젝트의 원본 1~24개를 선택해 Strix 진단을 준비합니다. 선택 원본과 입력한 대상 URL은 실행 전에 현재 SCOPE에 포함되는지 검사합니다.

원본 요청·응답 본문, 쿠키·토큰·인증값은 자동으로 전달하지 않습니다. 선택한 자료는 원본 ID·메서드·URL 등 제한된 메타데이터를 진단 맥락으로 제공하기 위한 것입니다. 로그인 요청을 선택했다고 Strix가 해당 세션을 자동으로 사용하는 것은 아닙니다.

## 2. 모델 실행 경로 선택

| 경로 | 동작 |
|---|---|
| 로컬 Halogen + Qwen 3.8 | 기존 Strix의 로컬 모델 설정을 확인하고 해당 설정을 실행에 사용합니다. |
| ChatGPT 구독 · Strix 자체 인증 | Strix가 지원하는 자체 ChatGPT OAuth 인증과 `chatgpt/<model>` 모델을 사용합니다. |

진단창의 **모델·Strix 설정** 탭에서 경로를 고르고 **로컬 모델 설정 확인** 또는 **Strix 구독 로그인 확인**을 눌러 실행할 모델을 확인합니다. ChatGPT 모델 입력 예시는 `chatgpt/gpt-5.4`이며 실제 계정과 Strix에서 사용할 수 있는 모델을 지정해야 합니다. 모델·인증 설정 확인과 실제 추론 성공은 별도입니다.

Strix 구독 인증은 Codex CLI 로그인과 별도입니다. 필요한 경우 사용자가 터미널에서 다음을 실행합니다.

```sh
strix auth login chatgpt
strix auth status
```

이번 검사 시점의 환경에서는 Strix 구독이 미로그인 상태였습니다. 이는 사용자의 이후 로그인 상태를 고정해서 설명하는 문구가 아닙니다. upstream Strix가 제공하는 OAuth 연동이며, upstream의 안내상 OpenAI 공식 지원 대상은 아닙니다. 이를 OpenAI 공식 구독 API로 설명하지 않습니다. 이 기능은 인증 파일·토큰을 표시하거나 복사하지 않습니다.

제공자·모델은 실행별로 선택하며 전역 Strix 모델 설정을 덮어쓰지 않습니다. 실패·거절 시 다른 제공자로 자동 전환하지 않습니다.

## 3. 기대 정책과 실행계획 확인

대상 URL·실행 파일·모델 경로·모드·최대 에이전트 턴·실행 상한을 확인하고, **테스트 계정·기대 정책**에 허용 범위와 원하는 검증을 적습니다. 인증값은 입력하지 않습니다.

예시:

```text
허가 대상은 표시된 테스트 사이트입니다.
계정 A/B는 서로 다른 일반 사용자이며 각자 소유한 주문만 조회할 수 있어야 합니다.
현재 원본은 계정 A가 내 주문을 조회했을 때의 메타데이터입니다.
원본의 인증값은 제공하지 않았습니다.
관찰·가설·추가 확인이 필요한 점을 구분해 주세요.
서비스 중단·과부하·대량 반복·삭제·비가역 변경 검사는 하지 말고,
그런 검사가 필요하면 중단하고 사용자 확인을 요청하세요.
```

**진단 입력 미리보기**를 읽은 뒤 **실행 계획 확인·진단 시작**을 누릅니다. 확인창의 대상·제공자·모델·모드·턴·시간·영향을 검토하고 **확인 후 실행**을 선택해야 진단을 시작합니다. 기본 선택은 취소이며 선택이나 준비만으로 Strix를 실행하지 않습니다. 승인 중 원본·프로젝트·SCOPE·설정이 바뀌면 다시 준비해야 합니다.

## 4. 진단 실행과 로그 확인

Strix CLI가 실제 대상에 요청하며 선택한 모델의 정책·사용량이 적용됩니다. 실행 중에는 새 진단을 동시에 시작하지 않습니다. **진행 로그**는 최근 일부만 표시하므로 화면의 짧은 로그를 전체 실행 기록으로 해석하지 않습니다.

`quick / standard / deep`은 진단 모드입니다. **최대 에이전트 턴은 에이전트의 반복 횟수이며 HTTP 요청 예산이 아닙니다.** 현재 CLI에는 이 연결부에서 강제할 전체 HTTP 요청 수 예산이 없습니다. SCOPE 확인은 실행 전의 대상·원본 검사이며, 에이전트의 모든 네트워크 통신을 격리하는 장치로 설명하지 않습니다.

가용성에 영향을 줄 검사를 금지하고 필요하면 사용자에게 확인하라는 내용은 Strix에 전달하는 지시문입니다. 실제 요청 수·무영향·네트워크 차단을 기술적으로 보장하지 않습니다. 사용자가 승인할 때 이 한계를 함께 검토해야 합니다.

## 5. 중지와 종료 확인

**중지**를 누르면 연결된 진단 프로세스의 중지를 요청합니다. 진단창을 닫거나 프로젝트를 전환하거나 확장을 종료해도 실행 상태를 정리합니다. 이미 대상 서버에서 시작한 작업을 되돌리는 기능은 아닙니다.

Strix가 별도 컨테이너나 백그라운드 작업을 시작할 수 있으므로 보고서의 컨테이너 정리 확인 상태를 봅니다. **미확인**이면 완전히 종료됐다고 판단하지 말고 기존 Strix 관리 도구로 남은 실행을 확인합니다.

## 6. 이번 실행 보고서 확인

**이번 실행 보고서**에서 실행 폴더와 보고서 경로를 확인하고 **첫 보고서 가림 미리보기**를 사용합니다. 연결부는 이번 실행의 보고서인지 검사한 뒤 텍스트로 표시하며 원문 HTML을 브라우저에서 자동 실행하지 않습니다. 종료 코드나 보고서 파일이 있다는 사실만으로 취약점이 검증된 것은 아닙니다. 실제 요청·응답, 기대 정책, 재현 가능성과 영향을 검토합니다.

## 검증 범위

연결부 시험은 fake CLI·가짜 Runner·합성 UI/API 어댑터를 사용해 실행계획, 승인 취소, 제공자 선택, SCOPE·프로젝트, 중지·종료 및 늦은 결과 폐기를 확인합니다. 합성 화면은 실제 Simple 패널을 그린 예시이며 사용자 Burp 캡처가 아닙니다. 실제 모델 추론과 사용자 Burp 실행·원격 작업 종료는 별도 확인 대상입니다. 수행한 검사 수·환경의 접근 제한·미완료 범위는 위 검증 기록에서 확인합니다.

실행 파일은 **Strix 실행 파일** 탭에서 확인합니다. 이 통합은 기존 `~/.strix/bin/strix` 실행 래퍼를 사용하며 `libexec` 직접 실행은 지원하지 않습니다. 미리보기는 Simple이 추가하는 관찰 자료이며 기존 Strix 전역 지침도 함께 적용됩니다.

새 진단의 결과는 `~/.burp-workbench-simple/strix-runs/run-*/strix_runs/` 아래에 보관됩니다. 기존 `~/strix_runs`와 별도이며, 현재 실행의 128 KiB 이하 보고서를 미리보기로 표시합니다. 더 큰 파일이나 이전 실행은 해당 폴더에서 확인할 수 있고 기존 Strix 웹 뷰어에는 실제 진단 폴더의 절대 경로를 전달할 수 있습니다.
