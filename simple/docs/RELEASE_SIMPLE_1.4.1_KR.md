# Workbench Simple 1.4.1 · 실사용 흐름 개선

Simple 1.4.0을 기준으로 매 라운드에 전체 8개 도구 흐름 검증 → 개선 적용 → 전체 흐름 재검증을 수행한 5라운드 개선판입니다. 총 10번의 독립 실행에서 각각 115개 확인 항목을 통과했습니다. 사전 조사에서 준비한 수정은 라운드별로 하나씩 적용했으며, 이전 실행 결과를 재사용하지 않았습니다. 새 스캔 도구를 늘리지 않고 상세 읽기·대상 변경·결과 갱신·URL 후보 가져오기·대시보드 결과 접근을 다듬습니다. 기존 8개 도구, 통합 점검, Mapper 0.3.6·helper 0.4.1·Katana 1.8.0을 유지합니다.

## 달라진 작업 흐름

1. **실행 중에도 근거를 계속 읽고 복사합니다.** 같은 실행·항목·본문이면 결과 갱신이 들어와도 상세 텍스트의 선택과 읽던 위치를 유지합니다. 다른 항목이나 실행을 선택하거나 본문이 바뀌면 새 내용을 표시합니다.
2. **대상 URL을 입력하고 계정을 고릅니다.** Enter를 누르거나 URL 칸에서 나가면 새 대상의 계정 목록을 갱신합니다. 해당 대상에 같은 계정 ID가 있으면 유지하고, 없으면 비로그인 또는 명시적인 계정 선택 상태로 둡니다. 첫 인증 계정을 임의로 선택하지 않습니다. 잘못된 URL·일시적인 계정 조회 실패는 안내하며 정상 입력으로 복구합니다. 등록 목록 자체를 다시 읽는 `목록 새로고침`도 유지합니다.
3. **많은 결과를 갱신할 때 정렬과 원본 선택을 유지합니다.** 같은 내용은 표를 다시 만들지 않고, 바뀐 표만 한 번에 반영합니다. 숨겨진 분류, 진행 상태, 이력과 대시보드 알림은 계속 갱신합니다.
4. **URL 후보를 한 번에 가져옵니다.** 붙여넣기·수집 묶음·이전 DB 병합의 필터와 표 갱신을 모아서 처리합니다. 쿼리 값이 다른 URL, 출처와 관측/추정 메서드, 1,000건 상한, 정렬·선택·원본을 유지합니다. 일부 콜백이 실패해도 이미 받은 결과를 반영하고 다음 동작을 계속할 수 있습니다.
5. **대시보드 숫자에서 결과 목록으로 바로 이동합니다.** 카드·분류·중요도를 직접 선택하면 작은 창에서도 결과와 근거가 보이도록 이동합니다. 자동으로 들어오는 결과 갱신은 사용자가 읽던 스크롤 위치를 바꾸지 않습니다. 빈 조건은 기존 `조건 해제`로 복구합니다.

자주 쓰는 8개 도구·대시보드·통합 점검은 상단에서 사용합니다. 도움말·화면 설정·오류 기록은 `도움말·설정`, 세부 실행 조건은 `실행 조건`, URL 도구와 저장·가져오기는 기존 설정·더보기에서 사용합니다. 도구 이동마다 대상을 다시 입력하거나 설정을 다시 적용할 필요가 없습니다. 관리 기능을 상시 버튼으로 늘리지 않습니다.

대상 입력 완료·화면 열기·결과 필터·원본 보기·Repeater 준비·증거 추가는 대상 요청을 전송하지 않습니다. 점검 시작, 직접 GET 확인, Repeater의 Send는 기존처럼 명시적으로 실행합니다. [대시보드 수치의 집계 기준](RELEASE_SIMPLE_1.4.0_KR.md)은 유지합니다.

사용자가 선택한 환경은 저장소의 로컬 실습 환경입니다. 운영 Swing 컴포넌트와 실제 loopback HTTP를 사용하는 어댑터, 원본 LOOP 3.10.0 앱으로 확인합니다. 조작 수는 하네스가 수행한 명시적 UI 동작이며 사람의 작업 시간 측정이 아닙니다. 대량 자료의 EDT 시간·스레드 할당량은 합성 부하 진단이며, 살아 있는 힙 크기·RSS·실제 Burp의 그리기 시간·외부 사이트 성능으로 일반화하지 않습니다. 실제 Burp GUI·Windows DPI/IME·수동 브라우저 조작 검증은 별도로 구분합니다.

Simple 1.4.0과 모든 이전 버전의 배포 파일·가이드·검증 기록을 보존합니다. 기존 Workbench Next 0.53.4 소스는 변경하지 않습니다.
