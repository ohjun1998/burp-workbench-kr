# Workbench Strix 1.1.0 · 진단 에이전트와 대화

Workbench Strix의 별도 진단 창에서 **현재 진단 세션의 Strix 에이전트에게 후속 질문을 전달하고, 같은 대화의 답변을 확인하는 기능**을 추가합니다. 기존 Simple1.4.21 메인 디자인·메뉴·13개 도구와 실행계획 확인·중지·보고서 흐름은 유지합니다.

## 이전 버전과 달라지는 점

| 작업 | Strix1.0.1 | Strix1.1.0 |
| --- | --- | --- |
| 진단 중 특정 관찰에 질문 | 로그를 읽고 별도 터미널에서 확인 | 연결된 세션의 대화에서 질문·답변 확인 |
| 대화의 맥락 | 후속 질문 입력 없음 | 같은 Strix 에이전트의 기존 세션·기록 사용 |
| 질문 전달 | 제공하지 않음 | 전송 내용·현재 대상 확인 후 명시적 전송 |
| 실행 방식 | 비대화형 CLI 실행 | 대화 연결 또는 기존 비대화형 실행 선택 |
| 기존 메인 화면 | Simple1.4.21 | 같은 디자인·배치 유지 |

질문마다 새 진단을 생성하거나 다른 LLM에 답변을 요청하는 방식이 아닙니다. Strix의 현재 실행이 제공하는 인증된 로컬 live viewer를 통해 같은 에이전트에 전달합니다. 에이전트가 질문을 받았다는 확인과 모델 답변이 도착한 상태를 구분합니다.

## 사용 순서

1. 이전 Simple/Strix 확장을 언로드하고 `burp-workbench-strix-1.1.0.jar`를 로드합니다. 기존 `simple.*` 설정과 `.burp-workbench-simple` 기록은 이어 사용합니다.
2. 허가된 대상의 현재 원본을 선택하고 우클릭 **선택 원본으로 Strix 진단 준비**를 엽니다.
3. 대상·SCOPE·제공자·모델·실행 조건을 확인하고 대화 연결을 선택합니다. **원본·테스트 정책** 탭에서 **테스트 계정·기대 정책**을 적고 **진단 입력 미리보기**를 확인합니다. 기존 Halogen/Qwen 또는 Strix 자체 ChatGPT 구독 인증을 사용합니다.
4. 실행계획을 확인해 진단을 시작합니다. 대화 연결 상태를 확인한 후 질문을 입력합니다.
5. 전송 확인에서 대상·내용을 검토합니다. 취소하면 질문을 보내지 않습니다. 전송된 메시지와 답변은 대화 기록에서 읽습니다.
6. 후속 질문을 이어가거나 중지합니다. 세션 종료 후에는 연결을 유지한 대화로 표시하지 않습니다.

질문 예시: “방금 발견한 계정 간 주문 조회 차이는 어떤 원본에서 확인했나요? 관찰과 추정을 구분하고 추가 검증이 필요한 점을 설명해 주세요.” 민감한 토큰·쿠키·비밀번호나 원본 패킷 본문은 질문에 붙이지 않습니다.

별도 Strix 창의 중앙은 **진단 대화 / 진행 로그 / 이번 실행 보고서 / 원본·테스트 정책** 탭 중 선택한 화면이 넓게 사용합니다. 기존 정책 입력과 미리보기는 네 번째 탭에서 확인합니다. 메인 도구 화면과 메뉴 배치는 바꾸지 않습니다.

## 연결 조건과 동작

- Linux/macOS의 Python3와 대화 가능한 Strix CLI가 필요합니다. Windows의 POSIX PTY 대화 연결은 지원하지 않습니다. 기존 비대화형 진단 흐름은 유지하지만 Windows 실행을 검증한 것은 아닙니다.
- 실행 파일은 기존 `~/.strix/bin/strix` 래퍼를 사용합니다. 전역 Strix 설정과 OAuth 인증 파일을 변경하거나 토큰을 복사하지 않습니다. Strix 자체 ChatGPT 로그인과 Codex CLI 로그인은 별개입니다.
- 로컬 viewer 연결은 이번 실행이 소유한 loopback 주소와 인증 정보로 제한합니다. 연결 주소·토큰은 대화나 로그에 공개하지 않습니다.
- 화면은 모든 에이전트를 합한 최근 대화 최대200개·128Ki자 안에서 선택한 에이전트의 메시지를 보여줍니다. 표시 범위 밖의 원본 이력은 Strix 실행 기록에 유지됩니다.
- 대화는 Strix가 확정해 기록한 내용을 주기적으로 갱신합니다. 모델의 토큰 단위 스트리밍이나 즉시 답변을 보장하지 않습니다. 초기 진단이 완료되어도 소유한 Strix 프로세스가 살아 있고 실행 상한 안이면 같은 에이전트에게 후속 질문을 보낼 수 있습니다. 중지·프로세스 종료·시간 초과 때 대화 연결을 끝냅니다.
- 에이전트는 후속 질문에 따라 도구와 대상 요청을 실행할 수 있습니다. 질문 전송은 읽기 전용 분석을 보장하는 기능이 아니므로 매번 기본 취소인 확인창을 거칩니다. 최대 에이전트 턴은 HTTP 요청 예산이 아닙니다. 후속 질문으로 에이전트가 재개되면 초기 턴 예산이 늘어날 수 있어 전체 대화의 엄격한 턴 상한으로 해석하지 않습니다. 처음 시작한 실행 시간 상한은 질문으로 초기화되지 않습니다.
- 원본·프로젝트·SCOPE가 바뀌거나 이번 실행이 종료되면 이전 세션으로 새 질문을 보내지 않습니다. 다른 실행의 기록을 현재 대화로 섞지 않습니다.

## 연결이 안 될 때

진단 창의 상태와 로그에서 원인을 확인합니다. Python3 없음, 호환되지 않는 Strix, viewer 미지원/연결 실패, 세션 종료는 연결된 것으로 표시하지 않습니다. 기존 비대화형 진단을 선택하면 기존 실행·로그·보고서 기능을 사용할 수 있습니다. 실패한 질문을 자동 재전송하거나 새 진단·다른 제공자로 자동 전환하지 않습니다.
