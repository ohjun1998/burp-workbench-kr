# 시안의 구성 요소 적용 · Simple 1.4.8

사용자의 “아예 모든 부분을 동일하게” 요청은 기존 시안의 스타일을 일부 영역에만 적용하지 말고, 각 도구의 구성 요소와 상태까지 맞추라는 요구로 해석했습니다. 마지막에 첨부한 사각 단계 버튼은 기존 구현의 차이를 지적한 화면입니다. 승인 시안의 입력값 검사는 원형 번호·주황 밑줄과 분리된 대상 요약 줄을 사용합니다.

## 데이터와 조작

- 계정 3이 연결된 경우 원래 모델 열을 다시 표시합니다. 실행·메서드 메타데이터는 모델에 남고, 메서드는 URL 셀에 함께 표시합니다. 모든 계정을 가상의 Alice/Bob로 바꾸지 않습니다.
- 응답 차이의 색은 두 실제 미리보기에서 계산합니다. 검색 초기화 및 Raw/Pretty 전환 뒤에도 유지하고, 다른 모드끼리나 Hex/Render는 비교 색을 그리지 않습니다.
- 증거 검색은 문자 그대로 필터링합니다. 필터 후 삭제·이동은 불변 증거 ID와 모델 순서를 사용하며, 필터로 사라진 행에 잘못된 선택을 남기지 않습니다.
- B/I/코드/목록/링크는 선택한 보고서 텍스트에 Markdown 표기를 넣는 실제 동작입니다. 기존 일반 텍스트 초안·ZIP을 유지하며, 새 서식 저장 형식을 만들지 않습니다.
- Raw/JSON은 표시만 바꾸고 HTTP 원문 바이트를 수정하지 않습니다. 화면 이동·상세 열람·서식 조작은 네트워크 요청을 시작하지 않습니다.
- 캡처에 사용하는 데이터와 페이로드 결과는 테스트 하네스의 합성 예시입니다. 배포 제품에 예시 결과를 넣지 않습니다.

## 시각 검증 범위

8개 기본 도구와 준비 화면을 밝은/어두운 테마로 캡처하고 1024×720, 1280×800, 1600×1000에서 잘림·작성/읽기 영역을 검사합니다. 설정·대시보드·SCOPE에는 같은 공통 컨트롤 스타일을 적용하며 별도 SCOPE 캡처도 검사합니다.

승인 이미지는 서로 다른 내용·세부 구성을 가진 래스터 시안입니다. 원래 엔진에 없는 수치·결과·인증 상태를 만들어 동일하게 보이게 하지 않습니다. 실제 필드, 추가 기능, 플랫폼 글꼴과 네이티브 Burp 편집기는 차이가 남을 수 있습니다. 픽셀 단위 동일성이나 실제 Burp 본체 GUI 실행을 검증했다고 주장하지 않습니다.
