# Workbench Simple 1.2.0 변경 안내

SCOPE URL과 HTTP 계정을 선택하면 메뉴·환경·주요 경로·API·민감정보를 한 실행에서 확인하도록 재구성했습니다. 결과마다 근거·확실성·검사 상태와 원본을 연결하고, 필요한 기존 도구에서 검토한 뒤 증거로 저장합니다. **기존 8개 도구는 유지하고 상단에 SCOPE 통합 점검 진입점을 추가했습니다.** 기존 Next와 Simple 1.0.0·1.1.0 파일은 보존합니다.

## 추가한 핵심 흐름

1. **대상과 실행 조건 선택:** SCOPE URL·경로, HTTP 계정, 요청 수·깊이·간격·타임아웃·분석 한도를 한 번 정합니다. 실행 중 일시정지·재개·중지를 지원하며 범위·프로젝트 변경 시 새 점검을 시작합니다.
2. **발견과 응답 확인:** 정적 링크·JS·robots/sitemap·API 문서에서 발견한 항목과 기술별 후보를 구분해 제한된 조회 큐로 확인합니다. 서버·WAS·프레임워크·프록시/CDN·DB 단서, 숫자 버전의 근거를 함께 표시합니다. 로그인·WAF·429·soft404·부분 응답은 대상 내용 확인 완료로 처리하지 않습니다.
3. **중요 결과 검토:** 문서와 관측 API의 차이, 키·토큰·연결정보·내부 정보 후보, HTTP 계정별 노출 차이, 같은 조건의 이전 실행과 변경을 확인합니다. 키 후보는 공개 식별자·예제·비밀키 후보를 구분해 마스킹하고 자동 검증이나 인증 재사용을 하지 않습니다.
4. **메뉴·SPA 탐색 선택:** helper 0.4.0을 연결하고 현재 사이트와 SPA 통합 탐색을 허용하면 별도 탭에서 동적 메뉴·hash route·API 관측을 추가합니다. 브라우저 로그인 세션과 선택한 HTTP 계정은 별개이며 쿠키를 HTTP 계정으로 복사하지 않습니다.
5. **원본과 증거 연결:** 현재 실행의 불변 패킷 ID에서 요청·응답을 열고 Repeater 준비·계정 비교·API 찾기·입력값 검사·증거 추가로 연결합니다. 앞64 KiB 미리보기의 더 보기(…)에서 같은 전체 원본을 Burp 기본 읽기 전용 편집기로 엽니다. 과거 이력은 마스킹된 요약과 지문으로 구분하고 원본이 없으면 현재 원본처럼 열지 않습니다.

## 유지한 8개 도구와 정리한 부가 흐름

| 도구 | 유지한 주요 기능 | 메인 흐름에서 정리한 항목 |
|---|---|---|
| 요청·응답 | OFF/SCOPE 수집·검색·원본·도구 연결 | 중복 탐색·작업 관리 바 |
| 기능 매핑 | 기능·실행·세션 분류·근거·프로젝트 저장/열기 | 도우미와 세부 설정은 필요한 때 선택 |
| 계정 비교 | 계정·세션·정책 조건·선택 요청 직접 비교·결과 | 신규 요청 자동 비교 토글 |
| API 찾기 | 선택 응답의 API·키 후보·원본 위치·요청 준비 | 시작 시 전체 History 자동 순회, 부가 NPM·소스맵 조회의 메인 노출 |
| 서버·경로 | 환경 단서·후보 경로·선택 경로 직접 GET | 선택 대상·조건 중심으로 정리, 보조 설정은 필요할 때 사용 |
| 응답 분석 | 보안 단서·API 문서·저장 후 조회·원본과 증거 | 보조 설정은 필요할 때 사용 |
| 입력값 검사 | 검사 유형·위치·값·요청 한도·기준/변경/대조 결과 | 조건 선택과 결과 검토에서 바로 증거로 연결 |
| 재현·증거 | 순차 재현·중지·결과·가림·증거 ZIP | OAST·외부 도구·기존 브라우저 보조 화면 |

기존 폴더 탐색·화면 이력·작업 이어가기·도우미 관리 바는 메인 화면에서 제외했습니다. 새 SPA 탐색은 통합 점검에서 선택합니다. 도구 이동·원본 준비·증거 편집은 대상 요청을 전송하지 않으며 통합 점검과 각 도구의 실행 버튼에서 전송을 시작합니다.

## 결과를 읽을 때 확인할 점

기술·DB 단서와 응답 차이는 근거가 있는 후보이며 취약점 확정 판정이 아닙니다. 완료는 발견한 큐의 처리 상태이며 사이트 전체 기능의 검증 완료를 뜻하지 않습니다. 제외·실패·부분 분석 사유를 커버리지에서 함께 확인합니다.

HTTP 조회는 각 리디렉션의 허용 범위를 다시 확인합니다. 브라우저 모드는 URL 규칙으로 안전하게 표현할 수 없는 정규식 범위를 지원하지 않으며 좁은 범위가 필요한 리소스를 제외하면 부분 탐색으로 표시합니다. GET/HEAD와 알려진 변경 경로 제외 규칙은 모든 서버 GET 기능의 부작용 부재를 보장하지 않습니다.

브라우저 페이지·동작 한도와 네트워크 관측 수는 HTTP 요청 예산과 별개입니다. 대형 덤프·아카이브 후보는 자동 제외하며 압축을 푼 본문에도 분석 한도를 적용합니다. 이 분석 한도는 실제 응답 다운로드를 해당 바이트에서 강제로 중단한다는 뜻이 아닙니다.
