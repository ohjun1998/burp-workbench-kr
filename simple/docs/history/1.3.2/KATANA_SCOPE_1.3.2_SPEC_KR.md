관측 경로·남은 동작이 있으면 최초 최소1.5초·동작 뒤 최소350ms·최대3초의 DOM 관찰과350ms 안정 조건을 사용합니다. 경로·동작이 없는 빈 화면은3초 전체를 기다린 뒤 부분 상태로 남깁니다. 후보200개/문서·동작12회/문서·스크롤2회/문서·후보500개/실행·대기열100개 및 전체 페이지·동작 한도는 끝이 없는 탐색을 제한하며 초과 범위를 부분 상태로 남깁니다.

Katana의 표준 HTML·JS 수집과 브라우저 helper의 DOM 관측은 다른 실행입니다. 브라우저 세션을 HTTP 점검 계정으로 자동 증명하거나 쿠키를 복사하지 않습니다. 자동 로그인·폼 제출·무작위 버튼 실행·발견 키의 외부 검증은 추가하지 않습니다. 변경 경로·쓰기 메서드·Scope 밖 이동과 미확정 입력의 기존 제외 정책을 유지합니다.

실제 원본 앱 재시험의 시도·완료 응답·전송 오류를 별도로 집계하고, 요청 예산·시험 하네스 시간 제한·부분·미확인 결과를 그대로 보존합니다. fixture 성공이나 처리 대기열 종료를 모든 서비스 메뉴·취약점의 검증 완료로 확대하지 않습니다.

401 경로에 로그인 폼/경로·쿠키 변경 등의 세션 실패 징후가 없고 기존 구성 신원·동일 계정의 검증 근거가 확인된 경우에만 같은 인증 스냅샷의 새 신원 GET과 새 비로그인 대조 GET으로 제어 응답을 확인합니다. 인증 응답의 완전한2xx JSON 신원·조건 일치와 비로그인 대조가 그 신원을 증명하지 못하는 조건이 있어야 경로별 접근 거부·권한 미확인으로 남기며 거부 경로를 재시도하지 않습니다. 신원 URL 자체의401·예산/근거/Scope 부족·만료·불일치·challenge·리디렉션·잘못된 응답에서는 정상 신원 유지 예외를 적용하지 않고 기존 세션·예산 중단 정책을 유지합니다.
